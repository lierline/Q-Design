# 세 제품 공용 컴포넌트 통일

2026-10-10. 비교 화면에서 확인된 기본 부품의 차이를 공통 규칙과 실제 제품 어댑터에 반영했다. 운영 배포는 수행하지 않았다.

## 변경 결과

| 대상 | 적용한 공통 규칙 |
| --- | --- |
| 카드 | 아뜰리에의 전역 여백 초기화를 낮은 CSS 레이어로 이동했다. 공통 카드 안쪽 여백 24px와 설명 간격이 실제로 적용된다. |
| 폼 필드 | 이름표와 컨트롤 간격, 오류·도움말 묶음 간격은 `--qd-field-gap`을 따른다. 기본값은 공통 간격 단위 4px이다. |
| 여러 줄 입력창 | `--qd-textarea-min-height`를 따른다. 기본 높이는 80px이며 일반 입력창·버튼의 44px 기준과 분리된다. |
| 선택창 | 네이티브 화살표와 같은 오른쪽 여백을 사용한다. 여백은 `--qd-select-end-padding`으로 조정한다. |
| 비활성 입력창 | 인라인 기본 색에 가려지던 비활성 배경과 글자색을 공통 규칙으로 적용한다. |
| 입력창 배치·오류 문구 | 입력창의 블록 배치로 여러 줄 입력창 아래 기준선 여백을 없앴다. 오류 문구의 간격·행간·자간을 통일하고 모션 감소 설정을 따른다. |
| 상태 배지 | 메종의 기본 크기를 `qd-tag--sm`으로 맞췄다. 기본 배지의 실제 높이는 세 제품 모두 24px이다. |
| 표 머리글 | 공통 자간과 대소문자 규칙을 적용했다. 한글 표 머리글의 불필요한 벌어짐을 없앴다. |

제품별 대표 색과 업무 데이터·권한·저장 동작은 각 제품이 담당한다. 동일한 부품의 모양과 상태는 Q-Design이 담당한다.

## 비교 화면

`http://127.0.0.1:4818/preview/components.html`의 기본 화면은 **같은 역할의 컴포넌트**다. 세 제품에서 사용하는 부품을 같은 문구·상태·순서로 보여준다. 제품별 업무 예시와 배경·로그인 예시는 선택 메뉴에서 계속 볼 수 있다.

비교 화면의 모서리·글자·공통 인자 조절은 검토 화면에만 적용된다. 실제 제품을 바꾸려면 `patterns/components.css` 또는 `patterns/foundation.css`의 정본을 수정하고 산출물 생성·제품 동기화·검사를 수행한다.

## 검증

- 같은 역할의 실제 어댑터 비교: 밝기 2종 × 폭 375·412·1440px × 제품 3종. 18개 조건에서 검사한 디자인 수치 차이 0건.
- 비교 대상: 기본·보조·비활성 버튼, 일반·비활성 입력창, 선택창, 여러 줄 입력창, 배지, 카드, 표 머리글·셀, 진행 표시, 대화상자.
- 비교 항목: 글꼴, 크기, 굵기, 행간, 자간, 모서리, 여백, 주요 높이, 카드 내용 시작점, 비활성 색, 대화상자 규격, 가로 넘침.
- 기존 제품 업무 예시 브라우저 검사: 18개 조건 통과. 대화상자, 포커스 복귀, 테마·모서리 변경 및 비교 모드 전환 포함.
- 배경·로그인 예시 브라우저 검사: 18개 조건 통과.
- 메종 기존 컴포넌트 테스트: 42개 통과.
- 전역 모바일 헤더 높이가 여러 줄 입력창의 지역 변수에 영향받지 않는지 회귀 검사했다.
- 18개 조건에서 필드 전체 높이와 오류 문구 위치를 비교했다. 공통 간격을 8px로, 여러 줄 입력창을 120px로 변경했을 때 세 제품이 함께 따라가고 일반 입력창 높이는 44px를 유지하는지 확인했다.
- 새 비교 검사를 `check-components.mjs --browser`에 연결했다.
- 화면 스타일 추출기도 `--qd-field-gap`을 읽도록 수정했다. 9px 변경이 생성 결과에 반영되는 테스트를 통과했다. 재생성된 화면 CSS에서 바뀐 선언은 이름표 아래 여백 1개이며, 다른 512개 선언은 유지했다.
- 전체 릴리스 검사 `extract-all.mjs --check --only=Q-Atelier,Q-Works,Q-Forge`가 종료 코드 0으로 통과했다. 제품 앱 아이콘 지문 32/32도 일치한다.

최종 전체 검사 로그는 `D:/Claude/tmp/qd-parity-release-final.log`에 있다. 원본 사본, 스타일 목록, 실제 컴포넌트 전달 경로, 제품 동기화와 생성 산출물 대조를 포함한다. 아뜰리에의 기존 `tsconfig.build.json` 변경은 이번 수정에 포함하지 않았다.

기록은 `reviews/component-parity-results.json`, `reviews/component-parity-rule-revalidation.json`, `reviews/component-parity-final-revalidation.json`에 있다. 뒤의 두 파일은 정확한 변경 역변환과 기존 근거의 동일한 소비 지점을 확인한 기록이다. 근거의 지문을 일괄 승인하지 않았다.

이 검사는 기본 공용 부품의 통일성 검증이다. 이전 업무 화면 감사에서 남은 권한·상태·모바일 화면 후보의 전체 완료를 의미하지 않는다.
