# 문장 배치, 앱 소스와 운영 화면 점검

## 반영한 변경

세 제품의 한글 문장은 공통 `keep-all` 규칙으로 단어 단위 줄바꿈한다. 자신의 영역보다 긴 식별자는 `break-word`로 나눈다. 인쇄 문서는 고유 지면 폭을 유지하고 미리보기 영역 안에서 가로 스크롤한다. 조작부의 모서리와 윤곽, 아이콘 단추의 크기와 위험 동작 색상도 큐 디자인 역할 변수에 연결했다.

`patterns/copy-rules.json`에 9개 화면 문구 규칙을 기록했다. 처음 73개 파일의 154개 문구를 수정하고, 메종의 상태 및 창고 안내 6개 문구를 추가해 누적 76개 파일의 160개 문구를 연결했다. 작성 중, 검토 중, 결재 중, 심사 구분과 위험 표 설명을 정리했고, 품질 매뉴얼 초안의 활동 목록에는 구분점을 넣었다. ‘사용 중’ 상태 규칙은 검토한 제품과 파일에만 적용한다. ‘사용중지’ 같은 다른 업무 용어를 부분 치환하지 않는다. 업무 상태 코드, 사용자 입력, 계산, 명시적 줄바꿈은 유지했다. ‘있음 직함’은 [국립국어원 설명](https://www.korean.go.kr/front/mcfaq/mcfaqView.do?mcfaq_seq=9189&mn_id=97&pageIndex=1)에 부합하므로 원래 표기를 유지했다.

문구 전달은 원래 문구와 파일, 구문 종류, 줄 위치를 함께 기록한다. 중앙 규칙을 바꾸면 등록된 문구를 다시 생성한다. 제품의 포맷 설정과 플러그인을 해당 제품에서 불러와 먼저 적용한 뒤 정확한 구문 위치를 기록한다. 포맷 전후 전체 문자열 구문의 종류·내용·순서가 같아야 위치를 옮길 수 있다. 제품에서 해당 구문을 별도로 바꾸면 검사가 실패하며, 업무 데이터까지 일괄 치환하지 않는다.

역할별 권한과 부서별 메뉴의 설명 열은 공통 `--qd-table-description-min-width`를 따른다. 기본 160px, 가로 스크롤 표 안의 설명 역할이며 다른 짧은 식별자 열에 일괄 적용하지 않는다. 인쇄 표의 긴 식별자는 중앙 PrintStyles의 `wrap`을 사용하고, 짧은 날짜는 `nowrap`을 유지한다. 품목 분류표의 코드 셀을 이 규칙에 연결했다. 화면과 인쇄의 값 자체를 바꾸거나 잘라 숨기지 않는다.

감사 기록의 `item_codes.dimension_specs`, `lot_prefix`, `material`, `final_product`와 `process_step`은 검증한 필드 이름과 기존 공정 이름으로 표시한다. 기록의 키와 원래 값, 미지의 값에 대한 대체 표시는 보존한다. 표준 안내서는 기존 숫자 조항 비교기를 연결해 나중에 등록된 하위 조항도 부모 다음에 표시한다. 데이터베이스의 번호, 본문과 저장 순서는 변경하지 않았다.

## 앱 소스

세 Android 앱과 아뜰리에 iOS의 독립 오프라인 화면을 공통 HTML에서 생성한다. 시작 화면의 안내 크기, 좌우 여백과 제품명 크기도 중앙 변수에서 XML과 Swift로 생성한다. Android 안내 문장과 iOS 안내 문장은 화면 폭 안에서 여러 줄로 그릴 수 있도록 수정했다.

세 Android 디버그 빌드와 APK 안의 생성 파일 일치를 확인했다. 오프라인 화면은 세 제품, 두 테마, 320·375·412px, 기본 및 확대된 글자 간격의 36개 조합을 통과했다. Windows에서 iOS 컴파일이나 실제 기기 검사는 수행하지 못했다. 설치된 앱의 시작·오프라인 화면에는 새 앱 버전이 필요하며, 웹 배포만으로 기존 앱 번들이 바뀌지는 않는다.

## 실제 운영 검수

375px 메종에서 승인된 경영 검토 안건서와 보고서의 양쪽 문서 영역, 결재 날짜, 참석자 서명 날짜와 꼬리를 직접 확인했다. 날짜는 각각의 셀 안에 있고 화면 전체 가로 넘침은 없다. 위험 식별 인쇄 시안도 가로 지면 폭을 보존하며 문서 내부에서 스크롤된다. 과거 눌린 모바일 캡처는 발견 당시 증거로 유지하며 새 화면 통과 증거와 구분했다.

운영 아뜰리에 로그인의 입력·테마·주 동작은 375px에서 44px 이상, 모서리 10px이다. 밑줄로 선택을 표현하는 탭은 해당 역할을 유지한다. 카르넷 로그인 조작부도 모서리 10px와 공통 조작 윤곽을 사용한다.

375px 운영 메종에서 권한 설명 열 160px와 표의 상단·중간·하단을 직접 확인했다. 첫 표의 스크롤 높이는 7,501px에서 5,119px로 줄었고, 페이지 전체 가로 넘침 및 셀 내용 넘침은 없다. 모든 권한을 읽거나 모든 가로 스크롤 위치를 검수했다는 뜻은 아니다. 창고 등록 상태는 ‘사용 중’으로 표시된다. 표준 안내서의 7.1.5.1과 7.1.5.2가 부모 다음에 표시되는 것도 운영에서 확인했다.

부서별 메뉴 표도 설명 열 160px와 597개 셀의 내용 넘침 0개를 확인했다. 표의 상단과 하단, 오른쪽 끝의 ‘시스템 관리’ 열을 직접 보았다. 모든 중간 열의 모든 셀을 픽셀로 확인한 것은 아니다. 실제 품목 감사 기록에서는 ‘치수 규격·로트 접두·재질·최종 완제품·완제품 포장’과 ‘사용 중’이 표시되고, 모바일 폭 안에서 항목과 값이 나뉘어 읽히는 것을 확인했다.

## 검사 범위와 남은 항목

웹과 활성 앱 소스의 문자열 49,909개, 파일 3,365개를 수집했다. 이 수집은 한국어 전체 맞춤법의 통과 판정이 아니다. 명시적 개행 후보 382개는 문서·프롬프트·CSS·화면 문장 등 소비처가 다르므로 원문을 보존하고 개별 화면 또는 출력과 대조해야 한다. 문장 간격 검사에 잡힌 메종 인쇄 CSS 주석 한 곳은 화면 문구가 아니다.

공통 스타일 전달 408개, 팔레트 36개와 부품 대조를 통과했고 아이콘 32개는 고정 렌더러와 일치한다. 마지막 위험 표 문구 변경은 기존 위험 평가와 인쇄 폭 시험 32개를 통과했다. 설명 열 8개 조합과 긴 인쇄 식별자 4개 조합의 브라우저 검사를 릴리스 부품 검사에 추가했다. 메종 조항 순서 회귀 8개와 감사 기록 표시 24개 검사도 통과했다.

보관 캡처는 아뜰리에 661장, 메종 855장, 카르넷 295장 모두 직접 확인했다. 메종의 마지막 48장은 식별·추적성, 교육, 창고와 약관 화면이었다. 확인된 그림의 범위는 해시로 기록하며, 로딩 중 화면, 숨은 내부 목록·가로 열, 발견 당시 오류와 실제 운영 수정 증거를 구분한다. 캡처 확인은 모든 업무 상태, 권한, 모바일 폭의 통과를 뜻하지 않는다. 아뜰리에의 미판정 인자 1,036개, 불완전한 화면 증거, 확대 글꼴과 실제 기기 검수는 남는다. 메종과 카르넷의 현재 소스 인자 미판정은 0개다.

## 이후 반영 절차

큐 디자인 소유 규칙을 수정하고 `node tools/extract-all.mjs --sync --only=Q-Atelier,Q-Works,Q-Forge`를 실행한다. 실제 부품 브라우저 검사와 같은 제품 범위의 전체 릴리스 검사를 통과시킨 뒤 제품 변경을 커밋·배포한다. 운영 배포의 커밋과 별칭을 대조한다. 앱 번들 변경은 별도로 빌드하고 앱 버전을 배포한다.

중앙 파일 저장만으로 운영 웹이나 설치된 앱이 즉시 갱신되는 구조는 아니다. 중앙 규칙, 생성, 검증과 배포가 하나의 적용 경로다.
