# 제품 프로필의 모바일 선택 그룹과 안내 문구 정돈

아뜰리에 제품 정보 양식에서 멸균 방식과 작동 원리 선택 그룹이 좁은 카드 안에서 넘치던 문제를 수정했다. 운영의 수정 전 390px 화면에서 카드 내부 너비는 278px이며, 두 그룹의 내부 넘침은 각각 18px와 25px였다. 페이지 전체 너비만 검사하면 드러나지 않는 문제여서 그룹 내부와 버튼 내용 너비를 함께 확인한다.

## 중앙 규칙

`components/ProductProfileWizard.tsx`의 `RadioGrid`는 중앙 구현의 `foldGrid`를 사용한다. 최대 열 수는 기존 `QDPresentation.rendererInputs.gridColumns`의 2·3·4이며, 최소 열 너비는 `QDPresentation.choiceMinColumn[110]`, 간격은 `QDScale.space[2]`에서 받는다. 좁은 화면에서는 들어갈 수 있는 열 수로 접고 넓은 화면에서는 원래 배치를 유지한다. 71단계의 다음 후보 문단에 적었던 `QDPresentation.visual.choiceMinColumn`은 후보 조사 중의 잘못된 경로다. 실제 정본의 위치는 `QDPresentation.choiceMinColumn`이다.

안내의 `공공 DB 에서`를 `공공 DB에서`로 고쳤다. `patterns/copy-rules.json`의 `profile-public-db-particle-spacing`과 `dist/q-design.copy-bindings.json`으로 해당 파일의 해당 JSX 문구를 연결했다. 중앙 문구를 바꾸면 원래 문구를 기준으로 그 위치에 다시 내보낸다. 다른 제품·파일, 사용자 입력과 업무 데이터는 이 규칙의 대상이 아니다.

제품 변경 커밋은 `fe430c4dc312dc2026c4b3b5ca60ff3acd7aa035`다. 제품 파일의 변경은 레이아웃 표현식 한 곳과 안내 띄어쓰기 한 곳이며, 선택 항목·설명·선택 상태·선택 해제 콜백은 유지한다.

## 검증

- 실제 렌더러와 실제 선택 항목으로 밝은·어두운 테마, 320/375/390/430/768/1280px, 격리 배치·운영 카드 배치의 24개 사례를 검사했다. 수정 전 넘침은 14개 사례에서 재현됐고 수정 후에는 페이지·그룹 내부·버튼 내용의 넘침이 없었다.
- 768px 이상 사례에서는 기존과 실제 열 너비·버튼 너비·높이가 같았다. 중앙 최소 너비를 110에서 160으로 바꾸거나 CSS 간격·모서리 값을 바꾼 격리 시험에서도 변경이 실제 렌더러로 전달되고 내용이 넘치지 않았다. 이는 시험한 값과 문구에 대한 근거이며 임의의 모든 글꼴·치수 조합을 보장하지 않는다.
- 소스 전체와 실제 가져오기 심볼을 대조했다. 같은 이름의 다른 변수, 잘못된 최소 너비, 직접 지정한 간격, 동작 변경과 관계없는 파일 변경은 승인하지 않는다. 문구 바인딩 시험은 중앙 문구 변경이 정확한 JSX 위치 한 곳에 전달되는지도 확인한다.
- 이전 보고서 7개의 유지된 인자 13개, 근거 43개, 호출자·선언 메타데이터 28개를 재검증했다. 정확한 역변환으로 이전 보고서 전체 지문을 확인하며, 새 레이아웃 표현식을 이전 규칙으로 포괄 승인하지 않는다.
- 전체 판정 53,991개 중 정확히 두 레이아웃 기록만 중앙 조합으로 판정했다. 나머지 53,989개는 유지된 인자·근거 지문을 제외한 모든 필드와 순서를 보존했다. 미분류는 813건에서 811건이 됐다.

전체 세 제품 릴리스 검사는 종료 코드 0으로 통과했다. 공통 구현·정본 사본·앱 인자를 대조했고 앱 아이콘 32개도 모두 일치한다. 새 문구 연결 후 별도 문구 검사는 87개 파일에서 통과했다. 제품 Next.js 운영 빌드와 변경 관련 시험도 통과했다. 로그는 로컬 `D:/Claude/tmp/qd-phase72-release.log`, `qd-phase72-atelier-build.log`, `qd-phase72-browser.log`에 보관한다.

운영 반영과 실제 화면의 수정 후 검증을 진행 중이다. 수정 전 관찰은 `reviews/phase72-operating-profile-before.json`, 로컬 브라우저 근거는 `reviews/profile-responsive-browser.json`이다. 배포 완료와 수정 후 관찰을 확인한 뒤 이 문단을 갱신한다.

## 남은 범위

미분류 811건에는 실제 스타일로 확인된 511건과 추가 소비자 추적이 필요한 항목이 섞여 있다. 모두 하드코딩 오류라는 뜻은 아니다. 현재 인벤토리에서 공통 `lib/design/components.tsx`의 106건, 모바일 업무 부품의 21건, 결재선 편집기의 19건, 구독 표시의 17건 등이 다음 조사 대상이다. 이 숫자는 우선순위 자료이며 완료 판정이 아니다. 이번 단계에서 이전 전체 화면 540개 대상과 이미지 2,330개를 다시 촬영하지 않았다.

큐 디자인 변경은 생성, 사본 동기화, 제품 검사·빌드, 운영 배포를 거쳐 반영된다. 파일 저장만으로 운영이 즉시 바뀌지는 않는다. 이번 수정은 기존 중앙 값을 사용하는 아뜰리에 소비자의 연결이며 메종·카르넷 운영 코드는 변경하지 않았다. Android 실제 설치 검증은 남아 있고 iOS 검사는 사용자 요청에 따라 제외한다.
