# 공통 모노 글꼴 자원과 운영 반영

메종은 공통 글꼴 변수가 JetBrains Mono를 지정해도 실제 글꼴 등록이 없어 기기 글꼴로 대체될 수 있었다. 카르넷은 기존 Latin 글꼴 등록이 있으므로 누락으로 분류하지 않는다. 기존 파일은 중앙 캐시의 Latin 파일과 전체 바이트가 같았다.

patterns/mono-fonts.json에서 두 Unicode 범위, 400~800 굵기, swap 정책과 공식 라이선스를 관리한다. build-mono-fonts.mjs가 검증된 파일을 세 제품의 public/fonts/jetbrains-mono에 내보낸다. 메종과 카르넷은 중앙 CSS 사본을 루트에서 불러온다. 아뜰리에의 기존 Pretendard 92개 선언과 모노 2개 선언은 유지하고 생성 경로를 중앙에 연결했다. 제품의 독립적인 글꼴 검사에는 외부 큐 디자인 폴더가 필요하지 않다.

공통 글꼴 테스트 4개, 기존 문구 테스트 7개가 통과했다. 실제 CSS와 글꼴 전체 파일을 사용하는 독립 브라우저 검사 36개도 통과했다. 세 제품, 밝음·어두움, 320·1280px, 400·600·800 굵기에서 Latin·숫자 표본의 실제 렌더러가 JetBrains Mono 글리프를 사용함을 확인했다. 중앙 family 변경 후 실제 글리프 선택이 바뀌는 것도 확인했다. 이 검사는 한글 전체, 모든 운영 화면, 모든 기기의 글꼴 검수 완료를 뜻하지 않는다.

아뜰리에 정상 pre-push 검사 4,667개 통과, 예상 실패 1개, 제외 3개를 확인했다. 메종과 카르넷 타입 검사는 이 변경의 배포 전에 통과했다. 이후 운영 메종의 별도 /store 탭에서 공통 모노 face 2개가 실제 전달 CSS에 등록된 것을 확인했다. 사용자가 작성 중인 /store/new는 유지했다. 카르넷 운영에서도 기존 face와 중앙 face 등록을 함께 확인했다.

전체 릴리스는 현재 통과로 기록하지 않는다. 글꼴 배포 이후 사용자가 메종을 병행 수정 중이라고 확인했다. 메종의 기존 문구 바인딩 위치와 루트 검수 근거가 달라져 전체 검사에서 실패했다. 해당 변경을 덮어쓰거나 임의로 승인하지 않았다. 마지막으로 완료된 전체 릴리스는 78차의 586개 통과, 실패 0개, 아이콘 32/32다. 카르넷 루트의 모노 import만 추가됐다는 역검증 12건은 별도로 통과했다.

중앙 수정은 생성, 동기화, 제품 배포를 거쳐 운영에 적용된다. 중앙 파일 저장만으로 현재 운영 서버가 즉시 바뀌지는 않는다. 79차 이후에도 아뜰리에 미분류 582건은 남아 있다.
