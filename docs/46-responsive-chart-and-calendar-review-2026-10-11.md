# 모바일 차트, 달력과 파일 선택 규칙 점검

아뜰리에 차트의 글자가 모바일에서 가로로 눌리는 문제를 수정했다. 메종 운영 화면에서는 공급자 등록의 파일 선택 영역이 약 30px이고, 바코드 등록 달력이 본문에 6px의 내부 가로 넘침을 만드는 것도 확인했다. 이 두 제어의 공통 규칙은 세 제품의 생성 CSS에 연결했다.

## 중앙 규칙

| 대상 | 큐 디자인 원본 | 적용 방식 |
| --- | --- | --- |
| 차트 축 | `source/design/chart-layout.ts` | 현재 아뜰리에의 실제 차트 소비처로 생성한다. 화면 폭과 글자 크기를 측정하고 축 밀도, 여백과 정렬을 중앙 함수에서 계산한다. |
| 파일 선택 | `patterns/foundation.css` | 숨겨진 파일 입력을 직접 포함하는 사용자 정의 라벨에 공통 높이, 글꼴, 여백, 모서리와 키보드 포커스 표시를 적용한다. |
| 모바일 달력 | `patterns/foundation.css` | 달력이 들어 있는 공통 팝업을 640px 이하에서 화면 안에 배치한다. 한 달의 일곱 열은 폭을 고르게 쓰고, 석 달 기간 선택은 내부 가로 이동을 유지한다. |
| 판매 행 삭제 | `patterns/components.css`와 `patterns/foundation.css` | 약 20px였던 로컬 아이콘을 기존 공통 `qd-control-icon` 역할에 연결한다. 크기, 모서리와 위험 동작 색을 중앙 규칙에서 받는다. |

차트는 실제 데이터 인덱스 위치와 축 글자의 기준점을 맞춘다. 날짜 문자열을 자르지 않고 줄바꿈하며, 글자 크기를 바꾸면 축 여백과 표시 개수를 다시 계산한다. 기존 데이터, 목표값, 추세, 단위와 두 업무 화면의 의미 색은 유지한다. 현재 이 차트 모듈의 실제 소비처는 아뜰리에다. 세 제품에 같은 차트가 있다고 판정하지 않는다.

파일 선택 영역은 기본 44px 이상이고, 확대 글자에서는 내용에 맞춰 더 높아진다. 파일 형식, 선택 처리와 필수 검증은 기존 입력이 담당한다. 달력은 기존 DOM 부모, 날짜 제한, 날짜 선택과 닫기 처리를 유지한다. 짧은 화면에서는 팝업 내부로 세로 이동할 수 있다.

## 실제 부품 검증

차트는 제품의 실제 컴포넌트를 실행해 320·375·1,280px, 글자 12·24px, 밝음·어두움의 12개 조합을 통과했다. 모든 조합에서 SVG 가로 배율은 1이며, 날짜 겹침과 잘림이 없다. 데이터 점 60개, 정확한 날짜 기준점, 창 크기 변경, 실행 중 글자 변경, 한 점·빈 데이터와 긴 문장도 확인했다.

달력과 파일 선택은 메종의 실제 DatePicker·Calendar·DateRangePicker와 원문에서 추출한 변경 없는 FilePick 함수를 실행했다. 세 폭, 글자 13·24px와 두 테마의 12개 조합에서 페이지·본문 가로 넘침이 없다. 일곱 날짜 열의 폭과 높이를 확인했고, 126개 날짜를 가진 석 달 기간 선택도 유지한다. 중앙 높이를 48px, 모서리를 14px로 바꾸면 두 제어에 함께 반영된다. 480px 높이 화면의 팝업 경계, 날짜 제한, 날짜 선택, Escape와 외부 클릭도 확인했다.

같은 12개 조합에서 실제 SaleItemsTable의 삭제 버튼은 44px 이상, 모서리 10px와 공통 20px 아이콘을 사용한다. 검수용 두 줄 중 한 줄을 지우면 마지막 줄의 삭제 버튼이 비활성화되는 것도 확인했다. 저장이나 운영 데이터 변경은 하지 않았다. 기존 행 데이터 조합 두 곳은 아이콘 클래스와 장식 SVG 속성만 역변환하면 원문 전체가 같은 경우에만 재검증했다.

세 제품의 공통 부품 대조 18개 조합은 차이가 없다. 중앙 인자 전달 408개와 팔레트 36개, 앱 오프라인 화면 36개 조합을 통과했다. 세 Android 디버그 빌드와 APK 안의 최신 생성 HTML 일치도 확인했다. 정식 서명 앱은 그대로이며, iOS 컴파일과 실제 기기 검수는 수행하지 못했다.

기존 중앙 근거는 신규 규칙 블록을 제거하면 기존 선언 전체와 같고, 각 소비처의 원문 해시가 같은 경우에만 갱신했다. 중앙 사본의 지문도 따로 확인했다. 미분류 인자를 일괄 승인하지 않는다.

## 운영 및 남은 범위

아뜰리에 차트 커밋 `99bfeabfb129314b505c286167d1bb9ab69fc059`는 운영 배포 `dpl_36mC5QP3Rf68YegtRYxvjY68ddKz`의 READY 상태와 세 운영 별칭을 확인했다. 로그인된 운영 업무 화면의 차트를 새로 확인한 것은 아니며, 위 차트 검사는 실제 컴포넌트에 예시 데이터를 넣은 검증이다.

달력·파일 선택 추가 수정은 세 제품의 최종 릴리스 검사와 아이콘 32개 대조를 통과해 운영 배포 READY를 확인했다. 판매 행 삭제 아이콘 추가 수정도 마지막 릴리스 검사와 메종 운영 배포를 확인했다. 최종 운영 상태와 실제 메종 화면의 재검수 결과는 `reviews/production-copy-native-release-results.json`에 기록한다.

메종 운영 375px에서도 달력은 좌우 12px 안쪽, 상단 185.5px부터 하단 626.5px에 있고, 본문의 내부 가로 넘침이 없다. 파일 선택 두 영역은 높이 44px와 모서리 10px다. 공급자·바코드·매장 판매의 기본 등록 양식, 판매 표의 왼쪽부터 오른쪽 끝 열과 양식 하단을 직접 확인했다. 캡처와 측정은 각 운영 검수 JSON의 이미지 해시로 연결한다.

메종 최신 운영 커밋 `a74d7ab64bba6b2f2bd7dbcbf6ba7fc7c8f60f1c`에서도 판매 행 삭제 버튼은 44×44px, 모서리 10px, 아이콘 20px로 측정했다. 본문 폭과 스크롤 폭은 모두 365px이며, 넓은 판매 표만 내부에서 가로 이동한다. 운영에서는 마지막 한 줄의 비활성 상태만 확인했으며, 삭제 동작 검사는 별도 실제 부품 예시에서 수행했다.

보관된 기존 이미지 1,811장은 확인했지만, 아뜰리에 미분류 인자 1,006개와 불완전하거나 빠진 화면 검수 대상 63개가 남는다. 운영의 기본 등록 양식을 재검수한 것은 로컬 역할별 예시 데이터 화면의 검수 완료와 구분한다. 모든 업무 상태·권한·기기 인증을 완료한 것은 아니다.

큐 디자인 변경은 생성, 동기화, 검증과 제품 배포를 거쳐 운영에 반영한다. 중앙 파일을 저장하는 것만으로 운영 웹이나 기존 설치 앱 번들이 즉시 바뀌지는 않는다.
