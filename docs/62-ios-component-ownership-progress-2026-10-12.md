# iOS 표현 컴포넌트의 정본 연결

기존 아뜰리에 iOS의 `LaunchView.swift`와 `ToastView.swift`를 큐 디자인의 명시적인 정본 구현으로 등록했다. 정본은 `patterns/native/ios/`의 두 파일이며, `tools/build-ios-components.mjs`가 생성 사본과 실제 앱 소스를 대조·동기화한다. 전체 생성·동기화 절차와 릴리스 검사에 연결했다. 기존 웹 정본 29개와 Android 시작 화면 정본 3개를 대체하거나 그 집계에 합치지 않는다.

기존 iOS 커밋 `b3f9328`의 전체 파일과 대조해 실제 두 앱 소스가 그대로임을 확인했다. 배경, 모서리 10px, 글자·여백, 안내 메시지, 그리기·모션, 생명주기와 접근성 처리는 변경하지 않았다. 총 565개 파일 행에는 주석과 빈 줄도 포함되므로 디자인 인자 565개로 세지 않는다. 대조 기록은 `reviews/ios-component-ownership-proof.json`이다.

정본의 시작 시간과 안내 메시지 모서리를 각각 수정한 별도 임시 작업 공간에서 낡은 앱 소스가 검사에 실패하고 동기화 후 모두 일치하는지 확인했다. 이 임시 값은 실제 앱에 적용하지 않았다. 다른 제품만 선택하면 기존 iOS 앱 소스를 바꾸지 않는다. 기존 줄 끝을 보존하고 같은 파일은 다시 쓰지 않는다. 알 수 없는 컴포넌트·제품, 잘못된 정본, 불완전한 치환과 금지 문자를 거부한다. 생성 파일에 추가 변경이 생겨도 검사에 실패한다. 회귀 검사 3개가 통과했다.

공용 크기·문구 규칙과 배경 팔레트는 기존 생성 리소스를 계속 사용한다. UIKit·CoreText, 시스템 글꼴 확대, 동작 줄이기, 실행 입력, 앱 로고·글꼴 자산과 외부 `Palette`의 색은 별도 경계다. 두 정본의 모든 값이 웹의 공통 토큰 하나에 연결됐다고 승인한 것은 아니다. 다른 iOS 컴포넌트나 존재하지 않는 메종·카르넷 iOS 앱으로 범위를 확대하지 않는다.

Swift 파일도 큐 디자인의 금지 문자 검사에 포함했다. 설치된 정본 브라우저 경로 없이 실행한 첫 릴리스 검사는 아이콘 단계에서 실패했다. 아이콘 지문을 변경하지 않고 이미 설치된 Chromium 경로를 지정해 전체 검사를 다시 실행했다. 최종 `extract-all --check --only=Q-Atelier,Q-Works,Q-Forge`가 종료 코드 0으로 통과했고, 아이콘 32개가 기존 정본과 일치했다. 두 실제 iOS 소스의 일치와 회귀 검사도 릴리스 검사에 포함했다. 금지 문자·변경 공백 검사도 통과했다.

실제 앱 소스 변경이 없어 이번 단계의 제품 빌드·운영 배포 대상은 없다. iOS 컴파일·시뮬레이터·설치 기기·서명·배포를 검증한 기록은 아니다. iOS 저장소에는 새 커밋이나 푸시를 하지 않았다. 큐 디자인에서 정본을 변경한 뒤에는 생성·동기화와 Mac에서의 앱 빌드·서명·배포가 필요하다. 웹의 미분류 867개와 남은 화면 상태 검토는 그대로 유지한다.
