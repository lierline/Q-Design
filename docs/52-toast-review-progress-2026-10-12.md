# 공통 알림 검수 진행 기록

세 제품 알림의 너비, 안전 영역 여백, 줄바꿈을 Q-Design 공통 규칙으로 연결했다. 메종의 기본 흰색 원형 닫기 버튼도 중앙 규칙을 따르도록 수정했다. 이번 범위는 실제 공통 알림 부품이며 모든 업무 화면과 상태의 완료 인증은 아니다.

## 수정과 근거

아뜰리에 운영 업데이트 알림에서 한국어 단어가 중간에 끊기는 현상을 출발점으로 삼았다. 아뜰리에의 직접 지정 줄바꿈과 메종 라이브러리 기본 줄바꿈이 중앙 정책을 우회하고 있었다. 카르넷에서는 `calc(100vw-2rem)`에 필요한 연산자 공백이 없어 너비 제한이 적용되지 않았고, 긴 식별자가 화면 밖으로 나갔다.

`patterns/foundation.css`가 알림 최대 너비 360px, 화면 가장자리 여백과 안전 영역, 한글 단어 유지, 긴 식별자 줄바꿈을 소유한다. 실제 ToastProvider, Sonner 어댑터, Toasts가 같은 너비·여백 토큰과 `.qd-toast`의 문구 정책을 사용한다. 텍스트의 flex 최소 너비도 중앙 0값을 읽는다. 메시지 내용, 성공·오류 판정, 유지 시간, ARIA 역할과 닫기 동작은 보존했다.

메종 닫기 버튼은 알림 내부 오른쪽에 배치하고 중앙 제어 크기와 10px 모서리, 보조 글자색, 호버·키보드 초점을 따른다. 라이브러리의 기본 원형 흰색 면과 바깥 배치를 제거했다.

줄바꿈 CSS 변수를 React의 제한된 속성에 직접 넣었던 초기 수정은 타입 검사에서 실패했다. 아뜰리에는 정상 배포 전 검사에서 차단됐고, 메종의 첫 배포도 실패했다. 직접 속성 할당을 제거하고 공통 CSS 클래스로 옮긴 최종 수정은 두 제품의 전체 타입 검사와 세 제품 실제 알림 어댑터의 설치된 타입 검사를 통과했다. 공통 검사에 타입 검사와 과거 오류를 다시 주입하는 회귀 확인을 추가했다. 타입 단언이나 검사 우회는 사용하지 않았다.

## 검증

밝은·어두운 테마, 1280·390·375px 화면에서 실제 세 제품의 한국어 문구와 긴 식별자 알림 36개 조건을 검증했다. 단어 내부 줄바꿈, 메시지·화면 넘침, 너비·여백 적용 실패는 0건이었다. 공통 줄바꿈, 너비, 여백, flex 최소값을 바꾸면 세 제품의 실제 표시가 함께 바뀌었다. 메종 닫기 버튼 모서리 변경도 전파됐다. 실제 데스크톱과 390px 브라우저 화면을 직접 확인했다. 갤러리 검증 이미지는 업무 화면 증거 개수에 더하지 않았다.

공통 컴포넌트 계약과 전체 릴리스 검사가 통과했다. 아이콘 정본은 Chromium 151.0.7922.34, Playwright 1.62.1, sharp 0.34.5, libvips 8.17.3 조합이며 앱 아이콘 32개 지문이 모두 일치했다. 중앙 표시 인자 변경 408개와 생성 팔레트 확인 36개도 실패가 없었다.

기존 검토 기록은 변경하지 않은 원문과 정확한 선언 줄을 대조한 항목만 유지했다. 생성 사본은 이번 정본 변화만 포함하는지 확인했다. 카르넷 너비의 기존 추출 기록에는 원래 식을 보존하고 현재 호출을 새 공통 토큰과 정확한 소스 변경 증거에 연결했다. 새 메종 시각 인자 3개는 실제 설치된 Sonner 타입과 정본 선언을 근거로 별도 검토했다. 검사 지문을 임의로 맞추거나 미분류 항목을 일괄 승인하지 않았다.

추가 CSS 계산식 진단은 확인 가능한 소비 문맥 250개가 유효했다. 직접 소비 문맥이 없는 사용자 변수 165개와 미해결 문맥 1개는 정상으로 판정하지 않았다. 이 진단은 390px 어두운 갤러리의 문법 확인이며 전체 화면 인증이 아니다.

Android 세 앱을 최종 실제 자산으로 재빌드해 APK·AAB 6개의 포함 오프라인 자산, 컴파일된 중앙 팔레트·줄바꿈 전략과 릴리스를 대조했다. 오류 0개, 앱별 기존 린트 경고 9개다. 최종 로컬 커밋은 아뜰리에 `ce01b0a`, 메종 `1e5f836`, 카르넷 `82b5943`, iOS `b3f9328`이다. Android 산출물은 서명 전이며 설치 기기와 iOS 빌드는 검수하지 않았다.

## 웹 배포

최종 웹 커밋은 아뜰리에 `f794024ddccbdc7f8f6b4e4c8b599bc85ac830ee`, 메종 `c505e23c615eb728edbde959badf9f074b1f796e`, 카르넷 `8fcd78bbf0250543e93e718ce1ebee5dc3bcd72a`다. 세 배포가 모두 READY이고 해당 커밋 및 운영 주소 연결과 일치한다. 주소 연결 오류는 없다. 아뜰리에 `dpl_HTu2p9yZxdbZdVHqPKg1jSddqujg`, 메종 `dpl_8PtazZjRmSD1c4KCB2CyNe3v3kzC`, 카르넷 `dpl_DGAQtLwPaBktoXFsKQB7GN1SuHJr`다.

아뜰리에의 정상 배포 전 검사에서 타입 검사, 테스트 4,667개 통과(예상 실패 1개, 제외 3개), 린트 오류 0개를 확인했다. 기존 경고는 1,573개다. 최종 공통 CSS 방식으로 브라우저 검사 15개도 모두 통과했다. 운영 아뜰리에 전문가 로그인, 메종 판매 등록, 카르넷 로그인에서 공통 알림 최대 너비 360px, 20px 가장자리 여백과 중앙 `.qd-toast` 줄바꿈 규칙이 실제 로드되는 것을 확인했다. 운영 메시지를 임의로 만들거나 폼을 제출하지 않았다.

## 남은 범위

미분류 스타일 인자는 아뜰리에 900개, 메종 0개, 카르넷 0개다. 등록 역할별 주소 540개는 실제 화면 523개와 정상 제한·주소 이동 17개로 구분한다. 업무 화면 이미지 판정은 2,330개이며 과거 결함과 불완전 캡처도 포함한다. 추가 모바일·테마·입력·상호작용 상태, 네이티브 시각 인자와 설치 기기 확인, 앱 서명·배포, iOS 빌드는 남아 있다.

Q-Design 수정은 생성·동기화·제품 빌드·배포를 거쳐 웹에 적용된다. 앱에 포함되는 자산 변경은 재빌드와 서명·배포가 필요하다. 모든 화면과 모든 인자가 중앙 제어된 상태라고 인증하지 않는다. 원본 업무 화면과 전용 계정·초대 정보는 비공개 검수 증거로 보관한다.
