## 왜

오너 지적(2026-09-27): 「모든 컴포넌트에 왼쪽 강조 라인이 붙어 있는데… 클로드 특유의 디자인
형태라서 다른 디자인 형태를 고안하고 싶다. 지금 화면의 구조가 적절하지 않은 기분도 든다.」
그리고 원칙 하나: **「눈을 현혹하는 디자인보다 깔끔하게 눈에 잘 보이는 디자인」.**

상자 한쪽에 굵은 색 선을 긋는 강조(`borderLeft: 3px solid …`)는 오너 금지 목록에 9월 1일부터
있었습니다(«카드 한쪽의 굵은 컬러 보더»). 그런데 [클리셰 걸러내기](19-ai-cliche-screening.md)
도구가 이 항목을 세지 않았고 제품 쪽 계약도 없어, Q-Atelier 에만 188곳이 남았습니다.
금지 목록과 걸러내기 도구가 **서로 다른 목록을 보고 있었던 것**이 원인입니다.

대체의 근거는 오너가 정한 문서 기준(`D:/Claude/document-standards/STYLE_GUIDE.md`)입니다.

> 카드와 장식 상자는 상시 사용하지 않는다. 작은 강조문은 금색 라벨과 얇은 가로선 사이의
> 한두 문장으로 표현된다. 표는 진한 상단선 또는 머리행 아래 선, 연한 회색 행 구분선.

화면과 문서가 한 결이 됩니다.

## 정한 것

| 자리 | 쓰는 것 | 버리는 것 |
|---|---|---|
| 결재 화면(결재함 · 문서의 결재 관리 판) | **가로 결재 길**: 작성 → 검토 → 승인 한 줄. 지나온 칸은 옅은 금빛 원에 체크 · 서명 시각, 지금 차례는 금빛 겹원과 «지금», 남은 칸은 빈 원 | 카드 왼쪽 금색 선 · 종류별 큰 아이콘 · 카드 속 파일 상자 |
| 상태가 있는 항목 목록 | **괘선 목록**: 상자 없이 행 사이 가는 선, 상태는 오른쪽 **글자**(상태 색) | 항목 카드의 왼쪽 색 선 |
| 안내 · 주의 · 경고 | **강조문**: 금색(주의는 호박색 · 위험은 붉은색) 라벨 한 단어 + 한두 문장, 위아래 가는 가로선 사이 | 왼쪽 색 선 상자 · 큰 아이콘 |
| 지표 | **요약표**: 진한 윗선, 칸 사이 세로 가는 선, 숫자는 고정폭 글꼴 | 지표 카드의 왼쪽 색 선 |
| 열이 많은 목록 | **장부 표**: 열 머리 + 진한 윗선 + 머리 아래 선 + 연한 행 선, 합계는 겹밑줄, 세로 테두리 없음 | 행 왼쪽 색 선 |
| 절(구획) 머리 | 금색 두 자리 번호(고정폭) + 굵은 제목 + 먹색 선 | 머리 위 작은 대문자 라벨(eyebrow) |
| 선택된 메뉴 | 굵은 글자 + 글자 밑 짧은 금색 선(16px) | 메뉴 왼쪽 색 막대 |

**읽힘 규칙**(원칙 「깔끔하게 눈에 잘 보이게」):

- 상태는 **색만으로 말하지 않는다**. 늘 글자(«지연 3일» · «오늘» · «예정»)가 같이 간다
- 상태 · 이름 글자는 12px 이상. 흐린 글자는 대비 4.5:1 을 넘는 토큰만(`T.subtle` · `T.muted`)
- 금빛과 가는 선은 아껴 쓴다. 한 화면에 금빛 강조가 여럿이면 그중 하나만 남긴다

### 정본 CSS (받는 제품이 쓰는 것)

`tools/extract-nav.mjs` · `tools/extract-list.mjs` 가 위 부품을 읽어 같은 모양을 냅니다(2026-09-27).

- `.qd-nav-item`: 왼쪽 금막대 대신 `padding-left` 17px, 선택은 굵은 글자와 이름표의 `::after` 밑줄(한 번 펼쳐짐).
  이름표는 말줄임 때문에 넘친 것을 자르므로 밑줄 자리를 아래 안쪽 여백으로 만들고 같은 만큼 바깥 여백을 줄입니다.
  걷은 금점(`.qd-nav-dot`)은 받는 제품 마크업에서 걷을 때까지 `display: none` 으로 둡니다.
- `.qd-row`: 괘선 줄(행 아래 가는 선 · 모서리 없음 · 떠오름 없음 · 누르면 옅은 바탕). 줄 사이 8px 띄움도 걷었습니다.
- `.qd-panel--accent · ok · warn · danger`: 왼쪽 3px 대신 테두리 전체를 옅은 상태 색(원본 Bx 와 같은 55%).
  🔴 주의(호박색)와 금은 색차가 작아(ΔE76 10.37) 종전에는 세로줄로 갈랐습니다. 이제는 판 안의 **글자**가 가릅니다.
- `.qd-state-error`(못 읽은 자리): 왼쪽 선 대신 위아래 붉은 가는 가로선(원본 Alert 와 같은 규칙).

받는 세 제품으로 내려보내기(이행 순서 4 · 2026-09-27): Q-Carnet · Q-Sonar 는 `sync.mjs --write --only=Q-Sonar,Q-Forge`
로 내려보내고, 두 제품의 계약 검사가 찾던 옛 글자(금막대 `border-left: 3px solid transparent` · 카드 여백 `16px 18px` ·
마크업의 `qd-nav-dot`)를 새 정본 글자(`padding-left: 17px` · 선택 밑줄 `::after` · 괘선 줄 `14px 6px`)로 바꿨고 마크업의
금점을 걷었습니다. 🔴 Q-Maison 은 화면 검토 세션이 그 작업 폴더에서 커밋 안 된 고침을 들고 일하는 중이라, 폴더가 빈 뒤에
같은 일을 합니다(`--only` 는 그래서 생겼습니다). 세 제품에서 금점 마크업이 다 빠지면 정본의 다리(`.qd-nav-dot { display: none }`)도 지웁니다.

## 되돌아오지 않게

- Q-Atelier `lib/design/no-side-accent.test.ts`: 굵기 2px 이상 옆 색 선(`borderLeft` · `borderRight` ·
  CSS `border-left` · `border-right`)을 센다. **188 에서 동결**(2026-09-27), 부품 1차 뒤 **180**. 늘면 배포 빌드가 멈춘다.
  줄였으면 기준을 낮춰 다시 동결한다. 1px 옆 선은 나무 줄 · 칸 구분 같은 구조선일 수 있어 세지 않는다.
- ✅ [클리셰 걸러내기](19-ai-cliche-screening.md) 도구(`tools/screen-ai-cliches.mjs`)에 «옆 색 선» 항목을 더했다
  (2026-09-27 · 같은 규칙 · 주석 줄 제외). 첫 실측 Q-Atelier 화면 183 · 메일 16.
- 정본 생성기가 원본 부품에 왼쪽 선이 다시 생기면 멈춘다(`extract-list.mjs` 가 Bx · Alert 구역에서 `borderLeft` 를 찾으면 실패).

## 보여 주고 물린 시안 (다시 내밀지 말 것)

2026-09-27 대화 속 움직이는 시안으로 네 차례 골랐습니다. 오너는 매번 «다른 디자인 더» 로 넓혔고,
꾸밈 하나를 바꾸는 안보다 **화면을 세우는 방식이 다른 안**에 반응했습니다.

- 카드 꾸밈: 문서 머리띠 + 결재 도장 · 선 없이 면 · 모서리 재단 표시
- 결재함 세우기: 결재란 서류 · 목록과 아래 시트 · 한 문장 조판 (가로 결재 길만 채택)
- 강조 체계: 마름모 표식 · 책갈피 리본 · 면 색조 · 인주 도장 · 선의 모양(실선 · 점선 · 겹선) · 기한 실
- 문서 결 갈래: 목차 결(점선 잇기) · 여백 주석 (문서 결 기본 + 장부 결만 채택)
