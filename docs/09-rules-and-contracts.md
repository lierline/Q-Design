# 규칙과 계약

이 시스템에서 가장 옮길 가치가 있는 부분입니다.

토큰과 색은 취향이지만, **아래 26개는 「디자인이 시간이 지나도 안 무너지게」 하는 장치**입니다.
원본은 이것들을 문서가 아니라 **테스트**로 두었습니다. 문서는 안 읽히지만 테스트는 실패하기 때문입니다.

전문은 `source/contracts/` 에 있습니다. 그 폴더는 손으로 베낀 사본이 아니라
`node tools/refresh-source.mjs --write` 가 원본 저장소의 **커밋된** 내용에서 받아옵니다(㉖).

> 계약은 값이 아니라 **되돌아가는 것**을 막습니다.
> 2026-09-10 에 일곱 가지를 고치고 세어 보니 «규칙이 된 것» 은 셋뿐이었고 넷은
> 「고쳤지만 다음 사람이 다시 쓸 수 있는」 상태였습니다. ⑲~㉕ 가 그 넷을 메운 것입니다.

---

## 왜 문서가 아니라 테스트인가

원본에서 실제로 일어난 일들입니다.

- 색을 두 곳(`tokens.ts` · `globals.css`)에 적어 두었더니 한쪽만 고쳐져 라이트 모드에서 금색이 두 가지가 되었습니다
- 주석에 「4.5:1 통과」라 적어 두었는데 실제로는 4.45 였습니다
- 「하프스텝은 미세조정용」이라 적어 두었는데 실제로는 표류값이 되어 한 화면에 글자 크기가 12종이 되었습니다
- 「우회 함수는 둘뿐」이라 적어 두었는데 셋이었습니다

> **적어 둔 규칙은 지켜지지 않습니다. 실패하는 규칙만 지켜집니다.**

## 1. 색

### ① 대비: 텍스트 토큰이 «모든» 표면 위에서 AA

`contrast.test.ts`

```
표면 3종(bg · surface · surface2) × 텍스트 8종      = 24가지 조합 전부 4.5:1 이상
표면 3종               × 상태색 7종  × 2테마 = 42가지 + 배지 실조건 14가지
```

실패 메시지에 이렇게 적혀 있습니다.

> 색을 고칠 때는 **가장 어려운 표면**(대개 surface2)을 기준으로 잡을 것.
> bg 하나만 보고 맞추면 카드 위에서 조용히 미달한다.

인쇄 팔레트도 같은 검사를 받습니다. 심사원은 출력물을 읽기 때문입니다.

**배지는 순수 표면 위에 놓이지 않습니다.** `Tag` primary 가 `alpha(색, 0.1)` 배경을 깔기
때문에 글자가 놓이는 바닥은 «표면 + 그 색 10%» 이고 대비가 더 낮습니다.
계약은 그 **실조건까지** 잽니다. [색 문서 7절](02-color.md) 참조.

> 2026-09-10 이전에는 상태색 7종이 이 목록에 **없었습니다.** 더 엄격히 재니
> 일곱 중 여섯이 미달이었고, 가장 흔한 `gray`(초안·미시작)가 3.46 으로 가장 나빴습니다.
> 색상·채도는 두고 **명도만 3~8%p** 옮겨 고쳤습니다.
> 🔑 그때 배운 것: **「가드가 있다」는 「전수를 본다」가 아닙니다.**

### ② 팔레트 사본 동기화

같은 색이 TS 상수와 CSS 변수 두 곳에 있습니다. 계약이 값을 대조합니다.
한쪽만 고치면 실패합니다.

### ③ 다크/라이트 변수 집합 동등성

`theme-parity.test.ts` · 두 테마가 **정확히 같은 변수 이름 집합**을 정의해야 합니다.
라이트에만 없는 변수가 있으면 그 자리는 다크 값을 물려받아 조용히 깨집니다.

### ④ 새 hex 리터럴 동결

`no-new-hex.test.ts` · 소스 전체의 raw hex 사용량을 **326개로 동결**했습니다.
초과하면 실패하고, 줄이면 baseline 을 낮춰 다시 동결합니다.
hex 를 정의해도 되는 파일은 `tokens.ts` 하나뿐입니다.

### ⑤ 액센트 면 위 흰 글자 금지

`on-accent-contract.test.ts` · 컴포넌트에 `color: '#fff'` · `'white'` 리터럴이 **0개**여야 합니다.
액센트는 테마에 따라 밝기가 뒤집히므로, 흰 글자를 박으면 한쪽 테마에서 안 읽힙니다.
면제 목록이 있는데 **면제가 낡지 않았는지도 함께 검사합니다.**

## 2. 스케일

### ⑥ raw 스케일 동결 4종

`no-raw-scale.test.ts`

| 대상 | 동결값 | 대신 쓸 것 |
|---|---:|---|
| raw `fontSize` | 66 | `TYPE.*` / `typeStyle()` |

| raw spacing (padding/margin/gap) | 1448 | `S[*]` |

상태색만 0 인 것은, 이미 완전히 토큰화되었으므로 **되돌아가는 것을 금지**한다는 뜻입니다.

### ⑦ 셸 폭은 LAYOUT 토큰에서

`page-shell-contract.test.ts` · 520 · 720 · 820 · 1140 을 raw 로 쓰지 않습니다.
그리고 **폭을 잡았으면 가운데로 놓는지**까지 검사합니다.
`maxWidth` 만 주고 `margin: 0 auto` 를 빠뜨리면 왼쪽에 붙습니다.

### ⑧ 줄간격 사다리 TS ↔ CSS 동기화

`lh-css-sync.test.ts` · 세 가지를 봅니다.

1. TS `LH` 와 CSS `--qa-lh-*` 의 **키 집합이 같은가**
2. 같은 키의 **값이 정확히 같은가**
3. `globals.css` 에 raw `line-height` 가 **없는가** (전부 변수인가)

세 번째가 요점입니다. 값을 맞춰도 새 raw 가 들어오면 사다리가 다시 갈라집니다.

### ⑨ 승격 토큰의 1:1 매핑

`tokens-promoted.test.ts` · `STATE` 7색이 CSS 변수와 1:1 인가,
`OVERLAY`/`ELEVATION` 이 테마 인지 변수를 가리키는가, **`Z` 가 단조 증가하는가**,
`S` 하프스텝이 2px 단위로 정확한가.

## 3. 타이포

### ⑩ 한글 라벨에 자간을 주지 않는다

`label-tracking-contract.test.ts` · 세 가지를 봅니다.

1. `uppercase` 근처에 raw `letterSpacing` 리터럴이 **0개**
2. uppercase 를 쓰는 컴포넌트가 **여전히 존재**하는가 (계약이 헛돌지 않는가)
3. **검출기 자체가 raw 리터럴을 잡는가** (가드가 빈 그물이 아닌가)

> 2번과 3번이 중요합니다.
> 검사 대상이 사라지면 계약은 «언제나 통과»가 되어 조용히 죽습니다.
> 원본은 그 실패 형태를 여러 번 겪고 이 두 줄을 넣었습니다.

### ⑪ Tag 높이의 지배 요인 고정

`tag-metrics.test.ts` · 「무엇이 배지 높이를 결정하는가」를 잠급니다.

- 크기별 지배 요인이 고정 (`xs`/`sm` = minHeight · `md` = lineHeight)
- **md 의 여유가 0.1px** 임을 명시. 이 여유가 사라지면 지배가 뒤집힙니다
- `sm` 도 여유가 0.6px 뿐이라 「다음 조정에서 넘어갈 후보」로 적혀 있습니다
- `LH.snug` 를 올리면 **세 크기 모두** lineHeight 지배로 넘어갑니다

이 계약의 가치는 값을 지키는 데 있지 않고, **보이지 않는 사슬을 보이게 만든 데** 있습니다.

## 6. 접근성

### ⑲ Alert 은 색만으로 종류를 말하지 않는다

`alert-not-color-only.test.tsx` · 네 종류(오류·주의·성공·안내)를 구별하는 단서가
색뿐이면 색각 이상인 사람에게는 한 종류입니다. 실제로 원본의 107곳이 그랬습니다.

- 네 종류 모두 `role` 이 있고, **급한 것은 `alert` · 알림은 `status`** 로 갈린다
- 아이콘에 `aria-label` 이 있고 **네 이름이 서로 다르다**
- 아이콘은 `aria-hidden` 이 아니다 (제목 없이 쓰는 66곳이 여기에 기댄다)
- 🔑 **색을 전부 지워도 네 종류가 서로 다르다**
- `role` 이 같은 둘(오류 vs 주의)도 색 없이 서로 다르다

마지막 두 줄이 이 계약의 핵심입니다. 「aria 를 붙였다」가 아니라
**색을 빼고도 구별되는가**를 직접 확인합니다.

### ⑳ 초점 표시를 인라인으로 지우지 않는다

`focus-visible-contract.test.ts` · `style={{ outline: 'none' }}` 을 **동결**합니다.
인라인은 클래스를 이기므로, 전역 `:focus-visible` 규칙이 있어도 그 자리만 초점이
사라집니다. `/audit` 검색칸이 실제로 그랬습니다(Tab 29칸 중 1칸).

- 남아 있는 자리는 **이유가 코드에 적혀 있어야** 한다 (프로그램이 초점을 주는 상자 등)
- `globals.css` 의 초점 고리가 `input` · `textarea` · `select` 를 덮는가

두 번째가 요점입니다. 인라인을 다 걷어내도 27번째가 생기므로,
**전역 규칙 쪽을 넓혀** 표시가 남게 합니다.

## 7. 화면의 «말투»

색·크기 같은 값이 아니라, 화면이 사람에게 말을 거는 방식에 관한 규칙입니다.
`screen-voice.test.ts` 한 파일에 셋이 들어 있습니다.

### ㉑ 화면이 1인칭으로 말하지 않는다

대시보드가 「우리 회사는 지금 N개 제품에 대해 총 M건의 변경이 진행되고 있고,
모든 단계가 정상 흐름을 유지하고 있습니다」라고 말하고 있었습니다.
문장으로 요약해 주는 것은 챗봇의 어법입니다. **업무 도구는 값을 보여주고 읽는 것은 사람이 합니다.**

0 을 문장에 넣으면 정보가 아니라 빈칸을 메운 말이 됩니다(「총 0건의 변경이 진행되고 있고」).

### ㉒ 같은 사실을 화면마다 다른 형식으로 적지 않는다

제품 카드가 `device_class` raw 값을 그대로 찍어, 「2」로 저장된 제품은 제목 아래
숫자 하나만 떴습니다. 다른 화면은 「2등급」입니다.
표시 SSOT 인 `formatDeviceClass()` 가 이미 있었는데 아무도 안 쓰고 있었습니다.

🔑 **계약을 만들자 몰랐던 결함 두 곳이 더 드러났습니다.** 그것이 계약을 만드는 이유입니다.

### ㉓ 세는 값과 나누는 값을 같은 변수로 쓰지 않는다

```ts
const total = a + b + c || 1;   // ✗ 0 나눗셈을 막으려던 폴백이
                                //   표시에도 쓰여 화면이 「총 1건」이라 말했다
const total = a + b + c;        // ○ 표시에 쓰는 값
const denom = total || 1;       // ○ 나눗셈 전용
```

게다가 `total === 0` 이 참이 되지 않아 「평가 없음」 처리가 **한 번도 동작하지 않았습니다.**

> ⚠️ 셋 다 **좁은 그물**입니다. `|| 1` 도 `device_class` 도 정당한 쓰임이 많아 전면 금지할 수
> 없습니다. 그래서 «합계처럼 보이는 이름» 과 «JSX children 자리» 만 봅니다.
> 넓게 잡았을 때는 폼 value·상태 콜백·개수 계산이 전부 걸렸습니다(오탐 4/4).
>
> 한글은 부분 문자열이 잘 겹칩니다. 「제가」로 찾으면 「**문**제가 발견되면」을 잡습니다(오탐 3/3).
> 앞 글자가 한글이면 제외하는 뒤돌아보기가 필요합니다.

## 8. 사본과 문서

### ㉔ 나간 사본은 지문으로 대조한다

`q-design-copy.test.ts` · Q-Design 이 내보낸 조각은 받는 저장소 안에서 **손으로 고쳐질 수**
있습니다. 그러면 정본과 갈리는데 아무도 모릅니다.

- 파일 머리에 본문의 sha256 이 적혀 있고, **받는 쪽 테스트가 다시 계산해서 대조**한다
- DOCX 빌더가 그 사본에서 색을 가져오는가 (값을 손으로 적지 않는가)

내보내는 쪽도 같은 것을 봅니다. `node tools/extract-all.mjs --sync` 는 쓰고 나서
**정말 같아졌는지 다시 확인**합니다. 쓰기가 성공했다는 것과 같아졌다는 것은 다릅니다.

### ㉕ 문서 산출물: 종이 위 대비와 글꼴 폴백

대외 문서 생성기(`MedQraft/templates/mqhtml.py`)의 `verify()` 는 **실패하면 저장을 막습니다.**
2026-09-10 에 둘을 더했습니다.

| 검사 | 왜 |
|---|---|
| 종이 위 대비 | 팔레트의 뿌리가 다크 화면입니다. 나간 문서에서 캡션 2.97 · 금색 라벨 **1.96** 이었습니다 |
| 글꼴 폴백 | `'Noto Sans KR', sans-serif` 는 없는 글리프를 **굴림체**로 떨어뜨립니다. 다섯 중 둘이 그랬습니다 |

- 대비는 **흰 종이와 음영 표(`#F3F1EC`) 둘 다** 재고 나쁜 쪽으로 판정합니다.
  흰 배경만 보면 표 안에서 조용히 미달합니다
- «글자로 쓰인 색» 만 봅니다. 선·면·워터마크는 대비 대상이 아닙니다.
  그래서 금색을 **장식(`GOLD`)과 글자(`GOLD_INK`)로 나눴습니다**
- 🔴 이 검사를 만들면서 **빈 그물을 하나 만들었습니다.** 글꼴 값 안에는 작은따옴표가

  일부러 폴백을 지워 봤을 때 통과해서 알았습니다. 그래서
  **「글꼴 지정을 하나도 못 찾으면 실패」**도 함께 넣었습니다

## 9. 저장소 자신

### ㉖ 사본과 문서의 숫자가 원본과 같은가

이 저장소의 규칙은 「손으로 베끼지 않는다」인데, 정작 그것을 지키는 장치가 없었습니다.

| 도구 | 무엇을 지키나 |
|---|---|
| `refresh-source.mjs --check` | `source/` 가 원본 저장소의 **커밋된** 내용과 같은가 |
| `contrast-table.mjs --check` | `docs/02-color.md` 의 대비표가 산출물과 같은가 |

🔴 **실측(2026-09-10): 사본이 낡아 있었습니다.** 계약 넷이 원본에 생겼는데 사본에는 없었고,
AA 로 고친 상태색 일곱이 `dist/` 에 반영되지 않아 **Q-Sonar·Q-Forge 가 미달 회색(3.46)을
그대로 쓰고** 있었습니다. 문서 표도 옛 값 그대로였습니다.

🔑 **그래서 `refresh-source` 가 `extract-all` 의 맨 앞 단계입니다.**
낡은 `source/` 에서 파생된 산출물은 실패가 아니라 **«낡은 것에서 정확히 파생된» 초록불**로
나옵니다. 그것이 가장 위험한 실패 형태입니다.

- 원본의 **워킹트리가 아니라 HEAD** 를 읽습니다. 다른 세션이 고치는 중인 파일이
  사본에 얼어붙지 않게 합니다
- 지도가 설명하지 못하는 파일은 **«고아»** 로 보고합니다. 원본에서 지워졌는데
  사본에만 남은 파일이 「진실」 행세를 하는 것을 막습니다
- `source/_ORIGIN.json` 에 **어느 커밋의 사본인지** 적힙니다

## 옮겨 쓸 때 우선순위

전부 옮길 필요는 없습니다. 효과 순으로 넷만 꼽으면 이렇습니다.

| 순위 | 계약 | 막아 주는 것 |
|---|---|---|
| 1 | **대비 (모든 표면 × 모든 텍스트)** | 접근성 붕괴. 가장 자주, 가장 조용히 깨집니다 |
| 2 | **팔레트 사본 동기화** | 「라이트에서만 색이 두 개」 |
| 3 | **한글 자간 0** | 한국어 UI 에서 라벨이 흩어짐 |
| 4 | **raw 값 동결(baseline)** | 토큰이 있는데 손으로 적은 사본이 늘어남 |
| 5 | **사본 신선도(㉖)** | 고친 값이 «나가지 않은 채» 초록불이 되는 것 |

### 동결(baseline) 방식이 특히 쓸 만합니다

「raw 값을 쓰지 마라」는 새 프로젝트에나 가능한 규칙입니다.
이미 수천 곳이 있는 프로젝트에서는 **현재 개수를 세어 동결하고, 넘으면 실패**시키는 편이 실용적입니다.

```
현재 1448곳 → BASELINE = 1448 → 넘으면 실패 → 줄이면 baseline 을 낮춰 다시 동결
```

한 번에 고치지 않아도 되고, **나빠지는 것만 막습니다.**

### 그리고 계약을 만들 때마다

**일부러 깨뜨려 실패를 본 뒤 되돌리십시오.**
정규식 한 글자가 어긋나 아무것도 잡지 못하는 «빈 그물» 계약이 초록불을 내는 일이 실제로 있습니다.
