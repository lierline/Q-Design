# 조합 패턴

[컴포넌트 문서](06-components.md)가 부품 하나하나의 스펙이라면, 여기는 **부품이 모여 만드는 덩어리**입니다.
실제 화면에서 반복되는 조합만 골랐습니다.

---

## 1. 목록 행 (`EntityRow`)

```
┌─┬──────────────────────────────────────────────┬──────────────┐
│▌│ 제목                                          │ [액션] [액션] │
│ │ 조항 메타 · 통합 설명                          │              │
│ │ 📎 첨부파일명 · v1                             │              │
└─┴──────────────────────────────────────────────┴──────────────┘
 ↑ 왼쪽 2px 색 띠 = 상태
```

```
padding 16px 18px · minHeight 72 · gap 14 · radius 10
background surface · border 1px · border-left 2px 액센트
전환 background 200ms
```

**왼쪽 색 띠가 상태를 말합니다.** 배지보다 조용하고 훑기가 빠릅니다.
강조가 필요한 행만 띠 색을 올리고 나머지는 중립으로 둡니다.

액션 버튼은 오른쪽에 모읍니다. 그리고 **상태에 따라 버튼 자체가 바뀝니다.**

```
발효됨:  [승인·발효] [재업로드] [다운로드] [숙지]
미업로드: [미업로드]  [업로드]
```

버튼을 회색으로 죽이는 대신 **다른 버튼을 보여주는** 방식입니다.

## 2. 상세의 사실 블록 (`SectionCard` + `DetailRow`)

```
┌────────────────────────────────────────────┐
│ 접수 요약                                   │  ← 제목 (h3 톤)
│ 고객 보고 사실                              │  ← 부제 (caption · muted)
│                                            │
│ 접수 경로                             전화  │  ← DetailRow: 양끝 정렬
│ 고객                  서울피부과의원·김혜진   │
│ LOT                          LOT-2026-002  │
│ 접수일               2026-08-30 18:00:35   │
│                                            │
│ 시술 중 LED 조사 밝기가 고르지 않다는…       │  ← 본문 문단
└────────────────────────────────────────────┘
```

```
SectionCard  padding 24 · marginBottom 16 · background surface · radius 10
DetailRow    display flex · justify-content space-between · padding 6px 0
             라벨: mono 10px · subtle · labelTracking
             값:   13px · text
```

**라벨 왼쪽 / 값 오른쪽 양끝 정렬**이 핵심입니다.
값이 오른쪽 축에 정렬되면 여러 줄을 세로로 훑을 수 있습니다.
숫자·날짜가 많은 화면에서 표를 쓰지 않고도 표처럼 읽힙니다.

## 3. 단계 표시 (`StageTimeline`)

```
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│ ⓘ 접수   │ │ 🔍 조사  │ │ 📋 CAPA │ │ ✓ 종결   │
└──────────┘ └──────────┘ └──────────┘ └──────────┘
   ↑ 현재만 금색 테두리 + 밝은 글자. 나머지는 중립
```

`fill` 이면 전체폭을 4등분하고 gap 0, 아니면 gap 4 로 붙입니다.
마커는 `check · dot · circle · cancel · none` 다섯입니다.

**지나간 단계와 남은 단계를 색으로 나누지 않습니다.** 현재만 강조합니다.
지나간 것을 초록으로 칠하면 「끝났다」로 읽혀 되돌릴 수 없는 인상을 줍니다.

## 4. 폼 필드 (`Field`)

```
알려준 사람 *                      유입 채널  전화·이메일·포털·현장 등 자유 입력
┌─────────────────────┐          ┌─────────────────────┐
│ 고객              ▾ │          │                     │
└─────────────────────┘          └─────────────────────┘
```

- 라벨은 굵게, **힌트는 같은 줄 오른쪽에 muted 로 작게**
- 필수는 금색 별표
- 2열 격자가 기본, 긴 입력(요약·상세)만 전체폭
- 모바일에서 1열로 붕괴

힌트를 아래로 내리지 않는 이유는 세로 길이 때문입니다.
규제 폼은 필드가 많아서, 힌트를 줄마다 아래에 달면 화면이 두 배로 길어집니다.

### 구획 (`FormSection`)

```
기본 정보                          ← mono 10px · champagne · weight 600
──────────────────────────────     ← padding-bottom 4 · 1px 하단선
```

### 액션 (`FormActions`)

```
──────────────────────────────     ← 상단 1px 경계 · padding-top 14
                  [취소] [저장]    ← 오른쪽 정렬 · gap 8
marginTop 18
```

## 5. 큰 갈래 고르기 (`SegmentedChoice`)

```
┌───────────────────────────┐  ┌───────────────────────────┐
│ 🌐 시판 후                 │  │ 📈 생산                    │
│    고객·유통·서비스에서     │  │    현장 작업자·검사원에게   │
└───────────────────────────┘  └───────────────────────────┘
   ↑ 선택됨: 금색 테두리
```

두세 갈래 중 하나를 고르는 자리에 라디오 버튼을 쓰지 않습니다.
**아이콘 + 제목 + 한 줄 설명**을 담은 카드형으로 만듭니다.

접근성은 마크업으로 지킵니다: `role="radiogroup"` + `role="radio"` + roving tabindex.
화살표로 이동하고 비활성은 건너뜁니다. 계약이 전부 검사합니다.

셋으로 나뉘는 짧은 선택(긍정/중립/부정)은 같은 부품의 **좁은 변형**입니다.

## 6. 지표 행 (`KPI`)

```
진행 중 ⓘ        허가 받은 제품 ⓘ    내 검토 대기 ⓘ     진행 중 변경 ⓘ
2                1                  0                 0
아이디어~인허가    시판 중·허가 후 관리  검토 중·내 의견 미등록  조직 전체
```

```
padding 18px 20px · minHeight 124
라벨  mono 10px · subtle · 자간 1.5
값    weight 700 · 36px · lineHeight 1.05 · 자간 -0.02em
보조  11px · muted · marginTop 10 · minHeight 16
```

**숫자 색이 뜻을 실어 나릅니다.** 기본은 크림, 좋은 것은 초록, 주의는 금색, 위험은 빨강.
0 은 색을 주지 않습니다 (없는 것에 색을 칠하면 소음이 됩니다).

라벨 옆 ⓘ 는 툴팁입니다. 산식이나 집계 범위를 그 자리에서 폅니다.
`minHeight 16` 은 보조설명이 없는 칸도 높이를 맞추기 위한 것입니다.

## 7. 모듈 격자 (`HubModuleGrid`)

```
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ ▣  인허가 현황 │ │ ▣  보험 등재  │ │ ▣  부작용 보고 │
└──────────────┘ └──────────────┘ └──────────────┘
```

```

칸: padding 14px 16px · minHeight 62 · gap 12
아이콘: 샴페인 알파 배경 사각 · radius 6
이름: 13px
```

허브 화면의 입구 모음입니다. `auto-fill` 이라 화면이 넓으면 한 줄에 더 들어갑니다.

## 8. 탭 (`WorkspaceTab`)

```
허가 준비 (2)      허가 후 변경 (1)
개발 ~ RA 연계     제품 단위 변경 등록
━━━━━━━━━━━━
```

```
padding 14px 20px · fontSize 14
활성: weight 600 · text 색 · border-bottom 2px champagne
비활성: weight 400 · muted · 투명 하단선
개수는 champagne 색으로 제목 옆에
부제는 아래 줄에 작게
```

**탭에 부제가 붙습니다.** 이름만으로 무엇이 들어 있는지 모를 때 한 줄로 설명합니다.

## 9. 안내 (`HelpNote` · `Alert` · `InfoBox`)

세 가지가 역할이 다릅니다.

| 부품 | 언제 | 모양 |
|---|---|---|
| `HelpNote` | 이 기능이 무엇인지 (화면당 한 번, 헤더 아래) | 문단. 핵심어만 굵게 |
| `Alert` | 지금 일어난 일 · 조치가 필요한 것 | 색 배경 8% + 테두리 30% + mono 제목 |
| `InfoBox` | 이 블록에 대한 부연 | 색 배경 6% · 테두리 없음 · subtle |

범위를 밝힐 때는 기호를 씁니다.

```
◆ RA 카테고리 문서만 추적합니다 (기술 문서, 식약처 신청서 … 등 22종).
◇ 개발 카테고리 문서는 R&D 가 책임지며 본 화면에서는 표시하지 않습니다.
```

**포함과 제외를 나란히 적습니다.** 「무엇을 안 보여주는지」를 밝히는 것이
규제 시스템에서 신뢰를 만드는 방식입니다.

## 10. 현장 모드 조합

```
입고 수량
┌───────────────────────────────────────────────┐
│ 수량                                           │
│ 100 ea                                        │  ← 매우 큰 숫자
└───────────────────────────────────────────────┘
[ea] [set] [box] [kg] [g] [L] [mL] [m] [roll]     ← 단위는 버튼 격자
      ↑ 선택됨: 금색 테두리

☑ 표본검사 적용 (ISO 2859-1)
검사 수준
┌──────────┐ ┌──────────┐ ┌──────────┐
│ 수준 I    │ │ 수준 II   │ │ 수준 III  │
│ 완화      │ │ 보통      │ │ 엄격      │           ← 선택됨은 «채움»
└──────────┘ └──────────┘ └──────────┘

로트 크기    코드     표본 n    Ac / Re
   100        F        20       1 / 2            ← 계산 결과를 즉시 격자로

표본 중 발견 불량 수 (d)
┌────────────────────────────────┐ ┌────────┐
│ 0                              │ │  합격   │      ← 판정을 옆에 즉시
└────────────────────────────────┘ └────────┘
d ≤ Ac(1) 합격 · d ≥ Re(2) 불합격                  ← 판정 근거를 그 자리에

┌───────────────────────────────────────────────┐
│              검사 기록 저장                     │  ← 하단 고정 · 전체폭 · 초록
└───────────────────────────────────────────────┘
저장하면 자재 로트가 함께 생성되어…                 ← 결과 예고
```

일반 화면과 다른 점 넷.

1. **선택은 테두리가 아니라 «채움»** 입니다. 장갑 낀 손이 멀리서 봐야 합니다
2. **계산 결과를 숨기지 않습니다.** 규격·표본수·판정 기준을 그 자리에 폅니다
3. **판정 근거를 한 줄로 적습니다.** 결과만 주면 사람이 확인할 수 없습니다
4. **저장하면 무슨 일이 일어나는지 예고합니다**

## 11. 이 시스템이 안 하는 것

옮길 때 함께 가져가면 좋은 «절제» 목록입니다.

- **모달을 잘 안 씁니다.** 확인·간단 입력만. 내용은 화면에 폅니다
- **탭을 최상위에 두지 않습니다.** 사이드바가 1차, 탭은 한 화면 안의 2차 축입니다
- **아코디언을 남발하지 않습니다.** 접는 것은 「관련 양식 46종」처럼 진짜 긴 것만
- **툴팁에 필수 정보를 넣지 않습니다.** 산식·범위 같은 부연만
- **비활성 버튼으로 막지 않습니다.** 상태에 맞는 다른 버튼을 보여줍니다
- **빈 화면을 초라하게 두지 않습니다.** 96px 여백 + 큰 글리프 + 다음 행동 힌트
