# Q-Design 전체 적용 여부 재점검

2026-10-11. 결론은 **공통 기반의 전파와 세 제품의 운영배포를 확인했지만, 전체 화면의 디자인 감사 완료는 아직 인증할 수 없다**이다. 기본 부품 비교, 화면 연결 검사, 실제 업무 화면 감사의 완료 여부를 구분한다. 최신 운영 결과는 `42-production-and-screen-coverage.md`에 기록한다.

## 이번에 직접 확인하고 수정한 사항

실제 제품 어댑터에 공통 인자 20종을 각각 변경했다. 밝은 화면·어두운 화면, 375px·1440px, 세 제품의 12개 조건에서 408개 적용값을 검사했다. 모서리, 컨트롤 높이·글자, 이름표·오류·배지·카드 제목, 글꼴 계열·굵기, 카드 여백, 필드 간격, 선택창 여백, 표 셀, 진행률, 대화상자 규격을 포함한다.

기존에는 메종·카르넷의 버튼과 이름표 굵기가 숫자 500으로 고정되어 공통 굵기 변경을 따르지 않았다. 카드 제목도 600으로 고정되어 있었고, 카르넷에서는 전역 h3 규칙에 의해 700으로 덮였다. 공유 기반의 역할별 굵기 연결을 보정했다. 메종의 Tailwind 3가 레이어 규칙을 재배치하는 경우까지 확인했다. 현재 기본 카드 제목은 세 제품 모두 600이다.

색상 검사는 `palette-overrides.json`을 읽는 실제 생성기에 배경·입력 면·글자색 변경을 전달한 다음, 생성 CSS를 독립 검수 화면에 적용했다. 12개 조건의 36개 실제 색상 값이 변경을 따랐다. 제품의 원본 팔레트와 업무 데이터는 변경하지 않았다. 테마 전환의 중간 프레임이 아닌 전환 완료 후 값을 비교했다.

- 새 공통 인자 및 팔레트 전파 검사: **444개 통과, 실패 0개**.
- 기존 같은 역할의 기본 부품 비교: **18개 조건, 검사한 수치 차이 0개**.
- 로그인·배경·오프라인 검수 도구: **18개 제품·테마·폭 조건 및 편집기·오프라인 검사 통과**.
- 생성기와 수치 어댑터 회귀 검사: 11개 통과.
- 정확한 렌더러·격자·위젯 폭 근거 검사: 10개 통과.
- 전체 릴리스 검사 `extract-all.mjs --check --only=Q-Atelier,Q-Works,Q-Forge`: 종료 코드 0. 원본 사본 110개 일치, 실제 컴포넌트 계약 통과, 제품 앱 아이콘 지문 32/32 일치. 전체 화면 연결 검사를 포함한 최신 로그는 `D:/Claude/tmp/qd-production-release-with-screen-check.log`에 있다.

새 전파 검사는 `check-components.mjs --browser`에 연결했다. 기존 근거는 공유 CSS의 이전 본문 전체와 참조한 줄이 그대로임을 확인한 항목만 갱신했다. 생성 CSS와 제품 사본을 참조하는 목록은 생성기로 다시 계산했다.

## 큐 디자인 수정이 반영되는 실제 경로

| 변경 대상 | 수정하는 정본 | 반영 경로 |
| --- | --- | --- |
| 공용 부품 | `patterns/components.css` | 공통 CSS 동기화 후 제품 빌드 |
| 서체·간격·기반 역할 | `patterns/foundation.css` | 제품별 기반 CSS 생성 후 동기화 |
| 배경·로그인·앱 셸·제품별 기반 | `patterns/foundation/` | 같은 생성·동기화 경로 |
| 화면 색상·상태색 | `patterns/palette-overrides.json` | 제품별 CSS·런타임·관련 이메일 및 HTML 팔레트 생성 |
| JS 수치·반응형 조건·SVG 표현 | `source/design/atelier-runtime.ts` 등 등록된 수치 정본 | TypeScript 사본과 CSS 생성 후 재빌드 |
| 인쇄·이메일·독립 HTML | 해당 `patterns/foundation/` 규칙과 등록된 출력 정본 | 출력별 생성·검증. 화면 변수의 직접 상속을 가정하지 않음 |
| 앱 아이콘 | 등록된 공식 자산과 `tools/app-icons.mjs` | 고정 렌더러 생성·지문 대조·동기화 |

등록된 중앙 규칙은 Q-Design 안에서 수정할 수 있다. 제품의 생성 사본을 직접 수정하지 않는다. **파일 저장만으로 운영 중인 세 제품이 즉시 바뀌지는 않는다.** 생성·동기화·제품 재빌드·배포가 필요하다. 설치된 PWA는 서비스 워커와 캐시 갱신도 필요하다.

현재 기본 부품의 대표 인자가 전파된다는 결과를 모든 업무 화면의 모든 인자가 연결되었다는 결과로 확대하지 않는다. 출력의 물리 규격, 기계 판독용 치수, 공식 로고 비율, 업무 계산과 권한·데이터는 별도의 계약을 유지한다.

메종 `/audits/new`의 기존 `정기` 버튼은 높이 **29.984375px**이고 기본 `qd-choice`가 없었다. 이를 수정한 운영 화면에서 기본 클래스와 선택 상태 클래스가 함께 적용됨을 직접 확인했다. 높이는 **37.5px**, 글자 13px, 모서리 10px, 여백 상하 8px·좌우 12px이다. 새 심사 계획은 제출하지 않았다.

메종·카르넷 인자 분류의 미확정 수가 0이어도 화면 적용 완료는 아니다. 클래스가 중앙에서 생성되더라도 업무 화면이 공통 역할의 기본 클래스를 빠뜨릴 수 있다.

## 완료 판정과 검증 명령

`extract-all.mjs --check`는 소스·산출물·동기화·아이콘의 검사다. `check-components.mjs --browser`는 실제 부품 및 기반 예시의 검사다. 새 `design-readiness.mjs --check`는 미분류 인자, 남은 화면 근거, 선택 버튼 후보 및 전파 실패를 별도로 검사한다. 미완료가 있으면 종료 코드 1로 보고한다. 기존 자동 검사의 초록 결과를 전체 디자인 감사 완료로 해석하지 않도록 분리했다.

```text
node tools/extract-all.mjs --sync --only=Q-Atelier,Q-Works,Q-Forge
node tools/extract-all.mjs --check --only=Q-Atelier,Q-Works,Q-Forge
node tools/check-components.mjs --browser
node tools/design-readiness.mjs --write --check
```

소스나 생성 결과가 바뀌면 스타일 목록 및 해당 정확한 근거 목록의 재생성과 재검토도 필요하다. 원본 값 변경을 근거의 지문만 바꾸어 승인하지 않는다. `source/`의 아뜰리에 사본을 갱신할 때는 커밋된 제품 HEAD를 읽는다는 기존 제약을 유지한다.

결과는 `reviews/design-propagation-results.json`, 수정 전 결과는 `reviews/design-propagation-before.json`, 정확한 CSS 변경 기록은 `reviews/design-propagation-rule-revalidation.json`, 전체 완료 판정은 `reviews/design-readiness.json`에 있다. 세 제품은 main에 푸시하고 운영배포 READY를 확인했다. Q-Design 정본 저장소의 이번 변경은 아직 로컬 작업 트리에 있으며, 제품에 배포된 생성 사본과 구분한다.
