# 세 제품 기본 UI 구현 정본 연결 기록

공통 CSS를 읽던 기본 부품의 실제 구현도 Q-Design에서 관리하도록 연결했다. 이번 채택은 기존 본문을 그대로 옮긴 것이며 제품의 표시·콜백·접근성·입력·상태 동작과 공개 API는 변경하지 않았다. 표시 인자의 의미 검토와 화면 시각 인증은 별도로 유지한다.

## 정본과 범위

`patterns/component-implementations.json`이 명시한 27개 파일만 생성한다. 아뜰리에는 기본 부품 묶음, 선택 부품, 한글 표시와 알림의 4개 파일이다. 메종은 `components/ui` 18개 파일, 카르넷은 기본 UI·표·대화상자·알림·행 링크 5개 파일이다. 기본 구현 본문은 `patterns/component-implementations/`에서 관리한다.

`dist/q-design.component-implementations.json`에는 제품 경로, 정본 경로, 전체 본문 지문과 실제 내보내기를 기록한다. 합계는 값 내보내기 153개, 타입 내보내기 11개다. 보조 함수와 타입도 포함하므로 이를 UI 컴포넌트 164개라고 세지 않는다. 카르넷 표의 행 링크 재내보내기는 실제로 함께 소유한 행 링크 구현에 연결한다. 다른 파일이나 외부 모듈의 재내보내기는 자동으로 승인하지 않는다.

아뜰리에 `f794024ddccbdc7f8f6b4e4c8b599bc85ac830ee`, 메종 `c505e23c615eb728edbde959badf9f074b1f796e`, 카르넷 `8fcd78bbf0250543e93e718ce1ebee5dc3bcd72a`의 커밋된 본문과 채택한 정본을 전체 비교했다. 줄 끝 CRLF/LF만 정규화했고 원래 동작을 생략하지 않았다. `reviews/component-implementation-adoption.json`에 역사적 채택 근거를 저장했다. 제품에 머리표를 추가하거나 포맷을 바꾸지 않아 기존 본문 지문과 배포 코드도 유지된다.

## 생성·동기화와 문구 교정

`tools/build-component-implementations.mjs`를 전체 생성·동기화·릴리스 검사에 연결했다. 생성 사본의 독립 수정은 정본과 전체 파일 비교에서 실패한다. 메종 UI 폴더에 새 파일이 생기거나 정본 폴더에 목록 밖 파일이 있으면 범위 검토를 요구한다. 새 공개 부품은 기존 역할 등록 검사도 계속 받아야 한다. 모든 정본 구문과 선택 대상의 존재·범위를 검사한 뒤 실제 쓰기를 시작한다.

문구 교정은 소유한 구현의 정본을 수정한 뒤 생성으로 전달한다. 제품 사본만 교정해 다음 동기화 때 되돌리는 충돌을 방지했다. 기존 `lib/design` 제외에서 추가한 대상은 정본 목록의 세 UI 파일뿐이다. 검증 엔진과 변경 금지 토큰 원문은 교정 대상에 넣지 않았다. 기존 86개 문구 바인딩의 검사도 통과했다.

공통 모서리·팔레트·외형 변경은 가족 공통 CSS·표시 인자를 수정한다. 제품별 마크업과 입력 방식은 해당 구현 정본을 수정한다. 생성·동기화 후 제품 소스 커밋과 검사·빌드·배포, 최종 릴리스 검사를 수행해야 한다. 정본을 편집하는 것만으로 이미 배포된 사이트나 설치 앱이 즉시 갱신되는 것은 아니다.

## 검증

기본 구현과 문구 회귀 검사 11개가 통과했다. 별도 임시 작업 공간에서 세 실제 알림 구현의 너비 표현을 바꾸고, 선택한 제품만 동기화했을 때 다른 사본이 여전히 실패하는지 확인했다. 전체 동기화 후에는 세 사본이 정확히 바뀌었다. 표시 너비를 운영에서 바꾼 검사는 아니다.

마지막 정본의 구문 오류, 미검토 기본 내보내기, 새 메종 UI 파일, 목록 밖 정본과 미소유 재내보내기를 넣었을 때 앞 제품의 소스를 먼저 쓰지 않고 거부했다. 기존 카르넷 알림의 기본 내보내기는 명시적으로 등록한 렌더러 이름에 연결한다. 한글 문구 교정은 중앙 기본 부품 정본을 수정하고 생성 단계가 제품으로 전달하는지 확인했다. 실제 27개 제품 본문의 동기화 검사도 통과했고, 실제 제품 파일 변경은 0개다.

최종 `extract-all --check --only=Q-Atelier,Q-Works,Q-Forge`가 종료 코드 0으로 통과했다. 새 구현·문구 검사와 기존 역할 등록, 표시 인자·팔레트·동기화·앱 시작 화면 계약을 포함한다. Chromium 151.0.7922.34, Playwright 1.62.1, sharp 0.34.5, libvips 8.17.3의 기존 정본 조합으로 앱 아이콘 32개 지문도 일치했다. 금지 문자와 변경 공백 검사도 통과했다. 문구 교정의 실제 쓰기 명령은 현재 정본에 수정할 문구가 없어 파일·문구 변경 0개였다. 이번 코드 소유 채택을 새로운 화면 시각 인증으로 계산하지 않는다.

## 남은 범위

아뜰리에 스타일 미분류는 897개, 메종과 카르넷은 0개다. 이번 구현 소유를 근거로 미분류 인자를 승인하거나 숫자를 줄이지 않았다. 업무 데이터, 호출부 스타일·클래스, 콜백, 기기 설정과 외부 도메인 라벨은 따로 확인할 입력이다. 아직 정본에 편입하지 않은 공통 구현과 업무 조합도 남아 있다.

등록 주소 540개와 업무 화면 이미지 2,330개는 그대로다. 임시 코드 전파 검사를 실제 화면 검수에 더하지 않았다. 추가 모바일·테마·상호작용 상태, iOS 직접 지정 색상·알림·시작 화면, 다른 앱 클래스, 서명·설치 기기·iOS 빌드는 완료하지 않았다. 이번 단계는 웹·네이티브 제품의 실행 소스를 바꾸지 않아 직전 운영 배포와 서명 전 Android 산출물을 유지한다.
