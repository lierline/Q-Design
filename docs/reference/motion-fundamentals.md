# 모션 기초 공부 노트 · 이징 · 시간 · 안무 · 성능 · 접근성

작성일: 2026-11-09. 오빠 지시 «모션 그래픽 관련이니까 모션을 공부해 두길». 앞선 참고 조사 일곱([목록](../../README.md))에서 배운 것을 **모션 일반론**으로 한 번 정리합니다. 규칙이 아니라 공부 노트라 이 폴더에 둡니다. 정본 값은 바꾸지 않았습니다.
직접 읽은 1차 자료: Studio Illicit 글 «Easing, explained»([원문](https://www.illicitwebdesign.co.uk/blog/easing-explained-the-small-thing-that-makes-a-website-feel-expensive/) · 2026-10-12 · 릴스의 본문) · Material 3 motion 토큰([링크](https://m3.material.io/styles/motion/easing-and-duration/tokens-specs)) · Apple HIG Motion([링크](https://developer.apple.com/design/human-interface-guidelines/motion)) · GSAP Eases([링크](https://gsap.com/docs/v3/Eases/)) · MDN easing-function · `linear()`([링크](https://developer.mozilla.org/en-US/docs/Web/CSS/easing-function)) · WCAG 2.3.3([링크](https://www.w3.org/WAI/WCAG21/Understanding/animation-from-interactions.html)). 숫자는 제가 계산해 넣었습니다(3절 · 6절).

> **한 줄 요약.** 모션은 네 가지 결정입니다. **무엇이**(transform · opacity 만) **얼마나 오래**(100 ~ 400ms) **어떤 곡선으로**(들어올 때 out · 나갈 때 in · 옮길 때 in-out · 돌 때 linear) **어떤 순서로**(한 묶음 · 짧은 어긋남) 움직이는가. 우리 5장은 넷 다 정해 두었고, 다른 집과 다른 점은 곡선의 세기(expo.out) 하나와 «출렁임 0» 입니다.

## 1. 이징은 «속도의 변화» 입니다

곡선은 가로가 시간, 세로가 거리입니다. 가파르면 빠르고 평평하면 느립니다. 선형(linear)은 컨베이어 벨트처럼 한 속도라, 도착할 때 «유리문에 부딪히듯» 멈춥니다. 현실의 것은 그렇게 움직이지 않으니(차는 천천히 출발하고, 문은 닫히기 전에 느려지고, 떨어지는 폰은 바닥까지 빨라집니다) 화면도 그것을 빌릴 때 «맞다» 고 느낍니다. (Illicit 의 설명을 요약)

이름의 방향에 주의합니다. CSS 의 **ease-out** 은 «끝에서 느려짐»(들어올 때), **ease-in** 은 «처음에 느림, 끝에 빠름»(나갈 때). After Effects 는 같은 곡선을 거꾸로 부릅니다(Easy Ease In = CSS ease-out).

### 여섯 족(family)과 공식

| 족 | 뜻 | 공식(out 꼴) | CSS | GSAP | 넘침 |
| --- | --- | --- | --- | --- | ---: |
| power(다항) | 빠르게 나가 부드럽게 멈춤. 차수가 높을수록 급함 | `1 - (1-t)^n` | power2 `(0.33, 1, 0.68, 1)` · power3 `(0.22, 1, 0.36, 1)` · power4 `(0.25, 1, 0.5, 1)` | `power2.out` … | 0 |
| expo(지수) | power 의 극단. 첫 10% 시간에 절반을 감 | `1 - 2^(-10t)` | `(0.16, 1, 0.3, 1)` **= 우리 기본** | `expo.out` | 0 |
| sine | 가장 완만한 곡선 | `sin(t·π/2)` | `(0.61, 1, 0.88, 1)` | `sine.out` | 0 |
| back | 목적지를 지나쳤다 돌아옴 | `1 + (s+1)(t-1)^3 + s(t-1)^2` · s = 1.70158 | `(0.34, 1.56, 0.64, 1)` | `back.out(1.7)` | 10% |
| elastic | 용수철. 여러 번 진동 | `2^(-10t)·sin((t - p/4)·2π/p) + 1` · p = 0.3 | cubic-bezier 로 **못 그림** → `linear()` 또는 키프레임 | `elastic.out(1, 0.3)` | 37% |
| bounce | 떨어진 공. 바닥에서 되튐 | 포물선 조각 넷(7.5625 · 2.75) | `linear()` 또는 키프레임 | `bounce.out` | 0(되튐 25%) |
| steps | 이징 없음. 칸으로 뜀 | 계단 | `steps(5)` | `steps(5)` | 0 |

- 릴스 공 여덟의 실측([이징 조사](easing-study.md))이 이 표와 맞습니다. back.out(1.70158) 의 꼭대기는 1.10 · 전체 시간의 58%(1.4초에서 0.81초 · 실측 0.87), elastic 꼭대기 1.37(실측 1.40), bounce 의 첫 착지는 1/2.75 = 36%(실측 0.5초/1.4 = 36%) 뒤 0.75 까지 되튐(실측 0.75).
- **cubic-bezier 하나로는 한 번만 넘칠 수 있습니다**(제어점 y 가 1 을 넘으면 back). 두 번 이상 진동하는 elastic · bounce 는 CSS `linear(0, 0.2 10%, 1.37 20%, …)` 로 점을 찍어 흉내 내거나(크롬 113+ · 사파리 17.2+ · 파이어폭스 112+) 키프레임으로 나눕니다.
- CSS 기본 `ease` 는 `(0.25, 0.1, 0.25, 1)`: 살짝 들어가 빠르게 나가고 대부분의 시간을 멈추는 데 씁니다. 90% 도달이 전체의 62%. 아무 지정이 없으면 이것이 돕니다.

### 세기(강도)를 숫자로

«얼마나 급한가» 는 **90% 도달 시각**(전체 시간 대비) 하나로 읽힙니다.

| 곡선 | 첫 10% 시간에 간 거리 | 90% 도달 |
| --- | ---: | ---: |
| power2.out (릴스 · GSAP 기본) | 27% | 54% |
| power3.out (우리 접기) | 40% | 37% |
| expo.out **(우리 기본)** | 49% | 33% |
| Illicit 의 서명 곡선 `(0.19, 1, 0.22, 1)` | 48% | 31% |
| Material 3 emphasized-decelerate `(0.05, 0.7, 0.1, 1)` | · | 약 40% |
| CSS `ease` | 9% | 62% |

Illicit 가 «칼름하고 통제된» 브랜드에 고른 서명 곡선이 우리 기본과 거의 같은 급함입니다. 그들의 말: 「대부분의 이동을 곧바로 하고 착지에 시간을 들인다」. 우리 1장 «정밀 · 절제» 의 곡선이 그것입니다.

## 2. 시간: 사람이 느끼는 문턱

| 시간 | 느낌 | 쓰는 곳 |
| --- | --- | --- |
| ~100ms | «즉시». 원인과 결과가 하나로 묶임 | 호버 · 누름 반응 · 색 바뀜(우리 120ms) |
| 150 ~ 250ms | 작은 것이 «움직였다» 가 보이는 최소 | 단추 · 토글 · 칩 · 작은 판(우리 200ms) |
| 250 ~ 400ms | 큰 것(서랍 · 판 · 화면)이 «왔다» | 서랍 · 모달 · 페이지(우리 320ms) |
| 400 ~ 500ms | 한 번뿐인 강조의 상한 | 우리 480ms(1회 강조) |
| > 500ms | 「사람이 애니메이션을 기다리기 시작」(Illicit) | 얼굴 화면(로그인 «판이 열린다» 3.1초 · 첫 누름에 끊김)만 |

- 같은 곡선이라도 **거리에 비례해 시간을 늘리지 않습니다.** 큰 것은 조금 더 길게(1.3 ~ 1.6배), 먼 것은 같은 시간에 더 빠르게. Material 3 도 짧은 50 ~ 200ms(«short») · 250 ~ 400ms(«medium») · 450 ~ 600ms(«long») 세 묶음이고, 600 을 넘는 것은 «extra long» 으로 따로 둡니다.
- **나가는 것은 들어오는 것보다 짧게**(Material: 퇴장은 입장의 약 2/3). 사람은 사라지는 것을 보지 않습니다. 우리 5장에는 이 줄이 없습니다(이징 조사 4절의 «나가는 곡선» 과 함께 결정할 것).
- 급한 곡선은 체감 시간을 줄입니다. 우리 160ms 페이지 페이드는 expo.out 이라 눈에는 53ms 로 끝납니다. 그래서 시간을 더 줄이지 않아도 «빠르다» 가 성립합니다.

## 3. 안무: 순서가 움직임보다 중요합니다

1. **한 화면에 주인공 하나.** 동시에 여러 것이 다른 방향으로 움직이면 눈이 둘로 갈립니다(5장 «제각각 뜨는 위젯은 떠걱떠걱»).
2. **어긋남(stagger)은 짧게, 고정 상한.** 형제들이 35 ~ 50ms 씩 늦게 나타나면 «순서» 가 생기고, 9번째부터 지연을 고정해야 긴 목록의 끝이 몇 초 뒤에 뜨지 않습니다(우리 `.qa-stagger`). 릴스 OTP 의 민트 물결은 50ms 였습니다.
3. **따라옴(follow-through).** 큰 것이 멈춘 뒤 작은 것(이름 · 보조 글귀 · ✓)이 한 박자 늦게 서면 «끝났다» 가 읽힙니다. 입력 칸 조사의 «완료 ✓ + 보조 글귀» 가 이것입니다.
4. **끝난 상태를 멈춤.** 1.2초 이상(움직임 브리프 · 릴스 실측). 결과를 읽을 시간을 줍니다.
5. **방향은 뜻입니다.** 앞으로 가면 오른쪽에서, 뒤로 가면 왼쪽에서(화면 전환 조사 A). 위에서 내려오는 것은 «알림», 아래에서 올라오는 것은 «내가 연 것».
6. **크기는 바꾸지 않습니다.** 우리 결정(1장). 공유 요소 · 컨테이너 변형 같은 «크기가 변하는 안무» 는 사진이 주인공인 앱의 것이고, 글과 표가 주인공인 화면에서는 흐릿한 시간을 늘립니다.
7. **스크롤에 묶인 움직임은 linear.** 손가락이 이미 속도를 정하므로 곡선을 더하면 어긋납니다(Illicit 의 Topsham 사례 · ease "none").

디즈니 12원칙 가운데 UI 에 남는 것은 **Slow in · slow out(이징)** · **Staging(주인공 하나)** · **Follow-through / overlapping(따라옴 · 어긋남)** · **Timing** 넷입니다. Squash · stretch · anticipation · exaggeration 은 캐릭터의 것이고 업무 도구에서는 «출렁임» 으로 읽힙니다.

## 4. 스프링과 베지어

«스프링» 은 시간이 아니라 **물리값**(stiffness k · damping c · mass m)으로 적는 움직임입니다. 감쇠비 ζ = c / (2√(k·m)) 가 성격을 정합니다.

| 값 | ζ | 넘침 | 2% 안착 | 뜻 |
| --- | ---: | ---: | ---: | --- |
| stiffness 300 · damping 20 (UI Motion Prompts 의 값) | 0.58 | 10.8% | 0.40초 | back.out(1.7) 과 같은 양의 넘침 |
| stiffness 170 · damping 26 (Framer 기본) | 1.00 | 0% | 0.31초 | 임계 감쇠. 넘침 없이 power/expo.out 처럼 보임 |

- ζ ≥ 1 이면 스프링도 넘치지 않으므로 «스프링 = 출렁임» 이 아닙니다. 다만 CSS 로 옮길 때 **시간이 고정되지 않아** 토큰(160 · 200 · 320)과 맞지 않고, 우리가 금지하는 것은 ζ < 1 의 넘침입니다. 그래서 정본은 베지어(시간 고정 · 넘침 0)를 씁니다.
- 중간에 방향이 바뀌는 상호작용(끌다가 놓기)은 스프링이 맞습니다. 속도를 이어받기 때문입니다. 우리 제품에서 그런 자리는 위젯 끌기 하나뿐입니다.

## 5. 성능과 접근성

- **값싼 속성은 둘.** `transform` · `opacity` 는 합성기(compositor)만 돌리고, `width · height · top · left · margin` 은 매 프레임 레이아웃을 다시 잽니다(web.dev · Illicit FAQ). 그래서 1장 원칙 ③ 「이동과 투명도만」 은 미학이자 성능 규칙입니다. 탭줄 D(폭) · 입력 칸 B(높이) 가 «배치 전환 예외» 를 묻는 까닭이 이것입니다. 예외를 두더라도 요소 대여섯 · 160ms 안.
- **`will-change` 는 손이 얹힌 동안만.** 늘 켜 두면 합성 레이어가 살아 있어 메모리를 먹고, 화면 캡처가 비는 일(5장 `.qa-stagger` 주의)이 납니다. 11-05 감사에서 호버 한정으로 고쳤습니다.
- **움직임 줄이기(WCAG 2.3.3).** 전역 `0.01ms` 규칙만으로는 무한 반복이 «빠른 깜빡임» 이 되므로 개별 `animation: none` 이 필요합니다(5장). 어지럼을 일으키는 것은 큰 이동 · 확대 · 시차(parallax) · 자동 재생 루프이고, 색 바뀜 · 작은 투명도는 대체로 괜찮습니다. Illicit 도 같은 전역 CSS 를 쓰고 GSAP 은 `matchMedia("(prefers-reduced-motion: no-preference)")` 안에서만 돌립니다.
- **숨기지 않기.** 스크립트가 시작 위치를 정하면 스크립트가 실패해도 화면은 보여야 합니다(Illicit «Nothing hidden»). 우리 `.qa-page-fade` 가 reduce 에서 걷히고 SSR 첫 그림이 완성 상태인 것이 같은 생각입니다.

## 6. 한 집의 모션 규칙은 네 줄이면 됩니다

Illicit 의 네 줄: «서명 곡선 하나 · 들어오는 것은 ease-out 으로 1초 안에 · 줄이기 요청이면 끔 · 아무것도 숨기지 않음».
우리 5장의 네 줄: «`cubic-bezier(0.16, 1, 0.3, 1)` 하나 · 이동과 투명도만 · 120 · 200 · 320 · 480 · 무한 반복은 개별로 끔».

같은 꼴입니다. 우리에게 빠진 것은 **나가는 움직임의 줄**(곡선 · 시간 2/3)과 **곡선마다 «무엇이 움직일 때» 이름표**이고, 둘 다 [이징 조사](easing-study.md) 남은 일에 있습니다.

## 7. 남의 모션을 공부하는 법 (이번에 쓴 절차)

1. 릴스 임베드 `/reel/<id>/embed/` 의 JSON 에서 `video_url` 을 꺼내 받는다(없는 계정도 있음).
2. `ffmpeg -vf fps=30` 으로 프레임을 뽑고, 움직이는 것의 위치를 색으로 찾아 프레임마다 잰다.
3. 출발 0 · 도착 1 로 정규화해 p(t) 를 얻고, 알려진 cubic-bezier 들과 RMSE 로 맞춘다. 넘침은 최대값, 안착은 2% 안에 든 시각으로 읽는다.
4. 그 숫자를 우리 곡선과 같은 자(90% 도달 · 첫 10% 거리)로 나란히 놓는다.

«느낌» 으로 말하지 않고 곡선과 시각으로 말하면, 다음 사람이 같은 것을 다시 볼 수 있습니다.
