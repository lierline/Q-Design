## 이미지별로 볼 것

### `dashboard-audit-readiness` · 점수 대시보드

가장 많이 배울 것이 있는 화면입니다.

- **점수 배너**: 아이콘 사각 + `97 / 100` + 판정 문구 + 경고 한 줄 + 심각도 배지 3개(중대 0 · 주요 1 · 경미 2)
- **카드 바닥에 붙은 진행선.** 별도 게이지가 아니라 카드 자체가 게이지가 됩니다
- **영역 카드의 밑줄형 진행바.** 제목 아래 얇은 선이 점수를 나타냅니다. 100은 초록, 84는 금색
- **「근거 보기 ▾」로 판정 근거를 접어 둡니다.** 점수만 주지 않고 왜 그런지를 그 자리에서 폅니다
- **하단에 집계 출처와 시각**을 적습니다 (「기존 QMS 데이터… 실시간 집계 · 2026-09-09 19:07:19」)

> 점수를 보여주는 화면을 만든다면 이 셋을 가져가십시오.
> 근거를 접어 두기 · 출처와 시각 밝히기 · 심각도를 개수로 쪼개기.

### `matrix-design-trace` · 교차 매트릭스

- 6열(사용자 요구 · 설계입력 · 설계출력 · 검증 · 유효성확인 · 상태)
- 셀마다 **코드(mono·색)와 본문을 위아래로**. 코드 색이 열마다 다릅니다
- **3상 라디오 `○ ⊙ ⊗`**: 미정 · 통과 · 실패. 선택된 것만 초록 테두리
- 상단 KPI 가 «끊긴 사슬 0 · 실패 0 · 완결 7» 로 표의 건강도를 요약

> **3상 라디오가 요점입니다.** 체크박스는 「했다/안 했다」 두 상태뿐이라
> 「아직 안 봤다」와 「보고 실패했다」가 같아집니다. 판정 화면에서는 셋으로 나누십시오.

### `table-audit-trail` · 필터 + 표

- **필터 바**: 검색(포커스 시 금색 테두리) + 셀렉트 2개 + 날짜 범위 + 「× 초기화」
- 필터가 무엇을 하는지 한 줄로 설명 (「검색어: … 요약과 사용자 이메일에서 매칭됩니다」)
- **액션 분포를 차트 대신 「라벨 + 개수」 칩 무리로**. 15종이 자동 줄바꿈으로 깔립니다
- 표 안의 액션을 배지로 감싸 훑기 쉽게

### `list-deadlines` · 기한 추적

- KPI 를 **기한 구간**으로 나눔 (기한 초과 · D-30 이내 · D-90 이내 · 전체)
- **숫자 색이 긴급도** (0은 흰색, 임박은 빨강, 여유는 금색·파랑)
- 행 오른쪽에 `D-6` 과 실제 날짜를 위아래로. **D-day 색도 긴급도를 따릅니다**
- 「타 부서 담당」을 눈 아이콘으로 표시해 내 것과 남의 것을 구분

### `list-qms-documents` · 목록

- 행 왼쪽 금색 띠는 **강조 항목에만**
- **상태에 따라 버튼 자체가 바뀝니다**: 발효됨은 `[승인·발효][재업로드][다운로드][숙지]`, 미업로드는 `[미업로드][업로드]`
- 「관련 양식 46종 › 펼치기」로 긴 목록을 접어 둠
- 상단에 규모 선택(소규모/성장기/성숙기) 세그먼트로 **화면 전체의 기준을 바꿈**

### `detail-complaint` · 상세

- 제목이 이름이 아니라 **식별 코드**(`CPL-2026-001`), 이름은 부제로
- `StageTimeline` 4칸에서 **현재 단계만** 금색 테두리
- `DetailRow` 라벨 왼쪽 / 값 오른쪽 양끝 정렬
- 화면 끝의 **「다음 단계」 카드**가 다음 행동 2개를 제시

### `form-feedback-new` · 기본 폼

- **라벨 옆에 힌트가 같은 줄로** 붙습니다 (아래로 안 내립니다)
- 큰 갈래는 라디오가 아니라 **아이콘 + 제목 + 설명 카드**
- 질문형 라벨과 규제 조항 근거를 함께 (「어디서 온 정보인가요? §8.2.1 은 …」)

### `form-udi-complex` · 복잡한 폼

필드가 많고 조건부로 늘어나는 폼입니다. 기본 폼과 비교해 보십시오.

### `hub-ra-workspace` · 부서 허브

- 모듈 격자가 **입구 목록** 역할 (데이터가 아니라 갈 곳을 늘어놓음)
- KPI 4열 + 탭(부제 두 줄) + 범위 안내(`◆` 포함 / `◇` 제외)
- 프로젝트 카드에 코드 + 배지 + 진행률 + 문서 체크리스트 격자

### `field-receiving` · 현장 모드

- 키보드를 안 띄웁니다. 단위는 **버튼 격자**
- 선택은 테두리가 아니라 **채움**
- 계산 결과를 격자로 즉시 (로트 크기 · 코드 · 표본 n · Ac/Re)
- **판정 근거를 그 자리에 한 줄로** (`d ≤ Ac(1) 합격 · d ≥ Re(2) 불합격`)
- 하단 고정 저장 바 + 저장하면 무슨 일이 일어나는지 예고

## 라이트 모드 대비

`light/` 에 같은 화면 4장이 있습니다: 허브 · 목록 · 폼 · 상세.

다크와 나란히 놓고 보면 이 시스템이 라이트를 어떻게 다루는지 보입니다.

- 배경이 흰색이 아니라 **따뜻한 종이색**(`#faf9f6`)
- 금색이 훨씬 어두워짐 (`#b8935a` → `#8a6838`). 대비를 맞추려면 그럴 수밖에 없습니다
- **주 버튼이 뒤집힙니다.** 다크에서 크림 배경 + 검은 글자였던 것이 검은 배경 + 밝은 글자로
- 그림자가 검정이 아니라 **sepia 톤**
