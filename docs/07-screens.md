# 7장 · 화면 짜임

이 장은 화면을 어떤 순서로, 어느 폭에, 어떤 층으로 짜는지 정합니다. 앞의 두 절(화면 구조 · 조합 패턴)은 화면과 부품 덩어리의 꼴을 설명하고,
가운데 세 절(차림표 · 목록 · 화면 뼈대 정본)은 치수를 한 파일에서 뽑아 제품에 사본으로 내보내 **강제**합니다.
마지막 절은 업무 현황 · 문서 목록 화면에만 거는 조합 규칙입니다.

합친 옛 문서: 11 화면 구조 · 12 조합 패턴 · 15 차림표 정본 · 16 목록 정본 · 17 화면 뼈대 정본 · 25 업무 화면 정돈

제품 이름: 판 이름 Q-Forge 는 제품 Q-Carnet, 판 이름 Q-Works 는 제품 Q-Maison 입니다. 명령의 `--only=` 처럼 판 이름이 필요한 자리만 판 이름을 씁니다.

## 화면 구조

토큰과 부품을 다 옮겨도 화면이 다르게 보이는 이유는 여기 있습니다.
**요소를 어떤 순서로, 어느 폭에, 어떤 층으로 놓는가**가 인상의 절반입니다.
화면은 **다섯 가지 아키타입**으로 모입니다.

### 셸: 사이드바가 척추입니다

```
html · 100dvh · overflow hidden
└ flex
  ├ aside   240px 고정 (접으면 60px · 1024px 미만은 264px 서랍)
  └ main    flex 1 · height 100% · overflowY auto
            padding 32px 40px          ← MAIN_PADDING (SSOT)
```

레일의 치수는 아래 «차림표 정본»이 정합니다.

**스크롤하는 것은 `main` 이고 페이지가 아닙니다.** 사이드바는 화면에 고정됩니다.

가로 탭 바가 최상위 탐색인 앱과는 구조가 반대입니다.
이 시스템에서 가로 탭은 언제나 **2차 축**입니다 (한 화면 안의 단면 전환).

#### 사이드바 안쪽 순서

```
Q 로고 글리프 (세로 스택) + 조직명
─────────────────────────────
홈
워크스페이스        ∨   ← 접이식 묶음
  RA                   ← 활성: 굵은 글자 + 바탕 + 글자 밑 짧은 금색 선
    인허가 현황         ← 활성 묶음만 하위 메뉴 펼침
    보험 등재 조회
    …
연계 부서           ∧   ← 기본 접힘
업무                ∨
공통                ∨
설정                ∨
─────────────────────────────
MEDQRAFT CORE  v3.5.0    ← 모노 · muted · 판 번호 두 줄
Q-ATELIER      v1.3.0
THEME  ● DARK      ‹     ← 테마 토글 + 접기 단추
아바타 사용자명
       소유자 · 엔터프라이즈   ← 역할 줄은 적힌 그대로
로그아웃                  ← 글귀(테두리 · 바탕 없음)
```

- 묶음 이름표는 모노 · 작게 · muted 입니다 (「자원 관리」 · 「모니터링·측정」 · 「추적성·문서」). 한글이면 자간과 대문자를 풉니다.
- 묶음 접힘 상태는 `qa-nav-grp-<키>` 로 하나씩 저장합니다.
- 사이드바 접힘은 **계정별 키**로 저장합니다.
- 폰에서는 왼쪽으로 60px 넘게 밀면 닫힙니다.
- 항목 여백 · 아이콘 자리 · 활성 표시의 치수는 «차림표 정본»에 있습니다.

#### 부서가 곧 차림표 구조입니다

메뉴가 기능별이 아니라 **역할별**로 묶입니다. R&D · RA · QA · 생산 넷이고
각 부서에 「허브」 화면이 하나씩 있습니다 (`/research` · `/ra` · `/qa` · `/m`).

내 부서는 「워크스페이스」에, 남의 부서는 「연계 부서」에 접힌 채로 놓입니다.
**같은 앱이 사람마다 다른 모양으로 열립니다.**

#### 본문 우상단 고정 띠

```
● 엔터프라이즈 · CORE 0%        🔔③
```

구독 상태와 알림입니다. 사이드바가 아니라 본문 위에 떠 있습니다.

### 아키타입 다섯

#### ① 허브 (부서 워크스페이스)

```
PageHd            금색 막대 · 모노 부제 · 큰 제목 · 하단선
「ⓘ 이 페이지 사용법」 칩    ← PageGuide (화면 머리 ⓘ). 누르면 팝업
모노 이름표 「인허가 모듈」
모듈 격자          HubModuleGrid (조합 패턴 «모듈 격자»)
KPI 4열            라벨 + 큰 숫자 + 보조설명
가로 탭            WorkspaceTab 「허가 준비 (2)」 「허가 후 변경 (1)」 · 부제 · 활성만 금색 밑줄
범위 안내          ◆ 포함 / ◇ 제외 를 기호로 명시
엔티티 카드들       코드(모노) + 제목 + 배지 + 진행률 + 체크리스트 격자
```

허브는 **「이 부서 사람이 오늘 볼 것」의 목차**입니다. 데이터가 아니라 입구를 늘어놓습니다.

#### ② 목록

```
<div>                                  ← 폭 제한 없음. 전체폭을 씁니다
  PageHd (제목 · 조항 부제 · 「새 X」 단추)
  PageWidgetBoard                      ← 화면 머리 ⓘ(PageGuide)를 보드가 함께 그립니다
    · KPI 요약   (Grid minCol 140 · gap 12)
    · 목록       (EntityRow 반복 · locked)
    · ListPager
</div>
```

목록은 폭 제한이 없습니다. 표와 행은 넓을수록 좋기 때문입니다. 2026-10-27 부터는 상세 · 폼도 좁히지 않습니다(아래 «폭과 칸 격자»).

#### ③ 상세

```
<PageShell>                             ← 폭을 좁히지 않는 공용 틀(.qd-shell-page)
  ← 목록으로                            ← 뒤로 링크가 맨 위
  PageHd (모노 상태 부제 「접수 · Major」 · 코드 제목 「CPL-2026-001」)
  주 액션 단추                          ← 있으면 머리 바로 아래
  StageTimeline                        ← 4~6 마디 가로 (조합 패턴 «단계 표시»)
  SectionCard 여럿                      ← 조합 패턴 «상세의 사실 블록»
    · 제목 + 부제
    · DetailRow 반복 (라벨 왼쪽 / 값 오른쪽 양끝 정렬)
    · 본문 문단
    · 고치는 칸은 Fields 격자            ← 아래 «폭과 칸 격자»
  「다음 단계」 카드                     ← 화면 끝에서 다음 행동을 제시
</PageShell>
```

**제목이 이름이 아니라 «식별 코드»** 입니다. 이름은 부제로 갑니다.
규제 문서는 코드로 불리기 때문입니다.

마지막 「다음 단계」 카드가 이 시스템의 성격을 잘 보여 줍니다.
브랜드가 「동반자」와 「놓침 0」이라, 화면이 끝나는 자리에서 **다음에 무엇을 할지 짚어 줍니다.**

#### ④ 생성 폼

```
<PageShell>
  PageHd (조항 부제 「ISO 13485 §8.2.1: …」 · 제목 · 오른쪽 「← 목록」)
  <Bx padding …>                       ← 폼 전체가 카드 하나 안에
    SegmentedChoice                    ← 큰 갈래는 라디오가 아니라 카드형 선택
    FieldGroups                        ← 묶음이 둘 이상이면 감싼다(묶음 사이 24)
      Fields                           ← 칸 격자. 짧은 칸은 들어가는 만큼 한 줄에
        · 긴 칸(요약 · 상세 · 주소)은 wide 로 줄 끝까지
      Fields                           ← 뜻이 다른 묶음은 새 격자로
    FormSection (구획이 필요하면)
    체크박스 블록
    FormActions                        ← 상단 1px 경계 · 오른쪽 정렬
  </Bx>
</PageShell>
```

칸 이름표 · 힌트 · ⓘ 의 배치는 조합 패턴 «폼 필드»에 있습니다.

질문형 라벨(「어디서 온 정보인가요?」)과 조항 근거가 함께 오는 것은
「선생님」이라는 브랜드 정체성이 폼 구조로 나타난 것입니다.

#### ⑤ 현장 모드 (`/m/*`)

**규칙이 통째로 다릅니다.** 장갑 낀 손이 패드를 쓴다는 전제입니다.

```
셸 폭       520px (폰) → 768px 이상에서 760px      ← .qa-field-screen
입력        화면 키보드를 띄우지 않습니다
            수량은 숫자판 · 단위는 단추 격자 (ea/set/box/kg/g/L/mL/m/roll)
선택        «채운» 상태로 표시 (테두리가 아니라 금색 바탕)
계산 결과    즉시 격자로 (로트 크기 · 코드 · 표본 n · Ac/Re) + 판정 배지
판정 근거    그 자리에 한 줄로 (d ≤ Ac(1) 합격 · d ≥ Re(2) 불합격)
저장        하단 고정 · 전체폭 · 초록 · 매우 큼
```

계약(`source/contracts/field-no-keyboard.test.ts`)이 이것을 강제합니다.
`<textarea>` 가 없어야 하고, `<input>` 은 누르거나 고르거나 스캔만 합니다
(허용: `type` 이 button · checkbox · radio · file · date · time 이거나 `inputMode="none"`).
화면 조합은 조합 패턴 «현장 모드 조합»에 있습니다.

### 위젯 보드: 화면을 사용자가 재배치합니다

목록 · 허브 화면의 본문은 그냥 쌓인 것이 아니라 **보드**입니다.

```tsx
<PageWidgetBoard pageId="capa" pageGuideId="capa" userId={user.id} items={[
  { id: 'kpi',  title: 'KPI 요약',   node: kpiNode,  width: 'full' },
  { id: 'list', title: 'CAPA 목록', node: listNode, width: 'full', locked: true },
]} />
```

- 편집 모드를 켜면 **끌어서 순서 변경 + 표시/숨김**
- 위/아래 단추도 함께 둡니다 (접근성 · 모바일)
- `locked: true` 인 항목은 **순서만 바뀌고 숨길 수 없습니다** (필수 UI 실종 방지)
- `board:<pageId>:<userId>` 로 localStorage 에 저장합니다. 사용자별 · 화면별로 나뉩니다
- 평소엔 조작부가 안 보이고 편집 모드에서만 나옵니다

**`PageHd` 와 `PageGuide` 는 보드 밖에 둡니다.** 항상 고정 노출입니다.

> 이 구조가 쓸 만한 이유는, 「이 위젯을 보여 줄까 말까」를 논쟁하지 않아도 되기 때문입니다.
> 다만 **잠금을 안 걸면 필수 UI 가 사라집니다.** 폼 본문 · 저장 바 · 주요 표는 반드시 `locked` 입니다.

### 화면 안 요소 순서

다섯 아키타입에 공통으로 흐르는 순서가 있습니다.

```
1. 어디서 왔나        뒤로 링크 (상세만)
2. 무엇인가          PageHd: 막대 · 부제 · 제목 · 하단선
3. 이게 뭔지 설명     PageGuide 칩 (화면 머리 ⓘ)
4. 지금 상태         StageTimeline · KPI · 상태 배지
5. 내용             SectionCard · 목록 · 폼
6. 무엇을 할까       주 액션 · 「다음 단계」 카드 · FormActions
```

**설명이 3번에 온다**는 점이 특징입니다. 내용보다 먼저입니다.
규제를 처음 접하는 사람이 쓰는 시스템이라는 전제가 순서로 나타난 것입니다.
설명 글 자체는 화면에 깔지 않고 ⓘ 안에 둡니다 (조합 패턴 «안내»).

### 폭과 칸 격자 (2026-10-27 오너 결정 «3»)

| 화면 | 폭 | 정본 | 왜 |
|---|---:|---|---|
| 목록 · 허브 | 제한 없음 | | 행과 표 · 모듈 격자는 넓을수록 좋습니다 |
| 상세 · 생성 폼 | 제한 없음 | `PageShell` (`.qd-shell-page`) | 넓은 화면에서 양옆이 비지 않게. 넓이는 한 줄의 칸 수로 받습니다 |
| 현장 모드 | 520 → 760 | `LAYOUT.mobile` (520) | 폰과 패드. 장갑 낀 손으로 한 번에 한 가지 |

옛 판은 상세 820 · 폼 720 · 2단 1140 으로 좁히고 가운데 두었습니다. 넓은 화면에서 가운데 기둥만 남아 오너가 «꽉 채움 + 칸 자동» 을 골랐습니다.
현장 모드만 `LAYOUT.mobile` 로 좁히고 `margin: 0 auto` 로 가운데 놓습니다. 계약(`source/contracts/page-shell-contract.test.ts`)이 «현장 말고는 좁히지 않는다» 와 «좁힌 현장 틀은 가운데» 를 지킵니다.

상세 · 폼의 칸은 `Fields` (`.qd-fields`) 격자에 놓습니다. 칸 하나는 300px 를 지키고 들어가는 만큼 한 줄에 놓습니다(1920 다섯 칸 · 1440 세 칸 · 폰 한 칸). 값은 [4장 «칸 격자»](04-space-layout.md) 에 있습니다.

1. **긴 칸은 줄 끝까지.** 주소 · 비고 · 여러 줄 글 · 여러 개 고르기는 `wide` (`.qd-field-wide`)로 그 줄을 다 씁니다. 두 칸 폭으로 두면 세 칸이 드는 폭에서 옆에 빈 칸이 남습니다.
2. **적는 차례대로, 뜻으로 묶어서.** 단순히 넓히지 않고 사람이 적는 차례(누구 → 무엇 → 언제 → 판단)로 놓습니다. 짝인 칸(체결일 · 만료일, 수량 · 단위, 출처 · 출처 문서 번호)은 이웃하게 둡니다. 앞 칸을 고를 때만 나타나는 칸은 그 칸 바로 뒤에 둡니다. 뜻이 다른 묶음은 `Fields` 를 새로 열어 새 줄에서 시작하고, 잇달아 놓은 묶음은 `FieldGroups` 로 감쌉니다. 묶음 사이(24)는 줄 사이(16)보다 넓습니다.
3. **칸 안 회색 안내.** 글을 적는 칸에는 «무엇을 적는지» 를 회색 안내(placeholder)로 둡니다. 칸 이름이나 도움말을 되풀이하지 않고, 예는 «예: …» 로 시작하며, 근거 없는 수치 · 조항은 지어내지 않습니다. 날짜 · 고르기 칸에는 두지 않습니다. 읽기 전용 칸에서는 `In` · `Txt` 가 알아서 숨깁니다(빈 칸의 «예: …» 가 적힌 값처럼 읽히기 때문입니다).
4. **기록 표의 입력판은 펼친 보기와 같은 묶음 · 같은 차례.** `RegisterSection` 은 `view.groups` 대로 입력판을 그립니다. 묶음이 없는 표만 짧은 칸을 먼저 모읍니다.
5. **칸 이름 옆에는 짧은 형식 안내만.** «최소 5자» · «쉼표로 구분» 처럼 `FIELD_HINT_MAX`(20자) 안의 글귀만 이름 옆에 보입니다. 더 긴 글귀는 `FldRow` 가 칸 ⓘ 안으로 옮기고, 낭독기에는 칸 설명으로 그대로 잇습니다. 이름 옆 긴 문장(최대 165자가 있었습니다)은 이름과 눈길을 다투고 이름 줄을 여러 줄로 밀어 그 칸만 입력 상자가 내려앉았습니다. 무엇을 적는지 · 예는 3번의 회색 안내로, 근거 · 설명은 `info` 로 둡니다.
6. **잠긴 칸은 적는 칸과 달라 보이게.** 읽기 전용(`readonly`)과 꺼진 칸(`disabled`)은 화면 바탕(`--qd-bg`)과 옅은 테두리(`--qd-border`)를 씁니다. 흰 상자 · 진한 테두리 그대로면 «적어야 하나, 이미 적혔나» 가 갈리지 않습니다. 모양은 정본 CSS(`.qd-input[readonly]` · `.qd-input:disabled`)가 쥐고, 부품은 잠금 표시만 답니다.
7. **이름 줄 높이를 맞춘다.** 한 줄에 놓인 칸은 이름 줄 높이가 같아 입력 상자 윗선이 한 줄로 맞아야 합니다. 이름 옆 도움말은 칸 아래 도움말과 달리 위 여백을 두지 않습니다(4px 가 이름 줄을 키워 그 칸만 내려앉았습니다).

모달 · 드로어처럼 폭이 정해진 상자 안은 `foldGrid` 를 그대로 씁니다.

### 옮겨 쓸 때

전부 흉내 낼 필요는 없습니다. 인상을 만드는 것은 이 넷입니다.

1. **왼쪽 사이드바 고정 + `main` 만 스크롤.** 가로 탭을 최상위로 쓰면 완전히 다른 앱이 됩니다
2. **`PageHd` 를 모든 화면에 같은 모양으로.** 금색 막대 · 모노 부제 · 큰 제목 · 하단선
3. **상세 · 폼은 좁히지 말고 칸 격자로.** 넓은 화면은 한 줄의 칸 수로 받고, 긴 칸은 줄 끝까지 씁니다(2026-10-27 «3»)
4. **화면 끝에서 다음 행동을 제시.** 「다음 단계」 카드 하나가 시스템의 성격을 바꿉니다

## 조합 패턴

[6장 부품](06-components.md)이 부품 하나하나의 규격이라면, 여기는 **부품이 모여 만드는 덩어리**입니다.
실제 화면에서 되풀이되는 조합만 골랐습니다.

### 목록 행 (`EntityRow`)

```
 ◉  NC-2026-001  [중대]                           [액션] [액션]  ›
    광출력 측정값이 규격 상한을 초과했습니다
    조항 메타 · 통합 설명
──────────────────────────────────────────────────────────────── ← 아래 괘선 1px
 ↑ 아이콘 칩 (상태 색)
```

상자와 왼쪽 색 띠 없이 **괘선 목록**으로 섭니다. 상태는 배지 글자와 아이콘 칩 색이 말합니다
(오너 결정 2026-09-27 «문서 결», [8장](08-paper.md)). 치수는 «목록 정본 · 항목 줄»에 있습니다.

액션 단추는 오른쪽에 모읍니다. 그리고 **상태에 따라 단추 자체가 바뀝니다.**

```
발효됨:  [승인·발효] [재업로드] [다운로드] [숙지]
미업로드: [미업로드]  [업로드]
```

단추를 회색으로 죽이는 대신 **다른 단추를 보여 주는** 방식입니다.

### 상세의 사실 블록 (`SectionCard` + `DetailRow`)

```
┌────────────────────────────────────────────┐
│ 접수 요약                                   │  ← 제목 (h3 톤)
│ 고객 보고 사실                              │  ← 부제 (12px · subtle)
│                                            │
│ 접수 경로                             전화  │  ← DetailRow: 양끝 정렬
│ 고객                  서울피부과의원·김혜진   │
│ LOT                          LOT-2026-002  │
│ 접수일               2026-08-30 18:00:35   │
│                                            │
│ 시술 중 LED 조사 밝기가 고르지 않다는…       │  ← 본문 문단
└────────────────────────────────────────────┘
```

```
SectionCard  padding 24 · marginBottom 16 · background surface · radius 10
DetailRow    display flex · justify-content space-between · padding 6px 0
             라벨: 모노 12px · subtle · labelTracking (한글이면 자간 0 · 대문자 없음)
             값:   13px · text
```

**라벨 왼쪽 / 값 오른쪽 양끝 정렬**이 핵심입니다.
값이 오른쪽 축에 정렬되면 여러 줄을 세로로 훑을 수 있습니다.
숫자 · 날짜가 많은 화면에서 표를 쓰지 않고도 표처럼 읽힙니다.

### 단계 표시 (`StageTimeline`)

```
  ◯ ──────── ◯ ──────── ◉ ──────── ◯
 접수        조사       CAPA       종결
                         ↑ 현재: 라벨 · 캡션을 굵게 (emphasis)
```

```
마디     40px 원 · 마디 사이를 2px 선으로 잇습니다 · 라벨과 캡션은 마디 아래
배치     fill 이면 전체폭에 고르게 나눠 gap 0, 아니면 gap 4 · fit-content
마커     check · dot · circle · cancel · none
색       원의 색 · 채움(filled) · 연결선 색은 부르는 쪽이 넘깁니다
선택     selected 는 단계 거르기에서 고른 마디(금색 고리)입니다. «현재»와 다릅니다
```

**지나간 단계와 남은 단계를 색으로 나누지 않습니다.** 현재만 강조합니다.
지나간 것을 초록으로 칠하면 「끝났다」로 읽혀 되돌릴 수 없는 인상을 줍니다.

### 폼 필드 (`Field`)

```
알려준 사람 *                      유입 채널  전화·이메일·포털·현장 등 자유 입력
┌─────────────────────┐          ┌─────────────────────┐
│ 고객              ▾ │          │                     │
└─────────────────────┘          └─────────────────────┘
```

- 이름표는 작은 모노 글자(12 · 굵기 500)입니다. 한글이면 자간과 대문자를 풉니다
- **힌트는 같은 줄 오른쪽에 muted 로 작게** 붙입니다. 별도 줄로 내리지 않습니다
- 힌트는 「YYYY-MM-DD」 · 「최대 10MB」 같은 **짧은 형식 안내**에만 씁니다. 설명 문장
  (예: 「긍정 피드백도 §8.2.1 의 수집 대상입니다」)은 이름표 옆 ⓘ(`info`) 안에 넣습니다
- 필수는 빨간 별표, 필수가 아닌 칸은 이름표 안에 「필수 아님」
- 2열 격자가 기본, 긴 입력(요약 · 상세)만 전체폭
- 좁은 폭에서는 1열로 접힙니다

힌트를 아래로 내리지 않는 이유는 세로 길이 때문입니다.
규제 폼은 필드가 많아서, 힌트를 줄마다 아래에 달면 화면이 두 배로 길어집니다.

#### 구획 (`FormSection`)

```
01 기본 정보                       ← 구역 제목 꼴: 본문색 16 · 700 · 앞에 금색 모노 번호
──────────────────────────────     ← padding-bottom 4 · 1px 하단선 · 위 여백 20
```

구획 설명은 제목 옆 ⓘ 안에 둡니다.

#### 액션 (`FormActions`)

```
──────────────────────────────     ← 상단 1px 경계 · padding-top 14
                  [취소] [저장]    ← 오른쪽 정렬(기본) · gap 8
marginTop 18
```

정렬은 오른쪽(기본) · 양끝(`between`, 취소 왼쪽 · 저장 오른쪽) · 가운데 셋입니다.

### 큰 갈래 고르기 (`SegmentedChoice`)

```
┌───────────────────────────┐  ┌───────────────────────────┐
│ ✓ 🌐 시판 후               │  │ 📈 생산                    │
│    고객·유통·서비스에서     │  │    현장 작업자·검사원에게   │
└───────────────────────────┘  └───────────────────────────┘
   ↑ 선택됨: 짙은 테두리(글자색) + 체크
```

두세 갈래 중 하나를 고르는 자리에 라디오 단추를 쓰지 않습니다.
**아이콘 + 제목 + 한 줄 설명**을 담은 카드형으로 만듭니다.

골라진 칸은 **짙은 테두리 + 체크** 한 가지로 표시합니다. 채운 면은 주 단추 전용입니다.
선택을 채운 면으로 그리면 단추처럼 보여 «눌러야 하나» 헷갈리고, 뜻 색(초록 = 정상)과 겹쳐 상태로 읽힙니다.
항목 색은 체크 표시에만 남습니다. 현장 모드의 `ChoiceGroup` 은 장갑 손 규격이 따로 있어 «채움»을 씁니다.

접근성은 마크업으로 지킵니다: `role="radiogroup"` + `role="radio"` + roving tabindex.
화살표로 이동하고 비활성은 건너뜁니다. 계약이 전부 검사합니다.

셋으로 나뉘는 짧은 선택(긍정/중립/부정)은 같은 부품의 **좁은 변형**입니다.

### 지표 행 (`KPI`)

```
진행 중 ⓘ        허가 받은 제품 ⓘ    내 검토 대기 ⓘ     진행 중 변경 ⓘ
2                1                  0                 0
아이디어~인허가    시판 중·허가 후 관리  검토 중·내 의견 미등록  조직 전체
```

치수는 «화면 뼈대 정본 · 요약 지표»에 있습니다.

**숫자 색이 뜻을 실어 나릅니다.** 기본은 크림(본문색), 좋은 것은 초록, 주의는 금색, 위험은 빨강.
0 은 색을 주지 않습니다 (없는 것에 색을 칠하면 소음이 됩니다).

라벨 옆 ⓘ 는 산식이나 집계 범위를 그 자리에서 펴는 팝업입니다. 기본은 누르거나 Enter 로 엽니다.

### 모듈 격자 (`HubModuleGrid`)

```
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ ▣  인허가 현황 │ │ ▣  보험 등재  │ │ ▣  부작용 보고 │
└──────────────┘ └──────────────┘ └──────────────┘
```

```
grid-template-columns: repeat(auto-fill, minmax(180px, 1fr)) · gap 10
칸: padding 14px 16px · minHeight 62 · gap 12
아이콘: 샴페인 알파 배경 사각 · radius 10
이름: 13px
```

허브 화면의 입구 모음입니다. `auto-fill` 이라 화면이 넓으면 한 줄에 더 들어갑니다.

### 탭 (`WorkspaceTab`)

```
허가 준비 (2)      허가 후 변경 (1)
개발 ~ RA 연계     제품 단위 변경 등록
━━━━━━━━━━━━
```

```
padding 14px 20px · fontSize 14
활성: weight 600 · text 색 · border-bottom 2px champagne
비활성: weight 400 · muted · 투명 하단선
개수는 champagne 색으로 제목 옆에
부제는 아래 줄에 작게 (모노 12 · muted)
```

**탭에 부제가 붙습니다.** 이름만으로 무엇이 들어 있는지 모를 때 한 줄로 설명합니다.
개수와 부제가 붙는 허브 탭입니다. 화면 안을 가르는 일반 2차 탭 줄은 «화면 뼈대 정본»의 `.qd-tabs` 입니다.

### 안내 (ⓘ · `Alert` · `InfoBox`)

**설명 글은 화면에 깔지 않고 세 층의 ⓘ 안에 둡니다** (오너 결정 2026-10-08).

| 층 | 부품 |
|---|---|
| 화면 머리 | `PageGuide` 칩(「ⓘ 이 페이지 사용법」) · `PageHd` 의 `info` |
| 구역 | `SectionTitleInfo` · `SectionCard` · `FormSection` 의 ⓘ |
| 칸 | `Field` 의 `info` (`InfoDot`) |

ⓘ 안내는 언제나 다른 요소 위에 뜨는 팝업입니다. 본문 안에 펼쳐 아래 내용을 밀어내지 않습니다.
화면에 그대로 남는 글은 이것뿐입니다: 오류 · 경고(`Alert` · `FldError`), 빈 화면 한 줄(`EmptyState`),
다음 할 일 한 줄(`NextStep`, 앞에 금색 →), 법규 문구(`LegalNote`).
계약(`source/contracts/explanation-text-contract.test.ts`)이 화면에 날것으로 놓인 설명 문장을 셉니다.

| 부품 | 언제 | 모양 |
|---|---|---|
| `Alert` | 지금 일어난 일 · 조치가 필요한 것 | `qd-notice` 판(바탕 surface · 네 변 테두리를 상태 색 45% 로) + 아이콘 + 종류 말(오류 · 주의 · 완료 · 안내) + 제목. 오류 · 주의는 `role="alert"`, 완료 · 안내는 `role="status"` |
| `InfoBox` | 이 블록에 대한 부연 | 바탕 없이 위아래 가는 가로선(종류 색) 사이의 한두 문장 · 13px · subtle |

범위를 밝힐 때는 기호를 씁니다.

```
◆ RA 카테고리 문서만 추적합니다 (기술 문서, 식약처 신청서 … 등 22종).
◇ 개발 카테고리 문서는 R&D 가 책임지며 본 화면에서는 표시하지 않습니다.
```

**포함과 제외를 나란히 적습니다.** 「무엇을 안 보여 주는지」를 밝히는 것이
규제 시스템에서 신뢰를 만드는 방식입니다.

### 현장 모드 조합

```
입고 수량
┌───────────────────────────────────────────────┐
│ 수량                                           │
│ 100 ea                                        │  ← 매우 큰 숫자
└───────────────────────────────────────────────┘
[ea] [set] [box] [kg] [g] [L] [mL] [m] [roll]     ← 단위는 단추 격자
      ↑ 선택됨: 금색 테두리

☑ 표본검사 적용 (ISO 2859-1)
검사 수준
┌──────────┐ ┌──────────┐ ┌──────────┐
│ 수준 I    │ │ 수준 II   │ │ 수준 III  │
│ 완화      │ │ 보통      │ │ 엄격      │           ← 선택됨은 «채움»
└──────────┘ └──────────┘ └──────────┘

로트 크기    코드     표본 n    Ac / Re
   100        F        20       1 / 2            ← 계산 결과를 즉시 격자로

표본 중 발견 불량 수 (d)
┌────────────────────────────────┐ ┌────────┐
│ 0                              │ │  합격   │      ← 판정을 옆에 즉시
└────────────────────────────────┘ └────────┘

┌───────────────────────────────────────────────┐
```

일반 화면과 다른 점 넷.

1. **선택은 테두리가 아니라 «채움»** 입니다. 장갑 낀 손이 멀리서 봐야 합니다
2. **계산 결과를 숨기지 않습니다.** 규격 · 표본수 · 판정 기준을 그 자리에 폅니다
3. **판정 근거를 한 줄로 적습니다.** 결과만 주면 사람이 확인할 수 없습니다
4. **저장하면 무슨 일이 일어나는지 예고합니다**

### 이 시스템이 안 하는 것

옮길 때 함께 가져가면 좋은 «절제» 목록입니다.

- **모달을 잘 안 씁니다.** 확인 · 간단 입력만. 내용은 화면에 폅니다
- **탭을 최상위에 두지 않습니다.** 사이드바가 1차, 탭은 한 화면 안의 2차 축입니다
- **아코디언을 남발하지 않습니다.** 접는 것은 「관련 양식 46종」처럼 진짜 긴 것만
- **툴팁에 필수 정보를 넣지 않습니다.** 산식 · 범위 같은 부연만
- **비활성 단추로 막지 않습니다.** 상태에 맞는 다른 단추를 보여 줍니다
- **빈 화면을 초라하게 두지 않습니다.** 96px 여백 + 조용한 제목 + 다음 행동(단추나 표지)

| 차림표 | `tools/extract-nav.mjs` | `dist/q-design.nav.css` · `dist/q-design.nav.json`(치수 56 개) | `components/Sidebar.tsx` · `css/globals.css` · `components/components.tsx` · `components/TextAction.tsx` · `components/LogoutButton.tsx` |
| 목록 | `tools/extract-list.mjs` | `dist/q-design.list.css` · `dist/q-design.list.json` | `components/components.tsx`(DataTable · EntityRow · Tag) · `tokens/tag-metrics.ts` · `components/ListPager.tsx` · `components/ListToolbar.tsx` · `css/globals.css` |
| 화면 뼈대 | `tools/extract-screen.mjs` | `dist/q-design.screen.css` · `dist/q-design.screen.json` | `components/components.tsx`(KPI · Stat · Grid · PageHd · Btn · In · SectionTitle · Lbl) · `components/PageTabs.tsx` · `tokens/tokens.ts` · `tokens/main-padding.ts` · `css/globals.css`, 끝에 `patterns/workspace.css` |

- 추출기는 원본을 **읽습니다.** 숫자를 옮겨 적지 않습니다. 각 치수마다 탐침(probe)이 있고, 그 탐침은 지정한 구역 안에서
  **정확히 한 번** 맞아야 합니다(`tools/probe.mjs`).
  - **0 번 맞으면** 원본이 바뀐 것입니다. 값을 스크립트에 적어 넣지 말고 탐침을 고치십시오.
  - **2 번 이상 맞으면** 구역이 너무 넓은 것입니다. 접힌 레일과 펼친 레일이 같은 속성을 다른 값으로 쓰고,
    한 항목 안의 조각(링크 · 아이콘 · 밑줄 · 배지)이 저마다 `fontSize` 를 갖습니다. **뽑히기는 뽑히는데 어느 값인지 모르는**
    채로 두면 정본이 거짓말을 합니다.
- `dist/` 의 파일은 생성물입니다. 손으로 고치지 말고 원본을 고친 뒤 다시 만듭니다.
- 세 정본 모두 **Q-Sonar · Q-Carnet(판 Q-Forge) · Q-Maison(판 Q-Works)** 이 받습니다(`tools/sync-parts.mjs`).
  사본 머리에 본문의 sha256 지문이 찍히고, 받는 쪽 검사가 그 지문을 다시 계산해 대조합니다.
- 시험이 강제하는 다른 것들은 [10장 지키는 규칙](10-rules.md)에 있습니다.

```
node tools/extract-all.mjs            전부 다시 만들기 (세 추출기가 이 안에서 돕니다)
node tools/extract-all.mjs --check    만들지 않고 어긋난 곳만 보기
node tools/extract-all.mjs --sync     만든 뒤 제품으로 내보내기 (제품 저장소에 쓰는 길은 이것 하나)
```

### 왜 차림표만 따로 정본을 두는가

나란히 놓았을 때 «같은 집안» 인지를 정하는 것은 본문이 아니라 차림표입니다.
본문은 제품마다 다른 일을 하니 달라도 됩니다. Q-Atelier 는 문서를 다루고,
Q-Sonar 는 회사를 찾고, Q-Carnet 은 배치를 찍습니다.

**차림표는 제품들이 똑같이 하는 유일한 일입니다.** 그래서 여기가 어긋나면
다른 회사 제품으로 읽히고, 여기가 같으면 본문이 달라도 형제로 읽힙니다.

그리고 차림표는 **어긋나기 쉽습니다.** 「11px 14px」 같은 값을 저장소마다
손으로 적으면 값이 여러 벌이 됩니다. 한 곳이 `py-2`(8px)로 적히는 순간 항목 높이가
6px 낮아지고, 열 칸이면 60px 이 어긋나 바닥 블록의 자리가 달라집니다.
[[duplicated-fact-drift]] 그대로입니다.

### 치수 (`dist/q-design.nav.json` 에서 나옵니다)

#### 레일

```
폭          240px                 접으면 60px
서랍        264px  ·  max 85vw    1024px 미만에서 자동
높이        100dvh                100vh 가 아닙니다. iOS 주소창이 움직입니다
패딩        22px 16px             접히면 18px 6px
바탕        surface               오른쪽에 1px border
```

레일 위에 경고 띠 같은 것이 놓인 제품은 그 높이를 `--qd-rail-offset` 으로 알려 줍니다. 레일 높이에서 그만큼 뺍니다.

🔴 **스크롤하는 것은 `.qd-rail-nav` 이지 레일 전체가 아닙니다.**
레일을 통째로 스크롤로 두면 화면 높이가 768~1000px 일 때 로고와 바닥 계정
블록이 같이 밀려 올라가 「푸터가 없는」 것처럼 보입니다.

#### 로고 블록

```
표식        폭 108px (.qd-rail-mark)
조직명      모노 12px · 자간 0.4px · 등록한 표기 그대로(대문자로 바꾸지 않음 · 오너 결정 2026-09-28)
```

#### 항목

```
여백        11px 14px             ← 가장 흔히 어긋나는 값
왼쪽 여백   17px                  옛 왼쪽 막대 3px 를 여백으로 돌려 글자 자리가 그대로
글자        14px · 자간 0.1px     쉴 때 400 · 활성 600
아이콘      자리 18px · 글리프 16px · 선 굵기 1.75
간격        12px  (아이콘과 글자 사이) · 항목 사이 3px
활성        굵은 글자 + surface2 바탕 + 글자 밑 16px 금색 선(1.5px · 글자 아래 5px · 모서리 1)
전환        0.12s ease
배지        모노 12px · 굵기 700 · 여백 2px 8px · 알약 · danger 바탕
```

선택 표시에 **왼쪽 금막대와 오른쪽 금점을 쓰지 않습니다.** 흔한 AI 화면의 꼴로 읽힌다는 오너 지적에 따른
«문서 결» 결정입니다(오너 결정 2026-09-27 · [8장](08-paper.md)). 항목의 모서리는 굴리지 않습니다.

> 이것은 **항목** 이야기입니다. 발치의 테마 상자 · 아이콘 단추는 10px 로 굴립니다
> (오너 결정 2026-09-14 「통일성이 더 중요」). 값은 원본 Sidebar 에서 읽습니다.

**밑줄은 들어설 때 한 번만 왼쪽부터 펼쳐집니다** (320ms · `cubic-bezier(0.16, 1, 0.3, 1)` · scaleX 0 → 1).
`prefers-reduced-motion` 에서는 펼치지 않고 그대로 보입니다. 원본은 별도 요소(`qa-nav-active-underline`),
정본은 이름표의 `::after` 입니다(이름표가 말줄임으로 넘친 것을 자르므로 아래 안쪽 여백에 둡니다).

「26일」처럼 읽는 말이 들어가는 배지는 조용한 배지(`.qd-nav-badge--quiet`: 테두리 · 모서리 6)로 둡니다.
빨간 알약으로 만들면 급하지 않은 것이 급해 보이고, 열 칸에 열 개가 켜집니다.

#### 묶음 이름표

```
여백        12px 14px 4px
글자        모노 12px · 자간 1.6px · 대문자 · muted
```

🔴 **한글에는 자간과 대문자를 걸지 않습니다.** 그 장치는 라틴 글자 사이를
벌리라고 만든 값이라 한글에 걸면 「묶 음」 처럼 벌어집니다. 한글이 섞인
이름표에는 `data-hangul` 을 붙이십시오. 자간과 대문자가 함께 풀립니다.
Q-Atelier `lib/design/tokens.ts` 의 `labelTracking()` 과 같은 규칙입니다([3장](03-typography.md)).

「원본과 같게」와 「규칙대로」가 갈릴 때는 **규칙이 이깁니다.**
규칙에는 근거가 있고, 박힌 값에는 없습니다.

#### 바닥

```
판 번호     여백 4px 4px 8px · 모노 12px · 자간 0.6px
            왼쪽 이름 muted / 오른쪽 판 champagne
테마 줄     여백 10px 14px · 모노 12px · 자간 1.5px · 1px 테두리 · 모서리 10
            옆에 44x44 접기 단추(모서리 10)
경계        위쪽 1px border · padding-top 12px
아바타      32px 원 · champagne 22% 를 섞은 면 · weight 600 · 글자 14.4px
이름        13px · weight 500 · text
역할        본문 글꼴 12px · 자간 0.4px · 대문자 없음 · muted
로그아웃    글귀: 테두리 · 바탕 없음 · 최소높이 36(손가락 기기 44) · 여백 0 4px · 13px
            muted → 올리면 text
```

- 판 번호 줄의 대문자는 **이름에만** 겁니다. 줄 전체에 걸면 v1.3.0 이 V1.3.0 이 됩니다. 판 번호는 사람이 적은 그대로 나와야 합니다.
- 아바타 글자는 원본(`size × 0.45`)과 같게 14.4px 로 두고 반올림하지 않습니다. 사본이 원본과 다르면 안 됩니다.
- 역할 줄은 «소유자 · 엔터프라이즈» 처럼 적힌 그대로 본문 글꼴로 씁니다(오너 결정 2026-09-28). 한글이면 `data-hangul` 로 자간이 0 이 됩니다.
- 로그아웃은 보조 동작이라 **글귀**입니다(오너 결정 2026-09-28 · 원본 TextAction 과 같은 모양). 상자 단추로 두면 차림표 발치에서 주 동작처럼 무게를 가집니다.

### 뼈대

클래스 이름이 곧 계약입니다. 이 순서와 이 이름을 씁니다.

```html
<aside class="qd-rail">
  <a class="qd-rail-brand" href="/">
    <img src="/logo-mark.png" alt="">
    <span class="qd-rail-org" data-hangul>회사 이름</span>
  </a>

  <nav class="qd-rail-nav">
    <div class="qd-nav-group" data-hangul>실행</div>
    <a class="qd-nav-item is-active" href="/dashboard">
      <span class="qd-nav-icon"><svg>...</svg></span>
      <span class="qd-nav-label">오늘 할 일</span>
    </a>
    <a class="qd-nav-item" href="/targets">
      <span class="qd-nav-icon"><svg>...</svg></span>
      <span class="qd-nav-label">타깃 정의</span>
      <span class="qd-nav-badge">3</span>
    </a>
  </nav>

  <div class="qd-rail-version"><span>Q-SONAR</span><b>v1.4.0</b></div>

  <div class="qd-rail-row">
    <button class="qd-rail-theme"><span>Theme</span><b>● Dark</b></button>
    <a class="qd-rail-theme" data-tone="danger"><span>Sender</span><b>미설정</b></a>
    <button class="qd-rail-iconbtn">‹</button>
  </div>

  <div class="qd-rail-foot">
    <a class="qd-rail-user" href="/me">
      <span class="qd-avatar">R</span>
      <span class="qd-rail-user-text">

      </span>
    </a>
    <button class="qd-rail-logout">로그아웃</button>
  </div>

```

#### `data-tone` · 이 칸이 늘 「테마 토글」인 것은 아닙니다

`.qd-rail-theme` 자리는 기준 제품에서 테마 토글이지만, 제품에 따라 «막힘» 같은
상태가 들어가기도 합니다(Q-Sonar 는 발신 정보가 비어 메일 발송이 막힌 것을 여기
띄웁니다). 그래서 정본이 톤 둘을 엽니다.

| 값 | 테두리 | `<b>` 글자 |
|---|---|---|
| (없음) | `--qd-border` | `--qd-accent` |
| `data-tone='warning'` | `--qd-warn` 45% | `--qd-warn` |
| `data-tone='danger'` | `--qd-danger` 45% | `--qd-danger` |

> 🔑 정본이 톤을 안 열어 주면 제품이 인라인으로 덮게 되고, 그러면 «정본을 쓰지
> 않는 것»과 같습니다. 금색은 브랜드 · 활성 차림표 · 서명 장치만 맡고 상태를 말하지 않습니다
> ([2장 색](02-color.md)).

좁은 화면의 서랍은 같은 `<aside>` 에 `qd-rail--drawer` 를 더합니다.
그 안에서는 레일 자체가 스크롤합니다 (안쪽에 또 스크롤을 두면 바깥을 만질 때
안쪽이 잡힙니다).

### 글꼴

차림표의 모노 글자(조직명 · 묶음 이름표 · 판 번호 줄 · 테마 줄)는 **모든 제품이
같은 얼굴**을 씁니다. 사슬은 `dist/q-design.tokens.json` 에서 오고, 정본이
`--qd-font-mono` 의 바닥값으로 냅니다.

```
'JetBrains Mono', 'Consolas', 'Menlo', ui-monospace, var(--qa-font-pretendard), 'Pretendard Variable', monospace
```

치수를 다 맞춰도 글자의 생김새만 갈릴 수 있습니다. 사진으로는 잘 안 보이므로
**계산된 값을 재서** 찾습니다(`tools/diff-rails.mjs`).

받는 법은 제품마다 다르지만, 모두 사용자 브라우저가 바깥으로 나가지 않습니다.

```
Q-Sonar             next/font/google · 빌드할 때 받아 우리 서버에서 내보냅니다
Q-Maison · Q-Carnet 공통 모노 글꼴 조각(dist/q-design.mono-fonts.css)을 받습니다
                    woff2 를 /fonts/jetbrains-mono/ 에서 냅니다
```

⚠️ **사슬의 «라틴 바로 뒤»에 한글 글꼴을 둡니다.** 없으면 모노 칸에 한글이 한
조각 섞였을 때 브라우저가 아무 데나 떨어뜨려, 같은 글자가 자리마다 다른 얼굴로 나옵니다.

### 색 잇기

색 **이름**은 제품마다 다릅니다. Q-Atelier 는 `--qa-champagne`, Q-Sonar 는
`--color-gold`, Q-Carnet 은 `--color-brand`, Q-Maison 은 `hsl(var(--primary))` 입니다.
이름을 통일하는 것은 저장소 여럿을 동시에 뒤집는 일이라, 정본은 `--qd-*` 만 읽고 **잇는 줄**을 받습니다.

```css
/* Q-Sonar */
:root {
  --qd-surface-src:   var(--color-panel);
  --qd-surface2-src:  var(--color-panel2);
  --qd-border-src:    var(--color-line);
  --qd-text-src:      var(--color-ivory);
  --qd-subtle-src:    var(--color-dim);
  --qd-muted-src:     var(--color-faint);
  --qd-accent-src:    var(--color-gold);
  --qd-on-accent-src: var(--color-onaccent);
  --qd-danger-src:    #c97a7a;
}
```

Q-Sonar 는 이 줄을 제 전역 CSS 에 적고, Q-Carnet · Q-Maison 의 잇는 줄은 제품 기반 CSS
(`dist/q-design.foundation.carnet.css` · `dist/q-design.foundation.maison.css`)가 냅니다.

잇는 줄이 없으면 `--qa-*` 를 찾고, 그것도 없으면 이 파일이 생성될 때 박아 둔
Q-Atelier 값을 씁니다. 그 바닥값도 `dist/q-design.tokens.json` 에서 «생성» 된
것이지 손으로 적은 것이 아닙니다.

### 옮긴 뒤에 확인할 것

1. **항목 높이를 재 보십시오.** 11 + 14 + 11 = 글자 높이 + 22. 굴린 모서리나
   `py-2` 가 남아 있으면 여기서 드러납니다.
2. **한글 이름표가 벌어지지 않았는지.** `data-hangul` 을 빠뜨리면 「실 행」이 됩니다.
3. **선택 밑줄이 있는지.** 활성 항목 글자 밑의 16px 금색 선입니다. 이것 하나가 빠지면
   「비슷한데 뭔가 다른」 인상이 됩니다.
4. **화면 높이를 800px 로 줄여 보십시오.** 바닥 계정 블록이 붙어 있어야 합니다.
   밀려 올라가면 레일 전체를 스크롤로 둔 것입니다.
5. **모노 글자의 생김새.** 눈으로는 잘 안 갈리므로 `node tools/diff-rails.mjs`
   를 돌리십시오. 세 제품(Q-Atelier · Q-Sonar · Q-Carnet)을 띄워 계산된 값을 견주고 어긋난 자리만 짚습니다.
   한글이라 자간을 푼 자리는 「규칙대로 다름」으로 따로 셉니다.

## 목록 정본

제품들의 **목록 화면**을 한 벌로 묶는 규격입니다. 차림표 정본과 같은 성격이고(설명이 아니라 강제),
`dist/q-design.list.css` 한 파일에서 나옵니다. 만드는 법과 받는 제품은 «정본 세 벌이 강제하는 방식»과 같습니다.

### 왜 목록인가

차림표를 맞춘 다음 본문을 나란히 놓아 보면 인상이 가장 크게 갈리는 자리가 목록입니다.
**화면 면적의 대부분을 목록이 차지하는데** 셀 여백 · 머리글 글꼴 · 행 경계가 제품마다 달랐습니다.

### 꼴을 하나로 합치지 않습니다

Q-Atelier 에는 두 가지가 다 있습니다.

| 부품 | 언제 |
|---|---|
| `.qd-row` (항목 줄) | 항목 수가 적고 **하나하나가 사건**인 목록. 부적합 · 불만 · 변경평가 |
| `.qd-table` (표) | 수백~수천 줄을 훑는 자리. 밀도가 값어치입니다 |

4만 개 회사와 55개 자재 로트를 전부 항목 줄로 바꾸면 한 화면에 들어오는 줄이 크게 줍니다.
**통일은 «같은 꼴끼리» 맞추는 것**이지 꼴을 하나로 줄이는 것이 아닙니다.

### 진짜 `<table>` 에도 걸립니다

원본 `DataTable` 은 grid 로 짠 div 이지만, 받는 제품 가운데는 진짜 `<table>` 을 쓰는 곳이 있습니다.
마크업을 통째로 바꾸면 열 너비 · `colspan` · sticky 칸이 다 흔들립니다.
그래서 `.qd-table` 은 `table/th/td` 와 `div` 양쪽에 같은 값을 겁니다.

```html
<div class="qd-panel">
  <div class="qd-table-scroll">
    <table class="qd-table">
      <thead><tr><th>기업명</th><th data-hangul>상태</th></tr></thead>
      <tbody><tr><td>…</td><td class="qd-num">12</td></tr></tbody>
    </table>
  </div>
</div>
```

#### 한글 머리글

표 머리글은 모노 · 대문자 · 넓은 자간입니다. 한글에 걸면 「로 트 번 호」 처럼
벌어지므로 그 머리글에 `data-hangul` 을 붙입니다.

🔑 **머리글이 «거의 다» 한글인 제품은 표에 `qd-table--hangul` 을 겁니다.**
기본이 뒤집히고, 섞여 있는 라틴 머리글만 `data-latin` 을 답니다.
표를 400곳 넘게 손으로 짠 저장소에서는 언젠가 한 곳이 빠지고 그 한 곳만
벌어집니다. **많은 쪽을 기본으로 두면 빠뜨려도 조용히 틀리지 않습니다.**

### 치수 (`dist/q-design.list.json` 에서 나옵니다)

#### 판 (`.qd-panel`)

```
background surface · border 1px · radius 10
```

목록은 캔버스 위에 맨몸으로 놓이지 않습니다. 판이 없으면 표의 첫 줄과 마지막
줄이 어디서 시작하고 끝나는지 흐려집니다.

모서리는 **맥락을 읽습니다.** `--qd-radius-card: 0` 한 줄이면 각진 모서리를
브랜드로 쓰는 자매 테마가 자기 언어를 말합니다. 값을 두 벌로 두지 않고 폴백으로
처리한 원본의 설계를 그대로 옮겼습니다.

#### 판 «안»의 컨트롤도 같은 사다리에서 옵니다

```css
:root {
  --qd-radius-control: var(--qd-radius-control-src, var(--qd-radius, 10px));
}
```

`--qd-radius-card` 와 달리 이쪽은 `:root` 에 **선언합니다.** 카드 쪽은 «선언 안 된
변수 + 폴백» 자체가 자매 테마의 스위치라 선언하는 순간 계약이 바뀌지만, 컨트롤은
그런 계약이 없습니다. 각진 컨트롤을 브랜드로 쓰는 쪽은 `--qd-radius-control-src: 0`
한 줄이면 됩니다.

`html[data-theme='light']` 블록에는 넣지 않습니다. **모서리는 테마 축이 아니라
사다리입니다.**

> 🔴 판은 10px 인데 그 «안»의 단추 · 입력칸이 0px 로 갈리는 일이 생깁니다. 10 이라는 숫자는 이미
> 여러 곳에 있으므로(Q-Atelier `tokens.ts` · `dist/q-design.tokens.json`), 제품이 한 벌을 더 적지 않도록 정본이 내보냅니다.

#### 표 (`.qd-table`)

```
머리글  padding 12px 12px · 모노 12px · weight 500 · 자간 0.12em · 대문자 · subtle
셀      padding 11px 12px · 13px · text
경계    행마다 1px · 마지막 행은 없음
hover   누를 수 있는 행만 surface2   ← 안에 링크·단추가 있거나 role="link" 이거나
조밀    .qd-table--dense 는 8px
숫자    .qd-num 은 오른쪽 정렬 + tabular-nums
```

**누를 수 있는 행만 반응합니다.** 전부 반응하면 어디가 링크인지 알 수 없습니다.
`<tr>` 은 `<a>` 로 감쌀 수 없어 `role="link"` 로 다니는 제품이 있어서, 알아보는
길을 셋 두었습니다 (안에 링크·단추 / `role="link"` / `.qd-tr--click`).

#### 항목 줄 (`.qd-row`)


```html
<a class="qd-row" style="--qd-row-accent: var(--qd-danger)">
```

#### 한글 규칙

- 건수 글 · 검색 지우기 · 다음 할 일 표지에 한글이 있으면 `data-hangul` 을 붙입니다. 자간이 풀리고, 건수 글 · 검색 지우기는 글꼴도 본문체로 바뀝니다.
- 단추(이전 · 다음 · 검색)는 기본이 한글이라 자간이 없습니다. 라틴(PREV · NEXT)만 `data-latin` 으로
  대문자 · 1.2px 를 받습니다(`.qd-btn` 과 같은 규칙).
- 찾기 단추의 글은 모든 제품에서 **「검색」** 입니다(오너 결정 2026-09-25). 찾기 칸 안내(「… 검색」)와도 같은 말입니다.

#### 초점 · 줄 높이 · 표 안 빈 줄 · 따라오기 · 인쇄

- 초점: 쪽 이동 단추 · 거르개 칸 · 찾기 단추 · 검색 지우기 · 다음 할 일 표지는 원본 전역 규칙과 같은 고리(금색 2px ·
  4px 띄움 · 옅은 금색 4px)를 스스로 겁니다. 제품의 전역 규칙에 기대지 않습니다.
- 줄 높이: 빈 목록 제목 · 표지는 원본 본문 줄간격 1.6 을 못 박습니다. 제품마다 바탕 줄간격이 달라 1px 씩 갈리기 때문입니다.
- 표 안 빈 줄: `.qd-table-empty` 를 표 칸(`td` · `.qd-td`)에 걸어도 같은 얼굴입니다. 한글이 있으면 `data-hangul`(모노 빈칸을 한글 낱말 간격으로).
- 따라오기: 거르개 띠를 굴려도 따라오게 하려면 `.qd-filter-bar--sticky` 와 `--qd-sticky-top`(제품의 머리띠 높이, 없으면 0).
  받는 제품 모두 원본처럼 따라오게 하고, 폰 폭에서도 따라옵니다(오너 결정 2026-09-25).
- 따라오는 띠가 키보드 초점을 가리지 않게: 정본 부품 `StickyFocusGuard`(원본은 여기
  `source/components/sticky-focus-guard.tsx`, 네 제품이 받음)를 앱 셸에 한 번 둡니다. 띠가 붙는
  자리 + 띠 높이 + 8px 를 재서 스크롤 틀의 `scroll-padding-top` 으로 둡니다(WCAG 2.4.11 · 오너 결정
  「초점 가림 고침」). 띠 높이가 화면 폭 · 칩 줄에 따라 달라 CSS 로 못 박지 않고 잽니다.
- 인쇄: 따라오는 띠는 제자리로 돌리고 찾기 폼(`.qd-filter-row`)은 종이에서 걷습니다(목록 정본의
  `@media print` · 원본 `.qa-list-toolbar` 인쇄 규칙과 같음). 🔴 인쇄 정본(`q-design.print.css`)에 두지 않습니다.
  그 파일을 받는 제품은 Q-Maison 하나뿐이라 나머지에서는 규칙이 «받아 두기만» 됩니다.

### 옮긴 뒤에 확인할 것

1. **셀 높이를 재 보십시오.** 11 + 13 + 11. `py-3` 이 남아 있으면 여기서 드러납니다.
2. **한글 머리글이 벌어지지 않았는지.** 빠뜨리기 쉬운 자리입니다.
3. **표가 판 안에 있는지.** 맨몸으로 놓이면 첫 줄과 끝 줄이 흐려집니다.
4. **못 누르는 행이 hover 에 반응하지 않는지.** 거짓 어포던스입니다.

### 요약 지표

목록 위에서 「지금 상태」를 숫자로 말합니다.

```
┌──────────────────────┐
│ 오늘 생산             │  ← 라벨: 모노 12px · weight 500 · 자간 1.5px · subtle
│                      │
│ 204 개                │  ← 값: 36px · weight 700 · 줄간격 1.05 · 자간 -0.02em · tabular-nums
│                      │
│ 이번 주 대비 +12       │  ← 부제: 12px · muted · 위 10 · 최소 높이 16
└──────────────────────┘
  padding 18px 20px · minHeight 124 · radius 10
  격자 auto-fit minmax(180px, 1fr) · gap 14
```

**라벨이 위, 숫자가 아래입니다.** 훑는 사람이 찾는 것은 라벨이 아니라 숫자이므로,
라벨을 작게 얹고 숫자를 크게 세웁니다.

값 글자는 좁은 칸에서 긴 금액이 넘치지 않게 칸 폭의 16% 로 줄어들되 20px 아래로는 안 내려가고 36px 를 넘지 않습니다.

🔑 **부제 자리는 값이 없어도 높이를 잡아 둡니다.** 안 그러면 부제가 있는 카드와
없는 카드의 높이가 달라 격자의 아랫줄이 들쭉날쭉해집니다.

**0 은 눌러 둡니다** (`.qd-kpi--zero`). 0 을 강조하면 아무 일도 없는 것이 일처럼
보입니다. 🔴 0 과 「못 읽음」(`.qd-kpi--unread`, 빨강)은 다른 얼굴입니다. 0 은 사실이고 못 읽음은 모름입니다.

**색은 한 변수로 받습니다.**

```html
<div class="qd-kpi" style="--qd-kpi-color: var(--qd-danger)">
  <div class="qd-kpi-label" data-hangul>이번 달 불량률</div>
  <div class="qd-kpi-value">0.49<span class="qd-kpi-unit">%</span></div>
  <div class="qd-kpi-sub">지난달 0.31%</div>
</div>
```

#### 카드를 붙이지 않습니다

한 상자 안에 칸을 붙이고 칸마다 선을 그으면, 항목이 줄바꿈될 때 남는 자리가
회색 덩어리로 남습니다. **카드를 따로 세우면 그 문제 자체가 없습니다.** 남는 자리는 그냥 빈 자리입니다.

### 구역 이름표

「인허가 모듈」 · 「활동 로그」처럼 덩어리 위에 붙는 한 줄입니다.
모노 12px · 자간 0.12em · 대문자 · muted 이고, 누를 수 없는 글이므로 아주 조용합니다.

⚠️ **한글이면 `data-hangul` 을 붙이십시오.** 자간과 대문자가 함께 풀립니다.
메뉴 이름(한글)을 화면 눈썹으로 쓰는 자리에서 자간이 걸려 「점 검 · 데 이 터」로 벌어지기 쉽습니다.

### 폭

폭 표와 그 까닭은 «화면 구조 · 폭을 고르는 법»에 있습니다. 정본 클래스는 이렇습니다.

```html
<div class="qd-shell-page space-y-6">              <!-- 상세 · 폼: 폭을 좁히지 않습니다 -->
  <div class="qd-field-groups">                    <!-- 묶음 모음: 묶음 사이 24 -->
    <div class="qd-fields">                        <!-- 칸 격자 -->
      <label …>…</label>
      <label class="qd-field-wide">…</label>       <!-- 긴 칸은 줄 끝까지 -->
    </div>
    <div class="qd-fields">…</div>                 <!-- 다음 묶음은 새 줄에서 -->
  </div>
</div>
<!-- 현장 모드만 520(LAYOUT.mobile) · 가운데 · 목록은 제한 없음 -->
```

🔑 **상세 · 폼은 좁히지 않고 칸 수로 넓이를 받습니다**(2026-10-27 오너 결정 «3»). 옛 판의 `.qd-shell-detail` 820 · `.qd-shell-form` 720 은 걷었습니다.
세 제품이 같은 클래스를 씁니다. Q-Atelier 는 `PageShell` · `Fields` · `FieldGroups` 부품으로, Q-Carnet 은 `PageShell` · `Field wide` 로, Q-Maison 은 화면 뿌리의 `data-shell` 표시자 옆에 클래스를 직접 답니다(2026-10-27).

본문 여백은 `--qd-main-pad-y` / `--qd-main-pad-x` (32px / 40px)와 `.qd-main` 으로도 냅니다.
sticky 밴드가 이 값을 실측해 inset 을 잡는 제품이 있습니다.

### 구역 이름 · 칸 이름표 · 2차 탭

제품마다 달랐던 세 자리입니다. 오너 결정(2026-09-24 「정본을 늘려 모두 맞추기」)으로
원본 SectionTitle · Lbl · PageTabs 에서 값을 읽어 올렸습니다. 한 장에서 보려면 `preview/parts.html`.

| 클래스 | 원본 | 모양 | 쓰는 자리 |
|---|---|---|---|
| `.qd-section-title` | SectionTitle | 본문색 16 · 굵기 700 · 줄간격 1.35 · 아래 14 · 앞에 금색 모노 번호(01 · 02 …, 12 · 600 · 자간 0.1em) | 판 «밖»에서 덩어리의 이름 |
| `.qd-field-label` | Lbl | subtle · 모노 12 · 굵기 500 · 라틴 1.5px · 대문자 · 아래 4 | 입력칸 바로 위 |
| `.qd-tabs` · `.qd-tab` | PageTabs | 밑선 위 글자 13 · 여백 12px 18px · 최소 높이 44 · 고른 탭 금색 밑줄 2 · 굵기 600 · 줄 아래 20 | 화면 «안»을 가르는 탭 |

- 구역 제목은 본문색으로 굵게 세우고, 금색은 앞의 모노 번호에만 남깁니다(오너 결정 2026-10-10 글자 단계 C안).
  번호는 화면(`main` 이나 대화상자) 안에서 구역 제목이 나오는 차례대로 붙습니다.
- `.qd-label`(구역 이름표)과 `.qd-section-title` 은 다릅니다. 앞은 카드 «안»의 조용한 이름표(muted),
  뒤는 화면을 구역으로 나누는 표지입니다.
- 한글이면 `data-hangul`(자간 · 대문자가 풀립니다). 탭 글자에는 처음부터 자간이 없습니다.
- 고른 탭은 `aria-selected="true"` 로 말합니다(`.qd-tab--active` 도 받습니다). 상자 · 알약 · 폴더
  모양 탭은 쓰지 않습니다(오너 결정 2026-09-24 「금색 밑줄 탭으로 통일」).
- 칸 이름표와 탭은 원본 본문 줄간격 1.6 을 못 박습니다(제품마다 바탕 줄간격이 달라서). 탭은 원본 전역 규칙과 같은 초점 고리를
  스스로 겁니다. 제목 · 이름표가 단추 · 배지와 한 줄에 서는 머리 줄에서는 `--flush`(아래 여백 0)를 씁니다
  (`.qd-section-title--flush` · `.qd-field-label--flush`).

```html
<div class="qd-tabs" role="tablist" aria-label="기록 관리">
  <a class="qd-tab" role="tab" aria-selected="true" href="?tab=a">개요</a>
  <a class="qd-tab" role="tab" aria-selected="false" href="?tab=b">기록</a>
</div>
<h2 class="qd-section-title" data-hangul>오늘 처리할 것</h2>
<label class="qd-field-label" for="due" data-hangul>기한</label>
<input class="qd-input" id="due">
```

### 옮긴 뒤에 확인할 것

1. **KPI 카드 높이가 고르게 맞는지.** 부제 자리를 안 잡으면 아랫줄이 들쭉날쭉합니다.
2. **한글 라벨이 벌어지지 않았는지.** `data-hangul` 을 빠뜨리기 쉬운 자리입니다.
3. **상세 · 폼에서 칸이 늘어나지 않고 칸 수가 늘어나는지.** 브라우저를 1920px 로 넓혀 보면 바로 드러납니다. 긴 칸이 줄 끝까지 닿는지, 잠긴 칸에 회색 안내가 남지 않았는지, 잠긴 칸이 바탕색으로 구별되는지, 한 줄의 입력 상자 윗선이 맞는지, 이름 옆에 긴 문장이 없는지도 봅니다.
4. **0 인 값이 눌려 있는지.**

## 업무 화면 정돈

업무 현황과 문서 목록 화면에 거는 **조합 규칙**입니다.
먹색 · 오프화이트 바탕, Pretendard, 10px 조작부, 괘선 중심의 문서 결은 그대로 둡니다.
화면 바깥에 `.qd-workspace` 를 붙인 화면에만 걸립니다.

### 먼저 볼 화면

[업무 화면 견본](../preview/workspace.html)에서 세 제품과 밝은 화면을 바꿔 볼 수 있습니다.
검토할 문서 보기, 검색, 상태 필터, 정렬, 검색 초기화, 문서 상세와 Escape 닫기가 동작합니다.
데이터는 모두 견본이라고 밝혀 둔 것이고, 서버 · 인증 · 저장 API 는 잇지 않았습니다.

### 규칙

| 자리 | 규칙 | 목적 |
|---|---|---|
| 화면 머리 | 제목, 한 문장의 설명, 주요 행동 하나 | 첫 행동을 빨리 찾게 합니다 |
| 요약 지표 | 세 칸의 요약표와 그 아래 검토 대기 목록 | 통계 다음에 바로 업무를 이어 갑니다 |
| 문서 목록 | 제목 15px, 메타데이터 13px, 번호 12px | 이름과 부가 정보를 구분합니다 |
| 조작부 | 단추 14px, 높이 최소 44px, 보조 행동도 선명한 글자색 | 링크처럼 흐린 주요 조작을 줄입니다 |
| 검색 | 이름표, 검색어, 상태, 정렬을 한 묶음으로 | 무엇을 거르고 있는지 보이게 합니다 |
| 모바일 | 행의 행동을 다음 줄로, 입력 글자 16px, 좁은 칸은 두 줄 배치 | 제목과 단추가 서로 밀리지 않게 합니다 |
| 상태 | 제품과 무관한 의미 색과 상태 글자 | 제품 색을 상태의 의미와 헷갈리지 않게 합니다 |
| 안내 | 같은 설명을 되풀이하지 않고 관련 업무 옆에 한 번 | 본문보다 안내가 커지는 것을 막습니다 |

12px 는 번호 · 시간 같은 짧은 메타데이터에만 씁니다. 보조 설명은 13px 이상이며 긴 한글 문장에
고정폭 글꼴이나 넓은 자간을 쓰지 않습니다. 모바일 요약표에서는 긴 부제를 생략해도
라벨 · 값 · 단위가 남습니다. 상태 색은 기존 토큰을 따릅니다.

### 제품 식별 색

전체 배경, 주 단추, 오류 · 완료 색은 공통입니다. 제품명과 메뉴의 작은 식별 표시에만 금속색을 씁니다.
PWA 색은 그대로 두고, 밝은 바탕 위 작은 글자에는 읽을 수 있게 조정한 색을 씁니다.

| 제품 | 어두운 화면 | 밝은 화면의 식별 글자 |
|---|---|---|
| Q-Atelier | `#b9b9b9` | `#595959` |
| Q-Maison | `#c9a66b` | `#84632f` |
| Q-Carnet | `#c7784f` | `#97522f` |

아이콘은 `dist/app-icons/` 의 실제 자산을 씁니다. 금속색을 경고 · 성공에 덮어쓰지 않습니다.

### 적용 방법

`q-design.screen.css` 를 다시 만들면 조합 규칙이 함께 들어갑니다.
화면 바깥에 `.qd-workspace` 를 붙인 경우에만 새 규칙이 걸립니다.

```html
<main class="qd-workspace" data-product="atelier">
  <header class="qd-work-head">
    <div>
      <h1 class="qd-work-title">문서 목록</h1>
      <p class="qd-work-intro">검토가 필요한 문서를 확인합니다.</p>
    </div>
    <a class="qd-btn qd-btn--primary" href="/my-tasks">검토할 문서 보기</a>
  </header>
</main>
```

- `data-product` 는 `atelier`, `maison`, `carnet` 중 하나입니다.
- 테마는 기존처럼 `html[data-theme="light"]` 로 고릅니다. 앱이 다른 테마 속성을 쓰면 기존 어댑터에서 잇습니다.
  Q-Maison 의 `.dark` 클래스 방식도 받습니다(밝은 화면이 기본).
- 전체 마크업은 `preview/workspace.html`, 공통 스타일 원본은 `patterns/workspace.css` 에 있습니다.
  견본의 상단 제품 선택기 · 예시 안내 · 사이드바 배치는 `preview/workspace-preview.css` 에만 있습니다.
- 운영 앱의 인증 · 메뉴 권한 · 문서 상태 · 저장 기능은 기존 구현을 잇습니다.
- 운영 현황은 `.qd-workspace--overview` 를 함께 씁니다. 기존 지표 수, 링크, 0 과 조회 실패의
  구분을 지키며 라벨 · 부제는 13px 로 맞춥니다. Q-Atelier 의 기존 인라인 지표 스타일을 위한
  좁은 선택자에만 `!important` 를 씁니다. 기존 지표의 의미 색과 숫자 크기 계산은 그대로 둡니다.
- Q-Carnet 의 현장 작업 화면은 이 적용 범위 밖입니다.

### 원본과 생성물

- `source/`: 다른 저장소의 커밋된 원본을 가져온 사본입니다.
- `patterns/workspace.css`: Q-Design 이 직접 갖는 화면 조합 규칙입니다. 원본 새로고침 대상 밖에 있습니다.
- `tools/extract-screen.mjs`: 부품에서 뽑은 CSS 뒤에 조합 규칙을 붙여 `dist/q-design.screen.css` 를 만듭니다.
- `tools/build-workspace.mjs`: `patterns/workspace.css` 와 `patterns/action-targets.css`(짧은 글귀 동작의 누를 자리)를 합쳐
  `dist/q-design.workspace.css` 를 만듭니다.
- `dist/q-design.screen.css` · `dist/q-design.workspace.css`: 생성물입니다. 직접 고치지 않습니다.
- `dist/q-design.workspace.css` 는 Q-Atelier · Q-Maison · Q-Carnet 이 받고 Q-Sonar 는 받지 않습니다(`tools/sync-parts.mjs` 「업무 화면」).
  같은 규칙이 `q-design.screen.css` 끝에도 있어 뼈대를 받는 제품에 함께 들어가지만, `.qd-workspace` 를 붙인 화면에만 걸립니다.

```powershell
node tools/extract-all.mjs               # 다시 만들기 (extract-screen · build-workspace 가 이 안에서 돕니다)
node tools/build-workspace.mjs --check   # 업무 화면 생성물이 원본과 같은지만 보기
node tools/check-chars.mjs               # 금지 문자 검사
python -m http.server 3421 --bind 127.0.0.1 --directory D:/Claude/Q-Design
```

브라우저에서 `http://127.0.0.1:3421/preview/workspace.html` 을 엽니다.
`?product=carnet&theme=light#documents` 로 제품 · 테마 · 화면을 고를 수 있습니다.
제품으로 내보내는 길은 `node tools/extract-all.mjs --sync` 하나입니다.

견본에서 확인한 것은 견본과 CSS 에 대한 것이며, 운영 제품의 회귀 검증을 대신하지 않습니다.
