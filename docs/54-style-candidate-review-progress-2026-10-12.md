# 미분류 스타일 후보 추가 검수 기록

화면 너비 후보로 잡힌 서버 변수 3개를 실제 사용처와 원본 함수까지 대조해 업무 데이터로 구분했다. 아뜰리에 미분류 수는 900개에서 897개로 줄었다. 이는 디자인 수정 3건이나 화면 검수 3개의 완료를 의미하지 않는다. 제품의 소스·권한 동작·계정·운영 배포는 이번 단계에서 변경하지 않았다.

## 판정 근거

교정 기록, 설비 이벤트, 거래처 반출입의 상세 API에서 `w`는 `assertWriteRole`의 결과다. 조직 식별자 또는 제한 응답이며 화면 너비가 아니다. 기존 검토는 응답 반환과 조직 비교·질의 조건만 허용했기 때문에 추가 업무 모듈 검사 호출을 미분류로 남겼다.

이번에는 `w.orgId`가 검토된 `moduleGate`의 두 번째 인자로 전달되는 사용처도 확인했다. 해당 함수는 조직의 활성 업무 모듈을 조회하고 정상일 때 null, 제한할 때 HTTP 응답을 반환한다. 호출은 정확한 모듈에서 직접 가져온 함수이며 await, 인자 개수와 위치, 모든 `w` 참조를 검사한다. 두 원본 함수 파일의 전체 지문이 바뀌면 새 검토를 요구한다.

검토 범위는 세 경로의 정확한 변수 선언이다. API 폴더나 `w`라는 이름 전체를 제외하지 않는다. 알 수 없는 호출, 스타일 전달, 별칭, 가져온 함수 이름을 가리는 선언, 잘못된 인자 위치와 타입 전용 import는 승인하지 않는다. 별도의 `loadSheets` 사용처 1개는 그대로 미분류다. 이후 렌더러의 표시 인자는 별도로 남는다.

## 검증과 보존

기존 좁은 검사에서 승인했던 29건과 미분류 4건의 결과는 유지했다. 추가 검사 3건은 별도 기록에 저장했고, 기존 검사로는 여전히 미분류여야 함을 확인했다. 기존·추가 회귀 검사 4개가 통과했다. 추가 스타일 사용, 별칭, 잘못된 호출·위치·가져오기와 이름 가림은 모두 거부됐다.

`8ae304c`의 전체 스타일 판정 보고서와 현재 보고서를 비교했다. 정확한 세 행의 업무 데이터 판정과 이에 따른 개수만 바뀌었다. 원문·위치·인자 지문·소스 지문, 다른 행의 판정과 보고서 메타데이터는 동일하다. 이를 `reviews/atelier-module-guard-decision-migration.json`에 기록했다. 이전 증거의 지문을 일괄 갱신하거나 나머지 후보를 승인하지 않았다.

전체 `extract-all --check --only=Q-Atelier,Q-Works,Q-Forge`는 종료 코드 0으로 통과했다. 기존 증거·동기화·공통 컴포넌트 계약과 추가 사용처 검사를 포함한다. 기존 정본 렌더러로 앱 아이콘 32개 지문도 모두 일치했다. 금지 문자와 변경 공백 검사도 통과했다. 이번 정적 검사를 새로운 업무 화면 시각 인증으로 확대하지 않는다.

## 현재 남은 범위

웹 미분류 스타일 인자는 아뜰리에 897개, 메종 0개, 카르넷 0개다. 미분류에는 실제 표시 조합과 런타임 인자, 업무 데이터 후보가 함께 있으므로 남은 숫자를 곧바로 디자인 결함 개수로 보지 않는다. 실제 사용처를 확인한 뒤 중앙 규칙 연결 또는 업무 입력 경계로 구분해야 한다.

역할별 등록 주소 540개와 업무 화면 이미지 2,330개는 유지한다. 이번 정적 사용처 검사를 새 화면 캡처로 계산하지 않았다. 추가 모바일·테마·상호작용 상태, iOS의 직접 지정 색상·알림·시작 화면, 다른 앱 클래스와 설치 기기 검수, 앱 서명·배포는 남아 있다. 중앙 생성·동기화·빌드·배포 절차는 계속 필요하며 모든 화면과 인자의 중앙 연결을 완료한 상태는 아니다.
