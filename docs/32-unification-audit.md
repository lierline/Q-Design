# 세 제품 디자인 통일 감사

이 문서는 첫 컴포넌트 연결 단계의 기록이다. 배경·인증·전역·출력·세부 인자와 최신 검증 범위는 [확장 감사](36-foundation-audit.md)를 따른다.

2026-10-10. 대상은 Q-Atelier, Q-Maison, Q-Carnet이다. [인계서](28-handoff-to-codex-2026-10-10.md)의 기존 결정을 확인하고, 이후 오너가 맡긴 실제 디자인 통일과 중앙 규칙 연결까지 수행했다. 로컬 제품 코드와 정본에 반영했으며 운영 배포는 실행하지 않았다.

## 변경 결과

같은 역할의 부품이 서로 다른 모서리, 글자 크기, 표면과 조작 높이를 갖던 원인은 제품별 고정값과 정본에 없던 역할이었다. 기존 차림표·목록·화면 정본에 더해 대화상자, 서랍, 정보 팝오버, 알림, 로딩, 진행, 카드, 선택, 달력, 체크 표시를 중앙 CSS에 연결했다. 제품의 React·Radix·native 구현은 데이터와 상호작용을 유지한다.

외형은 [components.css](../patterns/components.css), 화면 색상은 [palette-overrides.json](../patterns/palette-overrides.json)에서 바꾼다. 색상 생성기는 Atelier CSS 변수, Maison HSL 채널과 기존 Tailwind 색상 이름, Carnet 테마 변수로 같은 의미를 전달한다. 생성 CSS를 복사한 뒤 실제 앱의 import 경로와 사본 본문 지문까지 검사한다.

| 발견한 문제 | 반영한 조치 |
| --- | --- |
| 공용 역할 목록이 없고 신규 부품이 검사에서 빠짐 | 37개 역할과 15개 규칙 계열, 독립적인 공개 API 검사 범위 등록 |
| 모달·서랍·툴팁·토스트가 제품별 외형을 소유 | 공통 클래스, 치수·표면·상태·모션 토큰에 연결 |
| 고정 색상과 서로 다른 테마 형식이 중앙 변경을 차단 | 제품별 팔레트 생성과 명시적인 예외 매핑. Maison 기존 23색도 연결 |
| 오래된 추출기가 고정 숫자만 인식 | QD 어댑터와 중앙 CSS를 읽고 실행 중 CSS 변수를 유지하도록 수정 |
| 중첩 팝업에서 Escape·초점·스크롤 잠금이 충돌 | 최상위 팝업만 닫고 이전 초점과 바깥 스크롤 잠금을 복원 |
| 메종의 긴 위·아래 서랍이 뷰포트를 벗어남 | 동적 뷰포트 높이 제한과 내부 스크롤 적용 |
| 동작 감소 설정에서 메종 팝업이 잘못된 위치에 남음 | 오버레이 애니메이션과 전환을 명시적으로 중지 |
| 작은 체크·날짜·보조 행동과 목록 이동의 터치 영역 | 공용 44px 기준과 거친 포인터 규칙 연결. Carnet 현장 56px 유지 |
| 검색·목록 이동에 남은 고정 12px 조작 글자 | 13px 조작 토큰 연결. 수량 등 보조 글자는 12px 유지 |
| 원본 파일 검사에서 생성 사본과 runtime 누락을 혼동 | 정확한 내보내기 경로만 사본으로 인정. 테스트와 실제 runtime 분리 |

Atelier 은색, Maison 샴페인 골드, Carnet 구리색 식별을 유지한다. 본문 14px, 조작 13px, 보조 12px, 화면 제목 22px, 구역 제목 C안 16px, 대화상자 제목 18px, 바깥 모서리 10px가 현재 공통 기준이다. [관리 규칙](30-component-governance.md)에 상태, 예외, 책임과 변경 절차를 적었다.

## 전수 목록과 공개 API

| 제품 | 조사 코드 파일 | 렌더 선언 | 역할 등록 구현 | 검사 범위 내 공개 렌더 부품 | 연결된 정본 사본 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Q-Atelier | 709 | 1,153 | 87 | 69 / 69 | 9 |
| Q-Maison | 1,105 | 1,354 | 94 | 94 / 94 | 11 |
| Q-Carnet | 158 | 271 | 32 | 32 / 32 | 12 |
| 합계 | 1,972 | 2,778 | 213 | 195 / 195 | 32 |

[전체 목록](31-component-inventory.md)은 공개 부품뿐 아니라 화면 내부 함수와 업무 조합을 포함한다. 자동 분류는 적용할 규칙을 지정하는 수단이며 실제 화면의 준수 판정이 아니다. 위 195개는 [명시된 공개 API 범위](../source/component-public-api.json)의 수치이며 모든 렌더 선언을 공용 부품으로 부른 숫자가 아니다. 등록 면제는 없다.

새 공개 부품, 등록의 삭제, 사라진 구현, 정본 사본의 임의 수정, 끊어진 앱 import를 검사한다. 역할표 자체에서 항목을 지우는 방법으로 검사 범위를 줄일 수 없다. 새 공용 라이브러리 경로를 만들면 공개 API 범위도 함께 확장한다.

## 검증 근거

[비교 화면](../preview/components.html)은 세 제품의 실제 소스 컴포넌트를 가져온다. 밝음·어두움과 375·412·1440px 조합으로 18개 조건을 검사한다. 별도로 세 제품의 일반 모션 대화상자를 확인한다. 테스트용 예시 데이터이며 API 저장과 업무 데이터를 사용하지 않는다.

- 입력과 대화상자의 모서리, 가로 넘침, 불투명 표면, 조작 영역을 확인한다.
- 초점 진입, Tab·Shift+Tab, Escape, 호출 버튼으로의 초점 복원, 중첩 팝업의 닫기 순서를 확인한다.
- 메종의 긴 위·아래 서랍 안에서 키보드로 마지막 행동에 도달하는지 확인한다.
- 공통 모서리 10→14px와 조작 글자 13→15px를 바꾸어 실제 입력·대화상자까지 전파되는지 확인한다.
- 팔레트 생성기에 다른 본문색을 넣어 세 제품의 실제 입력과 팝업 글자색이 바뀌는지 확인한다.
- 임시 복사본에서 표 여백, 버튼 높이, 제목 크기를 바꾸고 차림표·목록·화면 추출 결과가 따라오는지 확인한다. 연결 삭제와 잘못된 변수는 실패해야 한다.

정본 검사 명령은 `node tools/check-components.mjs`다. `--browser`를 붙이면 실제 부품 빌드와 브라우저 검사도 실행한다. 브라우저 결과는 [results.json](../preview/screens/components/results.json)에 기록한다. Windows에서는 설치된 Edge와 로컬 브라우저 실행 권한이 필요하다.

| 실제 컴포넌트 브라우저 | 18개 폭·테마 조건과 3개 일반 모션 확인, 실패 0개. 모바일 12개 조건의 거친 포인터 확인 |

## 검증 범위와 남은 제약

전체 업무 화면의 로그인, 권한, 데이터별 분기, 저장, 결재, 인쇄 조합을 종단 검증한 결과는 아니다. 공용 부품 연결과 대표 실제 렌더 조건을 확인한 결과다. 제품별 업무 조합의 특수 색상·수치·레이아웃은 목록과 역할표에 남기고 공용 계약을 통해 검토한다. 이 수치를 전체 업무 화면의 시각 준수율로 사용하지 않는다.

메종 전체 타입 검사에는 변경 전부터 있던 `tests/unit/shell-rail.test.tsx:213`의 `b`가 undefined일 수 있다는 오류 하나가 남는다. 이번 변경 후 추가 오류는 없다.

기존 전체 자산 파이프라인의 앱 아이콘 재렌더 검사는 별도 제약이다. 설치된 Edge로 실행하면 저장된 v4 그림 지문과 달라 버전 보호 장치가 중단한다. 이 작업에서는 앱 아이콘 그림이나 판 번호를 바꾸지 않았다. 중앙 컴포넌트 검사는 통과 여부를 독립적으로 제공하며 아이콘 검사 실패를 숨기지 않는다. 기존 전체 추출·배포 검사를 통과했다고 보고하지 않는다.

Atelier 엔진 manifest 검사에는 저장 파일의 CRLF와 생성 문자열의 LF 비교에 따른 기존 차이가 있어 내용과 5개 엔진 ID를 별도로 대조했다. 잠긴 `tokens.ts`, 잠금 파일, 엔진 증거는 수정하지 않았다.

## 유지 절차

1. 공용 외형은 Q-Design `patterns/components.css`, 공통 색상은 `patterns/palette-overrides.json`을 수정한다.
2. 팔레트 변경이면 `node tools/build-palette.mjs`를 실행한다.
3. [관리 문서의 동기화 명령](30-component-governance.md)으로 해당 조각을 세 제품에 내보낸다.
4. `node tools/component-registry.mjs --write`로 목록을 갱신하고 `node tools/check-components.mjs --browser`를 실행한다.
5. 원본 제품 컴포넌트를 바꾸면 QA 커밋, 원본 사본 갱신, 관련 추출기 재생성도 수행한다.
6. 제품별 회귀 검사와 변경 검토 후 운영 반영을 결정한다. main 푸시는 운영 배포를 일으키므로 이 작업에서는 실행하지 않았다.

Q-Sonar는 이번 세 제품 구현·동기화 대상에 넣지 않았다. 기존에 존재하던 연구 문서 화면 변경과 별도 검토 시안도 보존했다.

QA 원본 추출을 위해 로컬 커밋 `41e463d9`, `9e780953`을 만들었다. 제품 운영 저장소로 push하지 않았다. Maison, Carnet, Q-Design의 구현과 생성물은 현재 작업트리에서 검토할 수 있다.
