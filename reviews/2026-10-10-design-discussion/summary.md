# Q-Design 디자인 검토 대조

2026-10-10. 대상은 Claude의 장부형 시안과 Codex의 맥락 유지형 문서 검토 시안이다.

## 논의 상태

사용자의 명시적 전송 승인 후 prompt.md를 Claude에 전달하고 답변을 받았다. 기존 검토 세션을 복사한 별도 대화이며, 원래 실행 중인 Claude 채팅에 메시지를 삽입한 것은 아니다. 답변 세션은 3499ff5e-71e4-4cc8-b16e-980ef3991dc3이다. Claude는 인용된 문서 규칙에 근거해 답했으며 이번 답변에서 해당 파일을 직접 재확인하지는 못했다고 밝혔다.

추가 코드 확인을 담은 followup.md도 사용자가 파일 내용의 외부 Claude 전송을 명시적으로 승인한 뒤 같은 세션에 전송했다. 2차 답변을 수신했으며 아래에 합의와 남은 쟁점을 기록한다. 원래 실행 중인 Claude 채팅이나 제품 코드는 변경하지 않았다.

## 기존 검토에서 공통으로 지지한 방향

1. 장식용 카드와 그림자를 줄이고 이어진 면과 절제된 구분선을 사용한다. 선택 상태와 글자 대비는 명확하게 유지한다.
2. 연속 문서 검토는 목록과 상세를 함께 보여주고, 집중 보기에서 돌아올 때 목록 위치와 초안을 유지한다. 단건 상세와 생성 폼은 업무에 필요한 본문 폭을 제공한다.
3. 구역 수만으로 탭을 만들지 않는다. 함께 대조할 정보는 한 화면에 둔다.
4. 핵심 행 동작은 항상 찾을 수 있어야 한다. 보조 동작만 마우스 올림과 키보드 초점에 반응하도록 한다.
5. 모바일은 스크롤 중에도 현재 대상이 식별되어야 한다. 기존 Claude 시안에 문서 번호가 없다는 표현은 부정확하며, 번호가 본문과 함께 스크롤된다는 것이 정확한 문제다.

## 이번 Claude 답변에서 확인된 동의

- 경계: 장식용 상자를 줄이되 선택, 초점, 오류, 입력 경계와 본문 읽기 폭을 유지한다.
- 흐름: 연속 검토에는 목록과 상세를 함께 보여주고, 단건 처리와 폼에는 이를 강제하지 않는다.
- 주 버튼: Claude가 금색 주 버튼 적용을 철회했다. 저장 동작 역시 중립색 버튼으로 표시하고, 초록은 저장 후 완료 상태에 사용한다.
- 모바일: 짧은 제목과 번호를 고정 헤더에 두고 메뉴를 앱 헤더에 붙인다. 메뉴를 연 상태의 회전과 가상 키보드는 아직 검증하지 않은 수용 기준으로 추가한다.
- 정보 구조: 탭은 동시 참조 필요성으로 판단하며, 핵심 행 동작은 항상 보이게 한다. 보조 동작은 마우스 올림과 키보드 초점 모두에서 드러나게 한다.
- 전환: 현재 제안한 120~260ms 범위는 적절하다는 의견이다. 이전 본문과 새 본문이 겹치지 않게 하고, 복귀 스크롤을 전환 시작 전에 복원하자는 보완 의견을 받았다.

## Codex 확인 결과와 2차 논의에 전달한 보정

- preview/context-review.js는 같은 본문 내용을 renderDetail()로 바꾸고, scrollTop을 복원한 뒤 animate(article)를 호출한다. Claude의 전환 순서 제안은 현재 코드에 이미 반영된 방식이다. 이번에는 코드 순서를 확인했으며 새로운 실행 검증을 하지는 않았다.
- 동작 줄이기는 현재 애니메이션 전체를 건너뛴다. Claude는 이동 없이 투명도만 쓰는 기준을 제안했지만, 즉시 전환도 허용하는 쪽이 적절하다는 것이 Codex의 보정 의견이다.
- docs/25는 제품 금속색을 식별 표시에 제한하지만 patterns/workspace.css의 초점 outline은 champagne 기반 accent를 사용한다. 선택, 단계, 체크, 초점의 공통 토큰 역할은 문서와 구현을 함께 대조한 뒤 확정해야 한다. 이것을 새 합의로 단정하지 않는다.
- Claude의 '의미색은 완료와 오류에만'이라는 기준은 경고, 보완 요청, 진행 상태를 누락한다. 제품 식별색과 업무 상태색을 분리하되 기존 상태 의미를 보존하자는 것이 Codex의 보정 의견이다.
- 모든 구분선에 같은 대비를 강제하기보다 조작부 및 상태 인지에 필요한 경계와 초점을 검증하고 장식 구분선을 구분하자는 것이 Codex의 의견이다. 이번 논의에서 대비 수치를 새로 측정하지 않았다.
- source/는 다른 저장소에서 수입한 사본이고 patterns/는 Q-Design 소유 조합 규칙이다. dist/는 생성물이므로 직접 수정하지 않는다.
- 시안의 상태는 메모리에서만 유지되며 새로고침하면 초기화된다. 모바일 회전과 실제 가상 키보드 상태는 미검증이다.

## 다음 시안의 검증 제안

1. 긴 목록에서 문서를 열고 집중 보기 후 돌아와도 같은 행과 스크롤 위치를 유지한다.
2. 두 문서 사이를 이동하며 작성한 메모가 각각 유지되고, 저장 실패 시 초안이 사라지지 않는다.
3. 모바일에서 긴 문서 제목, 메뉴 열림, 본문 스크롤 이후에도 현재 문서와 복귀 동작을 확인할 수 있다.
4. 밝은 모드와 어두운 모드 모두 선택, 키보드 초점, 오류, 비활성 상태를 구분할 수 있다.
5. 일반 전환과 동작 줄이기 설정에서 상태 복원 시점과 최종 위치가 같고, 빠른 연속 클릭에도 오래된 문서가 표시되지 않는다.

## 2차 답변 이후 정리

### 추가로 합의된 내용

- 기존 코드 설명대로 본문이 겹치지 않고 스크롤이 전환 전에 복원된다면, Claude가 제안했던 두 조건은 이미 충족된다. 해당 순서를 명세에도 기록한다.
- 동작 줄이기 설정에서 즉시 전환을 허용한다. Claude는 문구 변경이나 적절한 초점 이동으로 상태 변화를 알아볼 수 있어야 한다는 조건을 추가했다. Codex도 이 조건을 수용한다.
- 주 버튼은 중립색을 사용한다. 선택, 초점, 단계, 체크 색의 역할은 문서와 구현을 대조한 뒤 확정한다.
- 제품 식별색과 업무 상태색을 분리한다. 경고와 보완 요청 등 기존 상태의 의미는 보존하며, 완료와 오류에만 의미색을 제한하지 않는다.
- 장식 구분선과 조작부 인지에 필요한 경계를 구분한다. 모바일 회전, 가상 키보드, 메뉴 상태 복원은 아직 실제 기기에서 검증하지 않았다.

### 남은 검토와 Codex 의견

- Claude는 입력 칸과 보조 버튼의 윤곽을 대비 검증 대상에 남기자고 강조했다. Codex는 조작부를 식별하는 데 필요한 경계는 검증하되, 장식용 선과 같은 기준으로 일괄 처리하지 않는다는 기존 입장이다. 실제 화면에서 조작부가 어떻게 식별되는지에 따라 판단한다.
- Claude가 답변에서 언급한 4.16과 3.46의 대비 수치는 이번 Codex 논의에서 독립적으로 재계산하지 않았다. 접근성 검증 완료의 근거로 사용하지 않는다.
- Codex는 현재 집중 보기에서 목록이 즉시 사라지고 본문만 전환되는 방식이 상태 보존에는 충실해도 공간적 연결은 약하다고 본다. 이는 사용자에게 설명한 Codex의 추가 의견이며, 전송한 followup.md에는 포함되지 않았으므로 Claude와 합의된 내용으로 표시하지 않는다.
- 다음 시안에서 집중 보기의 폭 변화와 복귀 연결을 비교하는 것이 Codex의 권고다. 장부형 외관과 맥락 유지형 흐름을 결합하는 방향에는 양측이 동의했다. 이번 논의만으로 구현이나 정본 변경이 승인된 것으로 간주하지 않는다.

## 사용자 선택 후 시안 정돈과 전달

사용자가 폭이 이어지는 방식을 선택한 후 더 다듬어 Claude에게 전달하도록 요청했다. 시안에 다음을 반영하고, 기존 흐름 14개 및 비교 검증 8개를 다시 통과했다.

- 집중 320ms, 복귀 240ms로 조정하고 감속 곡선을 다듬었다. 목록의 작은 이동과 투명도를 함께 조절해 접히는 글자의 잘림을 줄였다.
- 비교 방식은 낮은 강조의 밑줄 선택으로 표현하고, 실제 검토 완료가 주요 행동으로 남도록 체험 버튼의 강조를 낮췄다.
- 두 보기의 본문 최대 폭과 도구 모음 여백을 통일했다. 기존 방식과 3배 느리게 비교는 유지한다.
- 제품 정본이나 운영 앱은 수정하지 않았다. 수정은 preview 시안과 해당 설명·검증 파일에 한정한다.

polished-handoff.md를 기존 Claude 논의 세션에 전송했고 수신 확인 답변을 받았다. 원래 실행 중인 별도 Claude 채팅에 메시지가 삽입된 것은 아니다.

Claude는 이미지를 직접 열어 검토하지 못했다고 명시했다. 숨겨진 목록의 키보드 초점, 모션 줄이기의 상태 안내, 공통 색 역할의 별도 확정, 실제 모바일 기기 검증을 유지 조건으로 제시했다. 느린 기기의 줄바꿈 움직임과 선택 행의 구분도 후속 확인 대상으로 남겼다.

Claude는 320ms와 240ms를 이전 120~260ms보다 길다고 표현했으나, 수치상 범위를 넘는 것은 집중 보기의 320ms뿐이다. 이 값은 사용자 선택 후 다듬은 시안 값이며 공통 정본의 확정값이 아니다.

## 다음 개선 의견 전달

사용자 요청으로 next-design-opinions.md를 기존 Claude 논의 세션에 전송했고 답변을 받았다. 이번에는 시안이나 정본을 변경하지 않았다.

전달 내용은 ① 상단 공간 정돈 ② 검토 진행에 반응하는 하단 행동 ③ 목록 우선순위와 기한 위치 유지 ④ 글자·여백 위계 ⑤ 관련 기록의 짧은 대조 보기다. 상단과 하단을 먼저 개선하고 관련 기록 미리보기를 뒤에 두는 우선순위를 제안했다.

Claude는 우선순위에 대체로 동의했다. 비교 도구를 접는 것은 현재 시안에 해당하는 개선이며, 운영 화면에도 같은 도구가 있다는 뜻으로 일반화하지 말자는 조건을 남겼다. 선택 전후 기한 유지, 완료 처리 후 목록 위치 보존, 정본과 다른 글자 수치는 후보로만 다루는 방향에도 동의했다. 화면과 코드는 이번 답변에서 직접 확인하지 않았다고 명시했다.

주 버튼의 이름과 행동을 '남은 항목 확인'에서 '검토 완료'로 바꾸는 제안에는 이견이 있었다. Claude는 같은 위치에서 행동이 바뀌면 습관적인 연속 클릭과 이름 변경 안내가 혼란을 만들 수 있다고 지적했다. 대안으로 '검토 완료' 버튼은 고정하고 옆에 '1/3 확인 · 남은 2개 보기' 보조 링크를 제안했다.

두 하단 안 중 하나로 합의하지 않았다. 어느 안이든 미완료 상태에서 실제 검토 완료가 실행되지 않게 조건 검사는 유지해야 한다는 것이 Codex의 판단이다. 별도 확인 클릭만으로 오조작 위험이 완전히 해소된다고 단정하지 않는다. 화면 비교 후 결정하는 것이 적절하다.
